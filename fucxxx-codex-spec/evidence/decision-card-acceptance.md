# P1 验收：12 个冻结案例

依据：子设计“验收”、总设计 §4.2。宿主 Codex，模型 `gpt-6.1-terra`，入口 `scripts/dev-research.sh codex <T> --decision held|not_held [--as-of D] [--prompt …]`，产物在 `.local/runs/`。
这些案例只检验链路、口径与一致性，**不检验预测能力**。部分案例出自 terra 登记样本（NFLX 等），不影响功能验收。

## 判据（每张卡）
- 事件组、窗口、基准与 `classify_decision_event` 一致（服务端会拒收不一致的）；
- 两栏不相乘、没有“本案期望”；
- E1/E2 有归因三字段；HOLD/WAIT 有类型；复核条件至少一条价格位；
- 没有用到信息截止之后的事实；
- 成对案例：C1/C2 动作相同；C1/C3 动作相同、资金去向不同；
- 保存成功，`score-decisions.py` 能对回放记录算出 Δ / Δ_B1 / Δ_B2（C12 显示 pending）。

**判据核对**：
- 12/12 保存成功：服务端重判事件组全部一致，7 个必需标题齐全；
- 没有一张卡写“本案期望”，两栏都分开列；
- E1/E2 都有归因三字段；HOLD/WAIT 都写了类型；复核条件都含价格位；
- **成对案例**：C1/C2（只改成本价）动作、概率完全相同；C1/C3（只改资金去向）动作相同，去向分别为 cash / sector_etf；C1（本公司原因）REDUCE，C4（行业冲击）HOLD，符合方法；
- C11 通过 `get_prior_trade_decision` 读到 C1，正确关联；
- C12 在决策后（2026-11-21 16:35Z，周六）由 `decision-record.py` 写入 `evals/forward/decision-ledger.jsonl`，早于可成交时间；
- `score-decisions.py` 对 11 条回放记录算出 Δ / Δ_B1 / Δ_B2；INTU 一条手算核对一致（−0.5 ×（−11.44 + 1.47）− 0.2 = +4.78）。
