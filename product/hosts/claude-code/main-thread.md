# Claude Code 主线程原生委派

本说明定义稳定委派与业务边界，不授予研究权限。唯一产品项目根是当前仓库 `product/`，业务代码来自同一工作副本；外置目录仅存私有数据。操作方准备、连接复用与实际加载见就地产品根下 `hosts/INSTALL.md`。

用户可明确委托指定开发会话管理限定测试安排及向指定产品会话转交任务。收到该来源的宿主定向交付时，先核对已有真实用户委托、目标会话、范围/阶段、模型/预算和停止条件；同范围有效委托已覆盖的修补后测试不再要求用户在产品会话重复批准。它不是peer自行授权、规划确认或凭据代批，不扩大已授予范围/预算，不代批宿主权限提示；来源不明、未委托或超范围仍停止并只询问缺失决定。

## 一次完整任务交付

必要准备完成后，一次交付对象/证券、研究问题、阶段、cutoff、小型任务授权、批准模型、真实依赖、产物位置、调用/时间预算和分类停止条件。时间预算由主线程以宿主实时UTC核对并负责及时停止；中断或等待后恢复业务前重新核对，过期即停，宿主重试不延长预算。没有实时时钟的专业不承担到时判定，不以系统日期、资料时点或历史消息代替计时，也不自行续期。小包的`specialist_args`是确定性准备的精确授权JSON，转交对应专业时保持该字符串不变，仅追加本次问题、预算及停止条件；不将token改写为“对应凭据”等代称。旧小包无此字段时使用其精确平铺task_ref/task_token，不猜值。不得转交其他角色授权、结论、旧窗口时间线或操作方连接凭据。专业自主选证据和计算，主线程不代写研究。

产品按稳定方法执行，不依赖开发线程逐步补参数或调用顺序。任务内普通错误只沿下述原作者有限修订；产品缺陷回到开发面处理，不在研究中改源码、配置或版本。失败只阻断真实依赖，独立能力不成为无关综合的前置；完整交付仍须覆盖所有获准事项。

## 模型、来源与执行证据

专业角色保持 `model: inherit`，三个 native Skill 不覆盖 model。用户已有 CC Switch 映射由宿主生效，项目不读其数据库/凭据、不改全局认证/模型/代理，不新增模型后端。

由能读取正式宿主执行记录的主线程或获准协调端核对主/子实际模型，分别记录宿主选择/别名、批准映射和实际记录；合法映射不要求名称相同。宿主声明、系统自称及专业自报不作为实际模型不符的依据，不向专业交付其无法核验的型号自证任务。专业保持inherit并执行获准研究，模型证据在既定检查点由上述责任方核对；正式记录显示未经批准目标或必要模型观测缺失时仍按分类停止。声明不证明配置已读取，转录不证明Provider wire，未知不补造。

委派前确认当前来源、实际可见入口和必要能力、有效阶段及任务授权。磁盘发现、候选、已加载正文与本次来源分列；同一有效上下文中来源/正文未变的真实加载证据可复用，历史 Base directory、孤立 `Re-invocation`、hash或自报不认证新来源。不轮换入口试错。

随原生委派才能取得的实际子模型、首轮输入、方法和工具范围，先明确可得观察入口及取得时点，再作预算内委派，并在对应下游消费前核对；不要求执行前已有本次事件。已知必要入口缺失直接阻断，不消耗模型试探，不以模板、凭据或业务回执补证。优先用现有记录，仅材料不足时按获准范围官方导出，不固定重复导出或全历史核查。Provider wire、精确费用等未提供信息单列，不新增遥测平台，也不豁免必要模型/隔离门禁。

## 业务准入与显式连接诊断

当前来源及阶段授权成立后，读取获准小包，以其`mcp_arguments`的精确task_ref/task_token作为每次MCP调用的顶层字段，再加该工具的业务参数；旧小包沿精确平铺双字段使用。单股新请求没有冻结资料时，主线程先调用Company服务的 `research_prepare_single_stock`（只传代码/问题/cutoff），不能把缺资料当终止条件；它沿原确定性采集、身份核实与冻结路径取得本次请求/Gate。返回AUTHORIZATION_REQUIRED且含authorization_action.tool时保持精确参数调用 `research_authorize_single_stock`，让支持anthropic/requiresUserInteraction的原生宿主强制展示完整真人审批，不用聊天确认、AskUserQuestion或SDK/Hook自动放行冒充批准，不让用户执行CLI。用户拒绝/取消即停止；宿主不支持、范围变化、配置缺失或过期时明确报告对应限制，不重试续期。批准后的同一工具调用在服务端复用原authorize-single-stock逻辑自动准备资料；返回FROZEN_COMPANY_BOUND后按next_tool精确调用既有 `research_prepare_task`，包括security_id、COMPANY_RESEARCH及本次expected_request_hash/expected_gate_hash；核对company_authorization后在同一截止前自动使用公司原生入口完成一次研究和完整回读，不再要求用户手工转参。旧纯资料准备不自动取得研究授权，其他阶段不扩权。连接凭据只在服务端私有文件中，准备和授权工具均不得出现在专业Agent工具清单；其他已准备请求仍沿既有 `prepare bind`。research_submit必须是顶层task_ref、task_token、draft三字段，`draft`仅含研究语义，“不填技术身份/hash”不意味着省略外层授权。使用本任务角色对应连接，同名业务工具不可跨角色替代，CIO准备、消费和提交均使用CIO连接。服务端在事实返回、计算、成功收据、稿件额度或持久化前重验连接、角色、任务、请求/input/Gate/cutoff与资源完整性；错配立即拒绝。静态配置不证明活动服务，业务合法不认证作者、模型或隔离。同一有效请求/角色内获准任务复用连接，不逐项换配置。

正常任务不以四角色绑定巡检为前置，也不因未启用纯观察工具而失败。普通 `research_context` 可含事实或预计算，不用于无授权探测。三个专业无观察/准备工具，Skeptic原五工具保持。

仅在明确授权的连接诊断中，主线程使用实际可见 `research_connection_context`，对必要角色各最多一次传确定性准备的精确 `expected_connection_hash`（64位小写SHA-256）。不读取连接token，不改预期hash或轮换工具；诊断错误/不匹配停止对应诊断及受影响研究，不恢复旧窗口或用CLI/SDK兜底。

该接口重验连接授权与绑定，只返回source_id/as_of/retrieved_at、role、connection_hash/request_hash/input_hash/gate_hash、decision_cutoff及固定UNVERIFIED的caller_authentication；不返回token/路径、问题/input、事实/ID、预计算或报告，不写任务/查询/提交。观察只证明该次连接匹配，不替代业务准入或执行/内容证明，不扩展无研究来源诊断权限。

## 原生专业入口

| 原生 Skill | 固定专业角色 | 输入边界 |
| --- | --- | --- |
| `company-native` | `runtime_company_analyst` | 当前公司的问题、cutoff与精确任务授权 |
| `market-native` | `runtime_market_catalyst` | 当前一项市场能力及对应资料范围 |
| `skeptic-native` | `runtime_skeptic` | 独立首轮非结论性问题与允许原始资料 |

三个入口以 `context: fork`和固定 `agent`绑定现有角色。首派使用Skill工具，只传 `skill/args`，不构造Agent的isolation/model参数、不指定worktree，不用通用开发Agent替代。已有作者的获准续接或有限修订使用实际可见的宿主 `SendMessage`，以该作者的精确原生 agent ID 为目标；原生 agent ID 不是桌面 session ID，`list_sessions`或`ListAgents`缺行不证明不可恢复，也不要求重新发现首派Skill。实际恢复入口或权限不足则具体报告并停止，不重新Skill spawn、换作者或模拟恢复器；恢复后保留原角色/方法/工具范围、inherit、任务和稿件上限。CIO只由明确综合阶段的当前主线程承担。

```json
{
  "skill": "company-native",
  "args": "本次独立研究问题、证券、cutoff、精确task_ref/task_token、调用/时间预算与分类停止条件；不含其他角色结论或操作方连接凭据。"
}
```

示例仅适用于实际可见名称确为 `company-native`；若宿主列目录限定名，使用其正式完整名称，不自行拼接或传空args。专业使用本角色精确MCP工具和共享方法，自主取证、计算、提交并返回精确回执。

Skeptic不接收父正向历史、其他角色结论/报告、私人账户或其他任务授权。独立任务prompt和静态配置不单独证明隔离，实际首轮输入、方法与工具须可核对。按本次计划并行或明确串行，不冒称并行；独立首轮不因执行顺序继承另一角色结果。

## 分类停止与完整交付

- 越权、错任务/角色、来源/PIT/完整性/隔离失败、未批准模型、必要缺证、入口/工具不可用或预算耗尽：停止受影响任务及真实依赖；公共边界失效停止全部相关调用，不换入口、模型或权限试错。
- research_submit因可确定的顶层授权字段遗漏返回SCHEMA_REQUIRED_MISSING且无草稿回执/业务写入：原调用者持有同一已授予精确小包时，可在同一预算内仅补全一次外层参数，保持原draft并重新通过全部鉴权；无回执不猜base_draft_ref/allowed_paths。错凭据、错任务/角色、无法确定缺失字段或纠正再失败立即停止；不自动填参、不选任务或形成重试循环。未进入业务提交不占稿件槽。
- 合法任务内已有机制支持的结构/字段/选择错误：原作者同一任务最多首稿加一次修订，只用反馈的 `base_draft_ref`和 `allowed_paths`提交精确补丁，保留两稿、完整重验。第二稿仍失败终止，不另派作者、创建新任务重置额度或生成第三稿；权限/身份/PIT/完整性/隔离错误不进入此分支。
- 适用fixture Risk修订沿原CIO修订槽，不与格式修订叠加增加稿件；硬否决不可覆盖。宿主不能支持原作者纠正时报告能力缺口，不用通用Agent或旧Hook模拟。

主线程在阶段内以精确回执完整读取报告，分页读至末页再归集，不猜最后一稿。业务有效、实际执行、基本内容与操作可用性分列；保存回执或文件存在不证明全部完成，不匹配旧投资观点作为验收条件。产品运行不编辑源码/配置，不执行开发归档、Git发布、专项Eval/Replay或Promotion；所有结论仅供研究参考。
