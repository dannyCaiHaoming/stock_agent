# 三个角色的输出格式

三方读取同一份共享数据。每条证据都写明：所用方法卡（id@version）、数据与期间、来源（source_id / accession），有统计就引用 `get_signal_stats` 的结果（样本数、主窗口 60 日 `mean_percentile_minus_50`（同日全股票池百分位−50，百分位点）及两个置信区间、状态），有案例就引用 `get_reference_cases` 的案例 id。

## 正向初稿（advocate）

```
# {TICKER} 正向论点（数据截至 {as_of}）
## 选用的方法与理由
| 方法卡 | 适用？ | 理由 |
## 投资论点
- 业务驱动：…（附数据）
- 预期差：价格隐含了什么（implied-expectations），我认为实际会怎样，为什么
- 催化剂：什么事件、大约何时会让预期差显现
## 证据
| # | 方法卡 | 事实与数字（期间、来源） | 统计证据（信号、n、60 日均值 vs 对照、状态） | 案例（id） |
## 可验证预测
| 目标 | 方向 | 概率 | 何时可验证 |   ← 目标与 forecasts 一致：revenue_growth、operating_margin、relative_return_126d、guidance
## 失效条件（出现什么就说明论点错了）
```

## 反向初稿（skeptic，第一步：独立）

```
# {TICKER} 反向论点（数据截至 {as_of}）
## 选用的方法与理由
## 主要风险（每条：风险 → 触发条件 → 对经营或估值的影响 → 是否已有证据显示正在发生 → 是否已被定价）
## 证据（同正向格式）
## 可验证预测
## 什么证据会证明我错
```

## 反向补充（skeptic，第二步：读正向论点后只补一轮）

```
# {TICKER} 对正向论点的核验
## 关键前提检验
| # | 正向论点的前提 | 证据是否支持（附工具依据） | 替代解释 | 若前提不成立的影响 |
## 正向遗漏的风险
## 结论：是否存在足以改变结论的反证（可以写“未发现足以改变结论的反证”，并说明查过什么）
```

## CIO 判断

写进报告：
- 时间尺度：本次判断针对的仓位类型（未持有 / 长线核心仓 / 交易仓）与主窗口；
- 方法适用性：采用了哪些方法卡、为什么；哪张卡在本案不适用；
- 多空权衡：两方证据中哪些决定结论、哪些被打折扣，统计与案例怎么用（样本不足的标“需要验证”，不当作依据）；
- 行情与持仓：当前趋势阶段、相对强弱、市场环境与用户持仓（如有）如何影响动作与仓位；
- 动作、仓位、方向预测（forecasts）、改判条件（经营事件触发，不设固定价格上限）。
