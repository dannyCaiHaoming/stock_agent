# 计划复核

这是研究建议，不执行交易。先遵守 `research-standards`。设计依据：`docs/design-position-lifecycle-2026-11-28.md` §3.6。

**复核的问题不是“股价涨了还是跌了”，而是“当初写下的理由，被新的公开事实增强、动摇还是推翻了”。** 价格只在第二步出现。

**原则**：
- 原计划是基准，不改写。之后的条件变化用 `revise_trade_plan` 追加版本，并写明理由与来源。
- 论点结论与上一次不同，必须指出一条在上一次复核（或计划冻结）之后才公开的**非价格**证据（公告、报道等）。只有价格变了、没有新事实，论点结论就不变，价格在第二步的动作里处理；工具会拒收没有新证据的改判。
- 不要因为亏了就说公司变差，也不要因为涨了就说论点增强。
- 结论与上一次相反、却说不清新证据时：保持原结论，把分歧写给用户，由用户决定。不要反复重跑挑结果。
- **历史回放**：带 `as_of` 参数的数据工具都传同一个日期；计划工具（`get_trade_plan`、`save_plan_review`、`revise_trade_plan`）由会话的回放设置自动限定，只看得到截止前的记录；保存时传 `replay_as_of`；不得使用你对该日期之后事件的记忆。

## 步骤

### 第一步：论点（这一步不要调用任何价格工具）
1. `get_trade_plan(plan_id, view="thesis")`：只读论点、催化剂、放弃理由的事实、持有依据、复核日，以及以往复核的论点结论与经营证据（这个视图不含价格、动作和报告全文）。记下上一次复核（或计划冻结）的时间。
2. 找这之后新公开的材料：`list_filings`（8-K、10-Q/10-K）、`get_filing_text`；`get_news_history`（回放）或联网检索。每条记下发布时间与来源：`published_at` 写 `YYYY-MM-DD`，或带时区的完整时间（如 `2026-03-03T16:05:00-05:00`）；盘中复核时，当天发布的材料必须写精确时间（只有日期会被拒收）。`get_market_context` 含价格，留到第二步。
3. 逐条对照原计划：
   - 每条**放弃理由的事实**：出现了 / 没出现 / 部分出现 / 还不能判断（例如财报还没发）；
   - **持有依据**中的经营部分：还成立吗；
   - 催化剂：被确认、被削弱，还是被新事件取代。
4. 写出论点结论，五选一：
   - `strengthened` 增强：新事实支持论点（例如指引再次上调）；
   - `unchanged` 不变：没有改变判断的新事实；
   - `weakened` 动摇：出现不利事实，但放弃条件还没有完全满足；
   - `broken` 已坏：放弃理由的事实已经出现；
   - `insufficient` 资料不足：关键材料还没公开或查不到。
   在这一步结束前，把结论和证据先写进报告的“论点复核”一节。

### 第二步：价格与动作
5. `get_trade_plan(plan_id)`（完整视图：失效位、入场、以往动作）、`get_price_history`（计划冻结以来）、`get_market_context`：当前价格与失效位的距离、自成交以来的涨跌、大盘与板块同期表现。价格失效位本身是原计划条件，在这里核对：收盘已跌破就写明（结算会在下一开盘按规则离场）。
6. 动作，三选一，必须能追到原计划条件：
   - `HOLD`：论点 unchanged / strengthened，价格未触失效位；
   - `REDUCE`（卖剩余的一半）：论点 weakened，或你认为风险明显上升但放弃条件尚未满足；
   - `EXIT`：论点 broken，或价格失效位已触发，或已到持有依据写明的离场条件。
   动作和原计划条件对不上时（例如论点 unchanged 却要 EXIT），设 `plan_deviation=true` 并写 `deviation_reason`。
7. **要调整条件吗**：只有新事实支持时才用 `revise_trade_plan`，可改的只有 `price_invalidation`、`hold_basis`、`review_dates`、`abandon_facts`。R0 不会变。写明 `reason` 与 `sources`。
   - **浮盈保护（每次复核都要回答）**：先算当前浮盈是几 R（(当前价 − 成交价) × 股数 ÷ R0）。浮盈达到约 2R 以上、且论点为 `unchanged` 或 `strengthened` 时，判断要不要把失效位上移，给出“是 / 否”和理由，写进“价格与动作”一节：
     - 上移的位置要有依据（例如新的平台下沿、财报反应日低点、近 20 日内的重要低点），不是固定百分比；
     - 上移要留出正常波动的空间（参考近 20 日的日波动），避免被噪声震出，让利润继续跑；
     - 不上移也要说为什么（例如价格离任何支撑都远、上移只会被正常波动打掉）。
   - 这是判断，不是规则：目的是“赢家拿住、但不把大部分浮盈还回去”，不是尽快锁利。
8. 写复核卡（模板见下），展示给用户，然后 `save_plan_review`。

## 保存参数

`save_plan_review`：`plan_id`、`thesis_verdict`、`evidence`（`[{kind: filing|news|price|other, source, published_at, claim, original_condition}]`，`original_condition` 写对照的原计划条件原文）、`action`、`action_reason`、`report_markdown`、`plan_deviation`、`deviation_reason`、`model`、`host`；回放时加 `replay_as_of`。

`NEW_EVIDENCE_REQUIRED` 表示你改了论点结论却没有给出上一次之后公开的证据：要么补上真实的新证据，要么把结论改回去。不要编造发布时间。被拒收时改正后重试一次；仍失败就告诉用户。
