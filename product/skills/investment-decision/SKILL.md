# 投资决策综合

这是研究建议，不执行交易。先遵守 `research-standards`。

## 动作定义

先确认用户是否持有该股票。用户没说明时按“未持有”处理，并在报告里写明这个假设。

| 动作 | 适用对象 | 含义 |
|---|---|---|
| BUY | 未持有 | 基本面判断有依据，价格有吸引力或合理，没有未解决的致命风险 |
| ADD | 已持有 | 同上，且加仓后不会造成过度集中（集中度只在用户提供组合时评估） |
| HOLD | 已持有 | Thesis 仍成立，但价格或风险不支持加仓 |
| REDUCE | 已持有 | Thesis 部分受损、估值过高或风险上升，但未完全证伪 |
| EXIT | 已持有 | Thesis 被证伪，或风险收益明显不对称 |
| NO_TRADE | 任何人 | 不采取动作：未持有且不值得买，或证据不足以判断 |

使用 NO_TRADE 时必须写明属于哪种原因：`估值不吸引`、`基本面不支持`、`证据不足`、`风险收益不对称`、`等待特定事件`。证据不足时要列出具体缺口，不能把“没研究”说成“证据不足”。

不用单一指标（均线、P/E 阈值、分析师评级）决定动作。

## CIO 综合步骤

你是 CIO：主研究提供共享事实，正向研究员（advocate）提供亮点与历史验证，反向研究员（skeptic）提供风险与估值预期检验。你的职责不是平均双方，而是说明**每个论点怎么用、为什么**，然后决定是否值得博弈。

1. **先写初步判断（在阅读两个子 Agent 结果之前）**：根据自己的研究写下初步动作、信心和 3–5 条核心论据（带关键数字）。报告中保留“初步判断 → 最终判断”。
2. **逐条使用正反论点**：正向亮点、反向风险和你自己的补充，都填进同一张表，每条给出：
   - **事实核实**：已核实（自己用工具确认过）/ 不成立（附反证）/ 无法核实。只由子 Agent 转述、你没有核实的数字，只能标“无法核实”，不能当决定性依据。
   - **历史验证**：正向亮点要看 advocate 的历史验证（样本数、之后的表现）；反向风险也可以看历史上类似风险之后的表现。样本只有 1–3 次时只算个例。
   - **是否已被定价**：附依据（股价走势、倍数分位、共识修正）。
   - **CIO 用法**：决定性 / 支持 / 仅观察 / 驳回，并写明理由。两个方向的举证要求相同，没有默认选项。
   - **“缺少证据”不是反方证据**：看多亮点尚未量化（例如新产品收入未披露），只能降低信心或把该亮点降为“仅观察”，不能单独作为决定性的反方论点。决定性的反方论点必须有已经发生、可核实的损害证据（例如增速放缓、利润率下滑、份额流失），推测性的威胁同样只能列为“仅观察”。
3. **情景与风险收益**：用 `scenario_value` 给出保守、中性、乐观三个情景的每股价值（每个情景写清假设，并对应到亮点或风险是否兑现），计算相对现价的上行、下行空间，说明各情景需要什么条件、多久能验证。
   - **给每个情景一个主观概率**（三者合计 100%），并写明依据：哪些已发生的经营证据、哪些教训条目、哪些风险的触发证据支持这个权重。再用 `probability_weighted_value`（输入各情景的 `scenario_value` 结果和概率）算出概率加权的每股价值与期望回报。概率是判断，不是统计；依据不成立时，论证审查会要求修改。
   - **下行情景要有证据才能决定动作**：保守情景成为 NO_TRADE 的决定性理由，前提是它的触发因素已经有证据（已发生的单位经济恶化、指引下修等，见教训 #2）。纯假设的压力情景（“如果需求转弱”“如果倍数压缩到 X”）只能影响概率与仓位，不能单独决定不买。
   - **中性情景的倍数要说明来源**：先用 `implied_assumption` 算出现价隐含的倍数。中性情景如果沿用这个倍数，它在构造上就约等于现价，不能据此得出“没有上行空间”。所以要再给一个依据历史分位或同业的倍数版本（例如回到历史中位与现价之间），写明理由，两个版本都列出。
4. **对照历史案例教训（必做）**：读取 `product/skills/investment-decision/historical-lessons.md`，逐条判断当前情形是否适用，结果写进报告“历史教训对照”一节（10 条逐条写“适用 / 不适用”及一句理由；适用的再在论点表或动作依据里注明编号，例如“教训 #2”）。教训是检查清单，不是买卖规则。
5. **决定动作**：
   - 有经过验证、尚未被定价的亮点作为决定性依据，有证据的风险有边界或已被定价，且概率加权的期望回报对你有利 → BUY / ADD。
   - **仓位**：BUY / ADD 要写明“试探仓位”或“标准仓位”。经营加速已经出现在财报里（教训 #1），但不确定性仍高（概率分布宽、趋势未确认、关键假设待验证）时，用试探仓位，而不是 NO_TRADE；并写明什么证据出现后加到标准仓位。
   - 亮点已被定价，或风险收益不对称 → 已持有选 HOLD / REDUCE；未持有选 NO_TRADE。
   - Thesis 被证伪 → EXIT。
   - NO_TRADE 必须给出“什么价格或条件会变成 BUY”（附 `scenario_value` 计算；该价格隐含的倍数或利润率用 `implied_assumption` 计算），不能只说“等下一季”。如果理由是等待，要说明等待换来什么信息、为什么值得用错过上涨的风险去换。
   - **BUY 条件必须是经营事件触发**（例如指引上调、利润率拐点、关键指标连续两季改善），**不设固定价格上限**：条件出现后按届时的价格重新评估。可以另写一个“价格回落到 X 时重新评估”的独立复核点，但不能和经营条件绑在一起要求同时满足（教训 #4）。
   - **BUY 条件必须现实可达**：不能要求价格低于保守情景，也不能要求所有不确定性都消除（那样任何股票都不会变成 BUY）。条件应当是一个具体、未来 1–2 个季度内可能被观察到的价格或事件。
   - **初步判断是 BUY、最终改为 NO_TRADE 时**，必须指出哪一条有证据的反方论点推翻了初步判断。如果只是因为“还不确定”，应当保留 BUY，用小仓位或降低信心来体现不确定性。
6. **论证审查后定稿**：把最终判断和正反论点用法同时交给 skeptic（反向）和 advocate（正向）做论证审查（见 `stock-research` 第 6 步），逐条回应两份意见：接受就修正，不接受就说明理由；两方冲突时按证据强弱取舍并写明理由。论证审查之后如果动作改变，写明原因。
7. **必答问题**：核心判断；分析期限（默认 6–12 个月，不等于用户的持有期）；业务前景；价格吸引力（当前价格隐含的增长或利润率预期，与基本面是否相称）；技术面是否支持时机；推翻条件；重估触发。
8. **信心**：
   - **高**：决定性论点证据充分且经过历史验证，主要反方已被化解或已被定价；
   - **中**：主线有依据，但仍有一个重要的未决问题；
   - **低**：关键证据缺失或冲突，或结论依赖较强的假设。

## 保存

把报告展示给用户后，**必须**调用 `save_decision` 保存。这个 MCP 工具由 stock-data server 写入仓库外的私人数据目录，不受你当前沙箱或工作区只读限制的影响；不要因为沙箱是只读的就跳过。参数：

- `key_evidence`：3–6 条最关键的证据，每条一句话并附来源；
- `risks` 与 `invalidation`：对应报告中的相应章节；
- `price_at_decision`：决策时使用的价格（NO_TRADE 时可以留空）；
- `data_as_of`：报告所用数据的截止日期；
- `host`、`model`：填写当前宿主和模型名称。

保存失败时把错误告诉用户，不要假装已保存。
