# 投资决策综合

这是研究建议，不执行交易。先遵守 `research-standards`。

## 动作定义

先确认用户是否持有该股票。用户没说明时按“未持有”处理，并在报告里写明这个假设。

| 动作 | 适用对象 | 含义 |
|---|---|---|
| BUY | 未持有 | 基本面判断有依据，价格有吸引力或合理，没有未解决的致命风险 |
| ADD | 已持有 | 同上，且加仓后不会造成过度集中（集中度只在用户提供组合时评估） |
| HOLD | 已持有 | Thesis 仍成立，但价格或风险不支持加仓 |
| REDUCE | 已持有 | Thesis 部分受损、估值过高或风险上升，但未完全证伪 |
| EXIT | 已持有 | Thesis 被证伪，或风险收益明显不对称 |
| NO_TRADE | 任何人 | 不采取动作：未持有且不值得买，或证据不足以判断 |

使用 NO_TRADE 时必须写明属于哪种原因：`估值不吸引`、`基本面不支持`、`证据不足`、`风险收益不对称`、`等待特定事件`。证据不足时要列出具体缺口，不能把“没研究”说成“证据不足”。

不用单一指标（均线、P/E 阈值、分析师评级）决定动作。

## 综合步骤

1. **先写初步判断（在阅读 skeptic 结果之前）**：根据自己的研究写下初步动作、信心、核心论据（3–5 条，每条带关键数字）和估值逻辑。之后的处置都以它为基准，报告中保留“初步判断 → 最终判断”，看得出反方实际改变了什么。
2. **必答问题**：
   - 核心判断是什么？
   - 分析期限（默认 6–12 个月；这不等于用户的持有期）；
   - 业务前景：向好 / 中性 / 向坏；
   - 价格吸引力：有吸引力 / 合理 / 偏贵 / 无法判断。要说明当前价格隐含的增长或利润率预期，与基本面是否相称，例如 10% 增长能否支撑 30 倍 P/E；
   - 技术面是否支持当前时机；
   - 最强反方论点与最强看多论点，以及各自的处置；
   - 推翻条件、重估触发。
3. **挑战处置（两栏，门槛对称）**：skeptic 独立首轮与论证审查的每一条，以及你自检补充的论点，都分两栏处置：
   - **事实核实**：已核实（自己用工具确认过）/ 不成立（附反证）/ 无法核实。只由 skeptic 转述、你没有核实的数字，只能标“无法核实”。
   - **对结论的影响**：推翻论点 / 削弱 / 已反映在价格中 / 被其他因素抵消 / 无关。
   - 任何一种处置都要给出依据，判定“削弱”和判定“已反映在价格中”的举证要求相同，没有哪一种是默认选项。“已反映在价格中”要有依据，例如股价已大幅下跌、倍数已处于历史低位、共识已下修。
4. **看多检验**：写出最强的看多论点（在什么价格、什么条件下值得买，或值得继续持有），并同样分两栏处置。结论为 NO_TRADE 时，必须说明看多论点为什么不足，以及什么价格或条件会改变结论。
5. **冲突处理**：各维度结论不一致时（例如基本面好但估值偏贵、技术走弱），明确说出哪个维度主导了决策、为什么。不投票，不平均，也不因为风险条目多就默认不买：要比较风险是否已被定价。
6. **信心**：
   - **高**：核心证据充分且一致，主要反方已被证据化解；
   - **中**：主线有依据，但仍有一个重要的未决问题；
   - **低**：关键证据缺失或冲突，或结论依赖较强的假设。

## 保存

把报告展示给用户后，**必须**调用 `save_decision` 保存。这个 MCP 工具由 stock-data server 写入仓库外的私人数据目录，不受你当前沙箱或工作区只读限制的影响；不要因为沙箱是只读的就跳过。参数：

- `key_evidence`：3–6 条最关键的证据，每条一句话并附来源；
- `risks` 与 `invalidation`：对应报告中的相应章节；
- `price_at_decision`：决策时使用的价格（NO_TRADE 时可以留空）；
- `data_as_of`：报告所用数据的截止日期；
- `host`、`model`：填写当前宿主和模型名称。

保存失败时把错误告诉用户，不要假装已保存。
