# 投资决策综合

这是研究建议，不执行交易。先遵守 `research-standards`。

## 动作定义

先确认用户是否持有该股票。用户没说明时按“未持有”处理，并在报告里写明这个假设。

| 动作 | 适用对象 | 含义 |
|---|---|---|
| BUY | 未持有 | 基本面判断有依据，价格有吸引力或合理，没有未解决的致命风险 |
| ADD | 已持有 | 同上，且加仓后不会造成过度集中（集中度只在用户提供组合时评估） |
| HOLD | 已持有 | Thesis 仍成立，但价格或风险不支持加仓 |
| REDUCE | 已持有 | Thesis 部分受损、估值过高或风险上升，但未完全证伪 |
| EXIT | 已持有 | Thesis 被证伪，或风险收益明显不对称 |
| NO_TRADE | 任何人 | 不采取动作：未持有且不值得买，或证据不足以判断 |

使用 NO_TRADE 时必须写明属于哪种原因：`估值不吸引`、`基本面不支持`、`证据不足`、`风险收益不对称`、`等待特定事件`。证据不足时要列出具体缺口，不能把“没研究”说成“证据不足”。

不用单一指标（均线、P/E 阈值、分析师评级）决定动作。

## CIO 综合步骤

你是 CIO：主研究提供共享事实，正向研究员（advocate）提供亮点与历史验证，反向研究员（skeptic）提供风险与估值预期检验。你的职责不是平均双方，而是说明**每个论点怎么用、为什么**，然后决定是否值得博弈。

1. **先写初步判断（在阅读两个子 Agent 结果之前）**：根据自己的研究写下初步动作、信心和 3–5 条核心论据（带关键数字）。报告中保留“初步判断 → 最终判断”。
2. **逐条使用正反论点**：正向亮点、反向风险和你自己的补充，都填进同一张表，每条给出：
   - **事实核实**：已核实（自己用工具确认过）/ 不成立（附反证）/ 无法核实。只由子 Agent 转述、你没有核实的数字，只能标“无法核实”，不能当决定性依据。
   - **历史验证**：正向亮点要看 advocate 的历史验证（样本数、之后的表现）；反向风险也可以看历史上类似风险之后的表现。样本只有 1–3 次时只算个例。
   - **是否已被定价**：附依据（股价走势、倍数分位、共识修正）。
   - **CIO 用法**：决定性 / 支持 / 仅观察 / 驳回，并写明理由。两个方向的举证要求相同，没有默认选项。
3. **情景与风险收益**：用 `scenario_value` 给出保守、中性、乐观三个情景的每股价值（每个情景写清假设，并对应到亮点或风险是否兑现），计算相对现价的上行、下行空间，说明各情景需要什么条件、多久能验证。
4. **决定动作**：
   - 有经过验证、尚未被定价的亮点作为决定性依据，风险有边界或已被定价，且情景的风险收益对你有利 → BUY / ADD（可以是“小仓位试探”，在理由中说明）。
   - 亮点已被定价，或风险收益不对称 → 已持有选 HOLD / REDUCE；未持有选 NO_TRADE。
   - Thesis 被证伪 → EXIT。
   - NO_TRADE 必须给出“什么价格或条件会变成 BUY”（附 `scenario_value` 计算），不能只说“等下一季”。如果理由是等待，要说明等待换来什么信息、为什么值得用错过上涨的风险去换。
5. **论证审查后定稿**：把最终判断和正反论点用法交给 skeptic 做论证审查（见 `stock-research` 第 6 步），逐条回应审查意见：接受就修正，不接受就说明理由。论证审查之后如果动作改变，写明原因。
6. **必答问题**：核心判断；分析期限（默认 6–12 个月，不等于用户的持有期）；业务前景；价格吸引力（当前价格隐含的增长或利润率预期，与基本面是否相称）；技术面是否支持时机；推翻条件；重估触发。
7. **信心**：
   - **高**：决定性论点证据充分且经过历史验证，主要反方已被化解或已被定价；
   - **中**：主线有依据，但仍有一个重要的未决问题；
   - **低**：关键证据缺失或冲突，或结论依赖较强的假设。

## 保存

把报告展示给用户后，**必须**调用 `save_decision` 保存。这个 MCP 工具由 stock-data server 写入仓库外的私人数据目录，不受你当前沙箱或工作区只读限制的影响；不要因为沙箱是只读的就跳过。参数：

- `key_evidence`：3–6 条最关键的证据，每条一句话并附来源；
- `risks` 与 `invalidation`：对应报告中的相应章节；
- `price_at_decision`：决策时使用的价格（NO_TRADE 时可以留空）；
- `data_as_of`：报告所用数据的截止日期；
- `host`、`model`：填写当前宿主和模型名称。

保存失败时把错误告诉用户，不要假装已保存。
