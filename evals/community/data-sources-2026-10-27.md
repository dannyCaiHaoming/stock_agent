# 社区关注度/情绪数据源探查（2026-10-27）

范围：moomoo `stock_feed`（只读公开 HTTP，`ai-news-search.moomoo.com`）。探查脚本与原始响应在 `.local/runs/community-probe/`。

## 1. 原始字段

`GET /stock_feed?keyword=<TICKER>&size=<N>` 返回 `{code, data:[...]}`，每条帖子只有 4 个字段：

| 字段 | 说明 |
|---|---|
| `id` | 字符串，随时间单调递增，可用于去重与排序 |
| `title` | 常为空或是带 HTML 的片段；官方/媒体文章则是标题 |
| `publish_time` | Unix 秒 |
| `desc` | HTML 正文，含 `<nnstock stocksymbol="XXX.US">` 标的标签（可抽取帖内提及的所有标的） |

没有：作者 ID/昵称、点赞、评论数、浏览量、语言字段、帖子类型、情绪标签。结论：**无法计算“不同发帖人数量”和“互动加权”**。唯一可替代的是正文推断的语言、帖内提及标的、文本长度。
内容混杂：用户短帖、广告/拉人头（referral）、盘前晨报、新闻稿、中文与英文混合（热门股 50 条里约 15–25% 为中文）。`keyword` 接受 `NVDA`、`US.NVDA`、中文名；`NVDA.US` 不被识别。

## 2. 分页与历史

- `size` 上限 50（>50 返回 `code=1 size不能超过50`），其他参数（page/offset/cursor/before/end_time/max_id/sort/order/lang 等 15 种）全部被忽略，返回的永远是**最新 50 条**。无分页、无历史端点（comment_feed 等 404）。
- 50 条覆盖的时间跨度随热度剧变：当天快照 106 只中，最忙的 GOOGL/MU/SNDK/TSLA 约 6 小时，NVDA 8–13 小时（取决于时段），中位数约 26 天，冷门股可达数月到一年多。
- 结论：**无法回溯历史**。热门股要覆盖 24 小时，需要盘中多次抓取（建议每 3–4 小时，UTC 全天），按帖子 `id` 去重合并；冷门股一天一次足够，但其帖子率噪声大（50 条跨数月，说明日均不足 1 条）。研究只能向前积累，现有 `.local/data/history/community/*.jsonl`（2026-10-20 起）可作为小规模回放样本，但每只股票每天只有最新 50 条，对热门股存在大量缺口，不能当连续序列用。
- 服务条款/限流：vendor 笔记（`product/vendor/moomoo-skills.md`）未写限流数；快照现行约 1 请求/秒、106 只连续请求未出现 429。无明确使用条款，保持低频、只读、仅作研究。

## 3. `moomoo-comment-sentiment` Skill

它只是提示词流程（SKILL.md），没有脚本：用同一个 `stock_feed`（默认 size 30，最多 50）取最新帖，由 LLM 在对话中过滤低质量帖、分类 bull/bear/neutral，输出 bull_pct/bear_pct/neutral_pct、有效帖数、代表观点、`time_range_earliest/latest`（东京时间）。
- 窗口：最新 N 条，不是固定时间窗，热门股只有数小时。
- 可复现性：数据随时间滚动；分类由 LLM 完成，同一批帖子不同次调用结果会不同，不可作为稳定因子。
- 约束：按 AGENTS.md，moomoo 的方向/情绪判断只作参考展示。研究用指标一律由我们对原始帖子自行计算；moomoo 标签（如以后出现）只作为对照记录。本次未调用该 Skill（无对话内 LLM 分类可复现），仅核对其数据契约与上面一致。

## 4. 隐私

- 现有接口不返回作者，不涉及个人标识。
- `scripts/snapshot-daily.py` 已预留：若上游以后出现 uid/昵称类字段，只写入 `author_hash`（SHA-256(盐+值) 前 16 位），盐在 `.local/data/community-salt`（随机生成、不入库），原始 ID/昵称不落盘。点赞/评论/浏览等字段若出现会原样保留，并在 `extra_fields` 列出任何未识别的新字段，便于发现接口变化。
- 帖子正文属第三方内容，保存在已忽略的 `.local/`，不提交。

## 5. 可计算 / 不可计算

可计算（自行从原始帖子算）：
- 每小时发帖率：`50 / span.hours`，或多次快照去重后按小时计数；对自身历史取 z-score/分位。注意热门股 50 条被截断，单次快照的率是右删失的，应以去重合并后的分钟/小时计数为准。
- 内容层面的“来源多样性”代理：去重后的标题/正文指纹数、模板化/广告帖占比、中文占比（`cjk_ratio`）。
- 话题集中度：`mentions`（帖内同时提及的标的）——例如纯该股帖 vs 大盘晨报；正文关键词熵。
- 自算多空倾向及其变化、分歧度：需要另建分类器（如 LLM 逐帖标注、事先固定提示词并记录版本），不依赖 moomoo 标签。

不可计算：
- 不同发帖人数、作者集中度、互动加权、浏览量——接口没有这些字段。
- 任何 2026-10-20 之前的历史序列；冷门股的短期（<1 天）帖子率。
- 严格的“帖子领先于价格”识别：只有帖子时间戳，没有行情对齐；需用 `publish_time` 与分钟级价格对齐，并以发帖前已知的收益作为控制变量（帖子跟随价格移动是主要混杂）。

## 6. 对快照脚本的改动

见 `scripts/snapshot-daily.py`：新增 `--out-dir`、`--rerun`（同日追加）；每行记录 `request_size` 与 `span`（最早/最晚时间、跨度小时）；每条帖子新增 `mentions`、`cjk_ratio`、`text_len`、`extra_fields`，以及上游若提供时的 `author_hash` 与互动字段；`code != 0` 时抛错进入重试/失败记录。旧字段保持不变。要覆盖热门股 24 小时，需要把社区快照改为每日多次调用 `--only community --rerun`（调度由用户决定，未改动）。
