## ADDED Requirements

### Requirement: 新版研究级 CIO 必须显式记录来源处置和全部目标挑战

显式启用 predecision-cio-synthesis/3.0.0 的单股或已确认持仓研究级 CIO SHALL 对每份已交付的非 Skeptic 报告在 source_dispositions 中记录采用、限制、不采用或未用于判断，包含报告引用、实际复核的原 claim_id、存在时可选的 gap_id、理由和判断影响。报告没有稳定 gap_id 时 MUST 保留作者的缺口说明而不编造 ID。原 Skeptic 报告 SHALL 经 challenge_dispositions 对目标证券的全部正式 challenge 逐项处置，保持原挑战对象及影响，不由 Python 按投资重要性筛选。所有处置对象 MUST 来自同 invocation 已实际完整读取的获准报告；未知对象、重复或遗漏报告/目标挑战、跨类型或跨来源引用须拒绝。机械校验不得签内容 PASS，也不得自动产生处置或改写作者取舍。

#### Scenario: 十份报告已交付但只回应一条挑战
- **WHEN** 新版 CIO 的获准目录含 Company、多维及目标 Skeptic，输出遗漏某份非 Skeptic 报告处置或某条正式目标挑战
- **THEN** 拒绝新版输出并保存具体遗漏，不以 consumed_reports 非空或已回应一条挑战作为全部覆盖证明

#### Scenario: 缺口没有稳定对象 ID
- **WHEN** 获准原报告的某缺口只有文本，没有 gap_id
- **THEN** CIO 可以在对应报告处置理由中准确说明该缺口及影响，gap_ids 留空；程序不生成虚假原对象、不强迫把缺口变为 challenge

### Requirement: 新版研究级 CIO 必须逐项支持事实和 Macro Market 判断

新版 key_facts 与 macro_market_transmission SHALL 逐项表达直接 Evidence 或精确冻结计算支持。直接事实引用 MUST 属于当前 Gate 并由本 CIO invocation 实际 query，不能以读过上游报告替代；事实血缘保留 source_id、as_of、retrieved_at、期间、单位和证券身份。计算支持 MUST 由作者从实际读取报告中明确选择，绑定原报告版本/内容 hash、原主张、计算身份、成功收据或预计算产物 hash、方法、值、单位、窗口、证券/基准和原输入血缘，并重验 PIT 及同源闭合。计算输入血缘不构成本 CIO 对原始事实的 query 证明，计算结果不得偷换成未经 query 的直接事实。每项 key_fact MUST 有直接 Evidence 或合格计算；传导项须区分有支持的分析与明确未知，不得以无依据文字冒充已验证方向。不开放 CIO calculate、搜索、联网或新提交工具，不建立新计算后端。

#### Scenario: 读取上游报告后选择精确相对收益结果
- **WHEN** CIO 从已读报告的实际主张选择合格的目标/基准同窗口相对收益计算
- **THEN** 可信装配保留原值、单位、窗口、双方身份、报告及产物绑定，本条引用精确对应；不要求模型抄 hash 或血缘，也不把计算输入全部记作 CIO 已 query

#### Scenario: 计算存在但选错指标或未经原主张引用
- **WHEN** 选择不在原主张 calculation_refs 中、产物已漂移、引用跨 run，或对象不存在
- **THEN** 原机械门禁拒绝；若对象合法但其窗口/指标不支持作者措辞，则由内容验收判失败，程序不按正文补选或替换

#### Scenario: 直接事实未 query
- **WHEN** 输出直接采用上游报告中的公司披露、政策或利率事实，但本 CIO invocation 没有 query 对应 Evidence
- **THEN** 拒绝直接引用，不将完整报告读取、冻结计算输入或开发读取冒充同 invocation 查询证明

#### Scenario: 传导净影响无法量化
- **WHEN** 已查询政策/利率、读取并选择目标/基准窗口，但资料无法证明公司的净盈利影响
- **THEN** 作者以实际支持分析条件机制、相反窗口和边界，明确净影响未知；不能用未知免除对已有材料的取舍，也不能将市场相关性写成公司因果结论

### Requirement: 新版研究级 CIO 中文报告必须同源展示处置与支持关系

新版 JSON 与中文报告 SHALL 同源保留 source_dispositions、原挑战对象与取舍、关键事实/传导的 Evidence 和计算对应、实际窗口及覆盖限制。渲染 MUST 不补结论、不替作者改研究立场、不隐藏不采用或未知理由。新版协议 MUST 由准备请求、交付、模型格式、可信装配、finalizer、checker 和读取/渲染共同显式绑定；未知或错配版本须拒绝，不能按字段存在猜协议或退回旧格式。旧 v1/v2、MRVL、旧持仓及 fixture 的 Schema 字节与已有执行/读取边界 MUST 保持，不迁移历史锁或把旧报告重认证为 v3。新研究级持仓请求只能沿原已授权证券范围启用新版，仍仅 RESEARCH_SYNTHESIS、账户适配未评估、Risk=NOT_RUN，不开启 PORTFOLIO_ADVICE、动作或新资产能力；无账户列表须由独立列表 Change 接线显式输入版本。

#### Scenario: 新版 JSON 有计算支持
- **WHEN** 新综合成功装配关键事实和传导的精确支持及来源处置
- **THEN** 中文报告可查看对应关系及作者原理由，与正式 JSON 一致；保存和渲染成功只算执行/契约证明，不自动成为研究内容 PASS

#### Scenario: 旧报告或错配交付
- **WHEN** 读取旧 v2 报告，或新请求/Schema/草稿协议不一致
- **THEN** 旧报告按原版本读取并保留旧边界；错配新版拒绝，不修改旧包、不自动降级新写入

### Requirement: 新研究宿主必须保存可解释的分段计时与固定执行预算

本次显式新版 Company、多维、Independent Skeptic 与 CIO 宿主 SHALL 记录可信 UTC 和同一宿主单调时钟的准备、进程创建、通信、本组清理、校验及渲染起止和耗时，保存实际传入预算、预算范围及固定 deadline。执行预算 SHALL 从进程创建前的单调时钟起算，通信只能使用剩余预算；输出、连接重试和 Hook 消息不得刷新期限。同步进程创建不可抢占及操作系统暂停/时钟跳变的保证边界 MUST 明示，墙钟超额与通信 timeout 必须分开，不把未观测时间推断为模型等待。清理沿原有界 grace 执行且单独记录，不延长研究预算。保留专属进程组、TERM/KILL、超时 124、中断 130、原字节日志、权限拒绝不重试、无关进程隔离及远端取消 UNKNOWN；不改代理、认证、权限、原 timeout 或 Hook 修订上限。

#### Scenario: 延迟创建或持续输出
- **WHEN** 进程创建消耗部分预算，或通信期间持续输出及连接重试
- **THEN** 剩余预算由同一个 deadline 算出，不重新开始完整预算；创建返回时已超额须进入超时与有界清理，记录不可抢占创建的实际耗时，不冒称准时取消了创建

#### Scenario: 通信成功但最终报告生成较晚
- **WHEN** 通信没有超时而校验、清理或渲染导致整体墙钟明显较长
- **THEN** 终态区分执行预算与总耗时，保存分段差额；时间证据不足须标未确认，不据进程零退出宣称端到端时限满足

#### Scenario: 历史没有分段证据
- **WHEN** 复核旧 ALB 的 2400 秒配置、timed_out=false 与约 86 分钟墙钟差异
- **THEN** 保留原记录和原因 UNCONFIRMED，不倒填计时或将连接错误/新计时实现当作旧根因已修

### Requirement: 四阶段进度必须来自可信事件且等待不得越过终态

新版研究 SHALL 对 Company、多维、Independent Skeptic、CIO 及父依赖等待提供绑定 run/stage/task/invocation 的状态、等待对象、最后有效事件、已用/剩余预算与超时/中断/失败原因。执行终态、契约/持久化、内容裁定 MUST 分列；TERMINAL/SAVED 不代表内容 PASS。派发前、等待返回后和归集前须读取并重验本组状态；全部终态后结束等待，缺成功依赖但已有失败终态时立即阻断消费者。无进展阈值产生具体诊断，阈值/状态查询/输出心跳不得延长固定阶段期限；状态读取自身的锁/读取等待也须有界，漂移或无法可信读取时显式失败，不用模型猜状态。状态视图 MUST 不交付研究正文或正向结论给独立首轮 Skeptic，不赋予重派/写库能力，不新增监控 Agent 或第二调度器。

#### Scenario: Skeptic 已保存但通知没有到达
- **WHEN** 本组可信 Stop/产物证明所有 Skeptic 已终态，而协作等待仍返回空对象
- **THEN** 按可信终态归集，不继续空等；内容裁定仍独立记录，独立首轮不因状态读取获得正向报告

#### Scenario: Hook 局部修订尚未终态
- **WHEN** Hook 记录 REPAIR_REQUESTED 或 StopBlocked，但没有合法最终 Stop/产物
- **THEN** 状态不冒充完成，保持既有修订次数/字段边界与剩余预算；耗尽后保存真实失败，不无限续期或重新派发

#### Scenario: 状态锁等待超额或身份漂移
- **WHEN** 可信状态读取的锁不可用、事件绑定错误或产物 hash 漂移
- **THEN** 有界返回具体错误并阻断不可信归集，保留原事件，不等待无限锁或把模型自报作为回退状态

### Requirement: usage 与重复交付必须有可核实的范围且不得重复计费统计

新版研究 SHALL 按真实 invocation 记录模型、父子绑定、实际执行/未执行、usage 原事件/hash、统计范围与输入/输出/缓存字段的可用性；累计与增量事件 MUST 先辨别再去重，父级含子级或范围不明时不得将父子直接相加。缺失 usage、网络阶段、模型前失败与缓存命中 MUST 分开，未知不能写成零。交付次数、响应/Prompt/草稿字节、重复完整报告读取和模型 token MUST 分开；无可靠计费价格/缓存口径时不输出实测费用或省费比例。可得实际 usage 与缺失范围一并显示，不能为优化排名隐去失败消耗。

#### Scenario: 父累计统计含子调用
- **WHEN** 一个父累计事件可能包含三个子调用，子级还各有 usage
- **THEN** 明确统计范围并仅对可证明非重叠部分求和；范围未知部分单列，不将它们计算成四份独立费用

#### Scenario: 没有 usage 或只有字节缩小
- **WHEN** 某 invocation 无 usage，或工具响应无损压缩了 80% 字节
- **THEN** usage 缺失显示 UNKNOWN 与证据缺口，字节收益单列；不宣称 token/费用下降 80% 或该次模型成本为零

### Requirement: 上下文优化与消耗停止必须保留研究信息和授权边界

新版研究 SHALL 复用现有无损共享和定点查询/报告读取，减少重复机械元数据/血缘及无进展的相同大包重读，不过滤正文、反证、限制或模型选择依据。展开结果 MUST 与原完整语义投影一致，净增上下文时不启用伪优化；新增来源处置等字段的输入/输出代价一并测量。调用数、执行时间和可观测 usage 的批准上限 MUST 在派发前及新事件后核对；达到边界不启动后续模型，未知 usage 不视为剩余无限。若 Provider 只在完成后给 usage，则明确不能保证在途 token 硬上限，使用调用/时间约束与完成后停止，不宣传不存在的计费实时控制。不新增自动语义纠错循环、擅自换模型或删除研究 Agent。

#### Scenario: 合法重复读取与失控重复不同
- **WHEN** 作者因新 claim 需要重读某已获准报告，或连续请求无变化的完整大包
- **THEN** 前者沿原授权交付且记录用途/成本；后者显示重复及无进展，采用既有可核实共享/定位路径并受固定预算约束，不能由程序擅自拒绝必要依据或改研究文字

#### Scenario: usage 达到预算而下一任务尚未派发
- **WHEN** 可确认累计 usage 达到批准边界，或调用/执行时间预算耗尽
- **THEN** 不追加模型调用，保存已完成成果和未执行原因；在途任务按既定停止/清理政策处理，费用未知和可能的超额如实保留，不自动换模型继续
