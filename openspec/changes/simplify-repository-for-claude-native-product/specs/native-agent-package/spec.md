## Purpose

让共享投研方法、现有职责和确定性业务工具在当前原生宿主中使用，由宿主负责模型与专业执行，项目只管理必要业务契约；与就地Claude产品入口共同保留授权、来源、独立反证、历史产物及私人数据边界。

## ADDED Requirements

### Requirement: 研究方法与角色必须共享且宿主配置保持薄层
系统 SHALL 为自有Skills与现有四类职责维护一份权威正文，提供宿主原生角色、Skill发现、业务工具及权限的薄配置。Claude本地使用当前仓库product产品根，不强制外置源码副本；其他宿主仅保留已存在模板及未验收状态。不得新增统一Agent Runtime、模型API/SDK后端、会话管理器、调度器或事件翻译协议；第三方Skill和用户其他配置保持原样。

#### Scenario: 原生宿主发现共享内容
- **WHEN** 用户选择获准产品项目并配置必要原生能力
- **THEN** 使用同一权威研究正文及确定性业务，不复制私人状态、不启动另一宿主；静态发现与实际加载分别记录

#### Scenario: 同名用户配置或角色冲突
- **WHEN** 目标已有不同的同名角色、Skill或MCP定义
- **THEN** 写入前报告冲突，不覆盖用户文件、不默默使用错误来源、不改第三方Skill

### Requirement: 正常研究必须由当前宿主原生执行
正常产品请求 SHALL 由当前宿主主线程调用共享 Skill、委派原生专业 Agent 并在明确综合阶段担任 CIO。项目 Python/Shell MUST NOT 启动额外宿主模型进程、调用模型 API/SDK，或实现派发/等待/重试的另一套执行循环。业务工具的有限数据处理、确定性查询与持久化进程不属于模型执行。现有单股、确认持仓、资料准备、多维、独立反证和显式 CIO 的输入及停止点 MUST 保留；独立 Intake、交易记录和复盘不自动进入 Council。

#### Scenario: 当前会话请求单股完整研究
- **WHEN** 请求通过现有证券、资料和阶段授权校验
- **THEN** 当前宿主完成专业委派和主线程综合，Python 仅提供业务能力，不创建第二个 Codex、Claude Code 或 OpenCode 模型会话

#### Scenario: 历史宿主操作例外已结束
- **WHEN** 当前诊断或验收遇到实际加载缺口，而历史记录曾单独批准并使用一次原idle宿主定点重启
- **THEN** 该操作只作为历史证据，不授再次终止/重启、进程探测、换会话/连接或修改全局设置的权限；当前能力不足时记录最小外部依赖，不将生命周期控制加入业务路由、正常研究或新的诊断流程，不建立模型launcher或重连管理器

#### Scenario: 阶段依赖或原生委派不可用
- **WHEN** 必需报告不合法、必要工具不可用或宿主不能执行该专业职责
- **THEN** 对应阶段明确阻断并保留已完成成果，不换宿主、伪造报告、自动重试或开放未授权阶段

#### Scenario: 明确用户委托的任务交付到达指定产品会话
- **WHEN** 用户已明确采用当前研究范围和目标产品会话，并确认任务交付或委托开发侧管理该范围内的测试安排及定向转交
- **THEN** 产品主线程核对真实用户来源、模型/调用/时间/取证/权限和分类停止条件后执行，不要求逐轮重问已委托测试额度；转交不冒充用户批准、调用方认证、宿主权限批准或执行证据。规划确认不自动授权实施或启动新会话/任务，已关闭阶段不自动恢复，预算委托不扩大样本、模型、数据/副作用或最终批准权限；新会话不因旧会话获准而自动获得授权。最新明确用户选择优先于旧持续委托；“仅更新规划”期间不授诊断、准备、新作者、恢复或取证，后续明确采用并推进时先同步实际受影响规划，再按届时有效授权与Design当前方案执行，不追认旧超时调用、恢复旧余额或形成自动重试政策。

#### Scenario: 转交指令的原始用户来源需要独立核对
- **WHEN** 当前范围已有真实用户委托，但产品不能仅从peer引述确认来源，且宿主已有可用的原始消息读取能力
- **THEN** 完整交付可提供指定开发会话和原始用户消息的精确定位，由产品在登记的只读范围及预算内独立核对；不以peer转述、文件/hash或自动反馈代替用户，不代答待批准或已取消的问题，不修改权限。必要入口/权限或原始来源不可得则停止，不换入口或读全历史/私人数据库；该核对不固定为普通研究前置，也不扩大既定业务范围、预算或原作者修订上限

### Requirement: 独立研究和业务工具授权必须实际隔离
专业研究 SHALL 仅获得任务授权的证券、问题、Gate 资料和工具，独立 Skeptic 首轮 MUST 不继承正向结论或其他私人账户信息。宿主工具权限与服务端任务授权 MUST 同时生效；提示词、角色名字、任务 ID 或访问凭据单独均不得作为实际调用方认证或隔离证明。无法提供与现有边界等价的输入/工具隔离时 MUST 阻断对应能力，不通过配置存在或角色自报放行。

#### Scenario: 首轮 Skeptic 被注入正向结果
- **WHEN** 独立首轮输入包含 Analyst、Market 或 CIO 的结论、摘要或内部报告引用
- **THEN** 拒绝独立首轮研究，不能借用同会话换角色或后续针对性反证掩盖污染

#### Scenario: 专业候选实际工具多于或少于精确白名单
- **WHEN** 本轮实际委派或限定官方记录显示Company/Market不等于各自11项、Skeptic不等于原5项，或出现观察/准备、通用工具及其他角色能力
- **THEN** 即使模板可解析或服务端会拒绝越权，也保持专业隔离失败并停止依赖阶段；记录首个实际差异，区分已有因果证据的项目接线/宿主兼容问题与尚待定位，不以工具可见越界推定已经泄漏，不自动换根/包/入口、追加窗口、扩大白名单或新增Python过滤执行层

#### Scenario: 非法调用在写入前被拒绝
- **WHEN** 调用缺少授权、绑定另一任务或请求超出 Gate 的事实及计算
- **THEN** 服务端在返回事实或修改报告状态前拒绝，不占用被冒用任务的修订额度；拒绝后原合法任务仍可正常提交

### Requirement: 原生业务连接必须按请求和角色限定任务路由
原生研究业务MCP SHALL 绑定一个合法研究请求、冻结Gate和明确角色范围，每次业务调用使用准备边界授予的精确任务引用及对应任务能力凭据；同一原生角色的多个获准证券/能力任务不要求逐项修改宿主配置或重启模型会话。服务端 MUST 在资料返回、计算、稿件名额或持久化前重验请求、Gate、角色、任务和允许对象；未授权、混用或未知引用拒绝且不改变合法任务。连接及任务凭据均不替代真实宿主调用方认证或独立上下文证明。业务路由 MUST NOT 派发/等待/重试Agent、维护宿主会话/生命周期、创建后台任务或调用模型；原生执行仍由当前宿主主线程承担。旧单任务接口及已保存产物按其原范围保留，不能自动扩权为新路由。

#### Scenario: 同一角色处理两项获准任务
- **WHEN** 当前宿主原生Company或Market角色在同一研究请求内分别处理任务A和B
- **THEN** 同一业务连接按各自引用/凭据访问相应资料与提交，证券、Gate、计算和报告绑定不串用，不更改宿主执行参数或启动新模型进程

#### Scenario: 任务引用与凭据或角色错配
- **WHEN** 使用A的凭据调用B、跨研究请求引用、未知任务或由非授权角色请求
- **THEN** 在取证或副作用前拒绝，B的稿件名额/文件不变，原合法调用仍可完成；Skeptic不能读取正向结果

#### Scenario: 原生角色只读取精确的小型任务授权
- **WHEN** 操作方通过已有task准备命令显式指定agent-grant输出位置
- **THEN** 在私有源码外新文件确定性写入本任务引用/凭据、最小范围与来源时点，不交付完整任务/事实ID/资源表或操作方连接凭据；原完整授权格式不变，正文和输出契约仍通过受限业务工具读取，不从旧上下文猜测或回退任务授权

#### Scenario: 精确授权参数由既有准备边界机械交付
- **WHEN** 操作方沿明确现有任务的小包准备可转交参数，主线程需要自己的MCP参数或向对应专业转交任务
- **THEN** 开发侧操作方脚本复用原agent_grant并重验任务及资源锁，保留平铺授权及最小来源/范围，提供只由该小包精确派生的mcp_arguments与specialist_args；后者是可直接转交的JSON字符串，不含其他角色授权、结论或操作方凭据。主线程不重建或猜测token，外层授权不因draft只含语义而省略；Schema与服务端鉴权不变，不自动填缺参数、不选任务/作者、不派发模型或管理宿主状态。脚本不修改已锁product/tools源码，不改旧任务/hash或排除资源；漂移仍拒绝，新私有文件create-only，不为交付视图新建任务

#### Scenario: 小型授权输出位置不合法
- **WHEN** 指定输出是相对路径、源码内路径、公开目录、symlink、已存在或与完整授权同路径
- **THEN** 在新任务创建前拒绝，旧文件和任务名额不变，不回显秘密、不自动选择另一位置

#### Scenario: 大型事实允许集的上下文交付
- **WHEN** 原生任务的事实ID列表过大，调用research_context读取任务权限和输出契约
- **THEN** 工具返回显式有界ID页、总数及精确下一页偏移，完整允许集和输出契约不被截断；所有页保持同一任务授权和资源检查，目录不计作事实查询，计算输入血缘经已有计算工具读取

#### Scenario: 模型已选择的事实响应超过字节预算
- **WHEN** research_query的合法精确ID请求数量在允许范围内，但完整事实响应超过既有64KiB上限
- **THEN** 按请求顺序返回能装入预算的完整事实页及total/offset/next_offset，显式offset/limit可继续同一选择；小请求未指定分页且全量能装下时保持原响应。每页先重验整组ID的任务授权、Gate/PIT和资源，事实原字节语义、source_id/as_of/retrieved_at与原事实hash不改，不截断字段、跳过大事实或替模型选证据；单事实连同页信封仍超限时拒绝且不生成成功查询收据

#### Scenario: 分页查询只消费实际返回的事实
- **WHEN** 查询页只返回本次选中ID的一部分，或未返回页含未知、跨任务或排除事实
- **THEN** 成功查询收据的evidence_ids只包含实际返回事实，input_hash绑定原请求参数、result_hash绑定实际页；未读后页不能被提交为已查询。整组不合法在任何页面返回/收据写入前拒绝；非法页参数、单事实超限或资源漂移也不记成功，不新增自动翻页、模型重试或宿主生命周期控制

#### Scenario: 计算目录含大量重复输入血缘
- **WHEN** 已有成功计算或precomputed统计的完整目录超过工具响应预算
- **THEN** 通过既有research_calculations按offset/limit返回有界精确引用/原数值/单位/方法及血缘数量/hash；用calculation_ref与evidence_offset/evidence_limit显式读取完整输入ID页。实际JSON含页信封不超过65,536 UTF-8字节，不截断单项、不自动选择或翻页，不把ID目录当原始事实query；内部完整对象、k绑定和提交装配保持，小型未指定分页的合法原响应兼容

#### Scenario: 计算页越权、漂移或参数不合法
- **WHEN** 计算页使用未知/跨任务引用、非法参数或单项超限，或任务/Gate/PIT/资源/precomputed文件hash不符
- **THEN** 在数据返回前拒绝且无新运算/写入/稿件额度消耗；每页重新核验，并明确实际返回血缘范围和来源三字段，不扩大原始事实权限或回签已停止窗口

#### Scenario: 计算工具的可选参数被Responses路径严格化
- **WHEN** 原生宿主的Responses兼容路径将research_calculations五个可选参数都列为required，使省略另一模式参数的合法请求无法表达
- **THEN** 既有MCP适配层允许offset、limit、calculation_ref、evidence_offset、evidence_limit显式null，Schema验证及连接/任务鉴权后仅将这些null还原为省略，再调用原计算服务。目录无需ref，精确血缘模式仍禁止非null目录参数混入；原省略请求与默认值、小响应兼容、显式分页及65,536 UTF-8字节预算不变。task_ref/task_token仍非null必填且不自动注入，非法非null值、未知/跨任务引用、角色/PIT/资源/precomputed漂移仍拒绝且无写入，不自动选计算、翻页或创建任务；其他工具及Python内部None契约不变。确定性兼容反例不冒充原Provider工具定义或真实Market消费，受改适配器须在实际产品加载后才能进入获准研究

#### Scenario: 大型报告的精确回读保持完整内容
- **WHEN** 已有MCP精确有效回执回读的完整报告因完整计算血缘超过响应预算
- **THEN** 小报告原响应保持，大型或显式offset/limit返回按Unicode字符偏移的有界canonical JSON片段及total/next_offset，完整页信封不超过65,536 UTF-8字节；每页绑定原回执/报告hash、完整payload_hash和来源三字段，明确不是完整报告。读取者以同一回执显式读完并无损拼接，未读末页不声明完整回读；每页重验原授权/资源/稿件及报告hash，非法参数、越权、漂移无写入。内部完整读取、提交/依赖/归档对象不改，不摘要、删血缘、自动翻页或新增交付服务

### Requirement: 正常业务准入不得依赖必做的连接巡检
正常研究 SHALL 以精确任务授权及逐调用服务端准入验证连接、任务、角色、请求/input/Gate/cutoff和资源完整性，必须在事实返回、计算、成功收据、稿件额度或持久化前拒绝错配。单独的四角色连接观察或模型手工传递预期hash MUST NOT 成为每次正常研究的必经步骤；仅在对应拒绝边界已实际验证后采用此简化路径。静态配置不证明活动服务，业务合法也不认证宿主模型、工具隔离或独立首轮。

#### Scenario: 未先执行纯连接观察的合法研究
- **WHEN** 当前来源、阶段与任务授权成立，实际业务调用通过全部连接/角色/请求/Gate和资源校验
- **THEN** 正常返回本任务获准内容，不因缺少额外绑定巡检或纯观察工具而拒绝；宿主执行与隔离仍按各自必要证据核对

#### Scenario: 活动服务仍绑定旧请求
- **WHEN** 新任务授权被提交到旧请求或错误角色的活动连接，或资源/PIT已不合法
- **THEN** 在事实返回和副作用前拒绝，不能因磁盘配置已更新、观察曾成功或模型自报而放行，也不改预期/凭据重试

### Requirement: 活动连接绑定观察必须最小只读且不替代任务授权
原生请求/角色连接 SHALL 保留research_connection_context用于获准主线程的显式连接诊断，不要求每个正常任务调用。输入只接受本次确定性准备的expected_connection_hash（64位小写SHA-256），不接受路径、角色、任务或凭据覆盖；预期hash不是授权凭据。服务端 MUST 复用既有连接授权重验其持有的token、私有文件权限、请求/input/Gate/cutoff及绑定，再由确定性层核对精确预期hash。成功输出只含source_id/as_of/retrieved_at、role、connection_hash、request_hash、input_hash、gate_hash、decision_cutoff及固定UNVERIFIED的caller_authentication；观察时点与资料cutoff分别记录。MUST NOT 返回凭据、私有路径、研究问题/input正文、事实/ID目录、预计算指标或报告/依赖，也不得创建任务、查询/提交产物或消耗稿件名额。普通业务调用仍须精确task_ref/task_token；旧单任务接口不自动获得此能力，三个专业角色不新增观察工具，Skeptic原五工具及独立首轮保持。观察只证明此次连接绑定，不认证调用方、模型、专业隔离、事实消费或内容。

#### Scenario: 尚无CIO任务时核对连接
- **WHEN** 当前CIO连接合法且传入本次准备的正确hash，但依赖报告尚未齐全、CIO任务未创建
- **THEN** 返回纯绑定白名单和当前观察三字段，caller_authentication仍UNVERIFIED，私有根及任务/查询/提交状态不变

#### Scenario: 缺授权、错预期或试图覆盖范围
- **WHEN** 连接token缺失/错误、连接或来源漂移、预期hash错误，或传入额外角色/路径/任务参数
- **THEN** 脱敏拒绝，无事实返回或副作用；有效旧连接也不能匹配新准备，不允许改hash后重试放行研究，原合法业务路径仍可按授权使用

#### Scenario: 非业务观察成功后请求业务工具
- **WHEN** 绑定观察成功，而随后业务调用缺少任务凭据、混用任务或越过Gate
- **THEN** 原业务门禁仍在返回事实或写入前拒绝，观察结果不充当研究授权、作者或首轮隔离证明

### Requirement: 业务有效性与宿主观察及内容裁定必须分离
