## Why

现有规则已要求聚焦验证和证据复用，但未明确约束开发 Agent 在同一工作切片中重复读取、审阅和检查，以及围绕发布回执无限延长收尾。用户要求将执行精简经验写入外层开发态 `AGENTS.md`，减少重复操作而不降低既定验收或安全要求。

## What Changes

- 只整合根 `AGENTS.md` 现有持续实施、证据复用及开发收尾条款：合并必要动作，按实际变化决定重检，未受影响且覆盖当前范围的有效证据复用。
- 仅摘要或回执文字变化时，聚焦其内容、引用和发布范围，不重新展开无关实现验收；开始/恢复读取当前规划及既定更广验收仍保留。
- 收尾提前识别真实阻断；成功后记录有限、真实的回执，不预填未知结果或无限追加“回执的回执”。
- 保留完整交付、失败复检、权限、共享修改保护、敏感检查、人工批准及历史不回签边界；不新增计时器、自动状态工具或流程平台。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `three-plane-governance`：在现有“开发必须在已授权范围持续实施”要求中补充执行精简、变化驱动复检和有限收尾，不另建重复治理能力。

## Impact

- 实施仅修改根 `AGENTS.md` 的少量现有条款；`CLAUDE.md` 已正式导入该文件，无须复制。开发流程已支持聚焦验证与证据复用，本次不修改它或测试源码。
- 最小验收：逐项核对新增要求及原安全/授权条款保留，运行现有 `tests.test_development_workflow`，检查受影响 Markdown 链接/格式、限定差异及本 Change strict。只证明文档/静态结构，不证明实际耗时、Agent 遵循或宿主权限强制。
- 不改产品、其他 Change、全局配置、外部 Skill 或历史证据；不运行产品/模型/Demo、网络探针、项目沙箱或专项评估，不新增辅助状态/回执文件、快照或真实研究验收。
- 无新增产品或外部运行依赖。明确冻结、共享改动不能安全分离或实际权限不足时仅暂停受影响步骤；收尾另需人工完成批准并核对当时 Git 约束，上次临时分支例外不自动沿用。
- 本轮仅规划，呈现后等待新的显式 apply；当前授权、进度及验证见 [Tasks](tasks.md#当前状态)。
