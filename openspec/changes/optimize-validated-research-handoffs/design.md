## Context

见 proposal.md。当前 `build_predecision_cio_prompt` 提供经绑定的短目录，却明确要求调用 `read_reports` 读取全部完整报告；`fixture_mcp.read_reports` 经 `read_cio_reports` 对精确 ID、路径、文件 hash 和 `research_reports.read` 授权校验后返回完整 JSON，`verify_cio_report_reads` 重建工具事件并要求 `read_ids == allowed`。因此只减小初始目录不会减少真实工具交付，直接删除全部已读检查则会把可见误作消费。`fixture_cio_model_input` 已对部分启动输入作投影。现有报告与引用闭合、来源 Gate、研究级 CIO（Risk NOT_RUN）、模型前拒绝组合动作，以及独立 Skeptic 首轮隔离均不得改变；目标规格见两个 delta 文件。

`enable-single-stock-research-synthesis` 正在共享 CIO 接缝实现 ALB 分支；其八维已达 8/8，但独立 Skeptic 第二次仍不足、未启动真实 CIO，故 ALB 不能作为完整新旧验收基线。另一个 Tiger Skill 入口完全独立。本文为后续实施设计，不表示测量或 A/B 已发生。

## Goals / Non-Goals

**Goals:** 用实际工具返回及可观察调用记录定位输入负担；仅给 CIO 已获准的冻结报告增加可版本化、可验证、可回退的索引→原文读取协议；让旧历史验证保持原状，并以研究质量先于效率的同源比较决定是否启用。

**Non-Goals:** 不改变上游研究写入及报告 Schema、Gate/PIT/权限、CIO 输出决策语义或产品入口；不让代码代替模型选论据，不构建跨 Agent 通用摘要平台，不降低旧运行的全文已读门禁，不触碰 Tiger 私人资料与凭据，不根据字节估算声称全链费用节省。

## Decisions

### 1. 先做交付链测量，再定候选预算与有界索引

对可只读核验的 MRVL 冻结运行逐层采样：报告文件字节/hash、准备包/Prompt 的实际序列化尺寸、工具日志若保留的原始返回与模型可见投影、工具事件、可观察的父与子 usage、缓存 token 及延迟。现有事件的 output_hash 可重建并核对规范化返回，但不等于保留了当时模型实际见到的序列化字节；无原始响应时仅报告“重建的候选体量”和观测缺口，不把它记作实际模型输入。区分工具原始 JSON 与短引用翻译后的模型可见返回；不把“构造过但未调用”的视图算输入。仅在现有日志具备时记录实际 usage/费用，tokenizer 参考数另列模型/版本及估算口径，缺子调用或账单时列未观测；不回显私人数据、原报告全文或令牌。测量结果锁定索引上限、待验质量点与成对运行预算，再开始实现。相比只用 full/compact 字节比，这能检验最可能昂贵的 MCP 边界，且不会伪称缓存命中等于新输入节省。

### 2. 独立交付版本，原报告作为唯一权威内容

在新 CIO invocation/准备包的冻结绑定中显式声明 report-delivery 协议版本，未声明者走原有 `read_reports` 和 `read_ids == allowed` 验证，不猜测或就地迁移。新版本的索引从已校验的获准 report catalog 和原 JSON 结构化字段确定性生成：每报告的 ID/角色/研究状态/文件 hash、claim/challenge 稳定定位、各类支持与反证、限制/缺口/冲突及单位、期间、来源等可发现指针；既有短引用映射在交付层转换，原文件和引用关系不重写。索引必须覆盖全部获准报告，不自动排名或裁剪研究争议；超过冻结尺寸或字段无法安全映射就不启用新交付。输出与事件同时绑定请求身份、目录/原报告 hash、视图版本及实际交付 hash。相比预先截短 Markdown 或改原报告 Schema，这样保留审计权威及旧消费者。

### 3. 只读导航和原文共用原授权，精确重验消费

新版本在已有 CIO 权限内增加显式索引读取与精确全文读取；可提供按报告内稳定 claim/challenge/section 标识的细节读取，但细节必须由原 JSON 的完整相关字段、附属引用/反证及观察限制组成，不能裁剪成一句结论。若细节范围无法证明闭合，选中报告一律读取全文；初版可采用“索引全量、选中报告全文”的保守切片，不为节省 token 降低验证。任何读取均沿原报告路径逃逸防护、身份、文件 hash、引用映射校验；拒绝未知片段、错版本、跨来源、事件被篡改。Prompt 明确先实际读全目录索引，对拟采用的报告/反证读必要详情或全文，再查询最终引用的 Evidence；禁止只凭索引宣称查过正文。原 `read_reports` 可继续在新版本做全文回退。相比只改 Prompt，这实际改变可观察 MCP 返回；相比一次打包全部摘要，这保留研究者追溯权。

新验证器根据冻结协议分派：旧版继续重建旧事件且要求全部全文已读；新版重建索引交付及细节/全文事件，要求全部获准索引确实交付、正式 `report_selections` 的报告都有闭合的详情/全文读取。若 CIO 正文没有机器可绑定的细粒度选择，就以选中报告全文为最低证据；不能从自然语言推断某段已读。实际已读取范围、目录授权和模型选择分别落审计证明；即便工具返回正文，也不宣称可测得模型的内在理解。Evidence 实际查询和原引用闭合要求保持；未选报告不能从仅索引自动晋升为已消费。与无版本地放松 `read_ids == allowed` 相比，这避免历史证明倒退。

### 4. 质量对照、版本启用与并行隔离

先在 MRVL 可核验冻包上构造零模型旧/新读取事件正反例：完整性漂移、报告缺失、无索引、索引超限、只交付索引就选报告、反证丢失、伪造事件、原旧包继续全读、Skeptic 隔离、拒绝 `PORTFOLIO_ADVICE`。与进行中的单股 Change 不并行编辑 CIO 共享源码或重签 ALB 包；待其真实终态稳定，重验其当前 spec/实现和单股版请求、目录、短引用消费路径再合并实现及补 ALB 兼容测试。此阶段的纯规划不启动任何模型。

在用户后续单独批准真实模型预算后，以同一冻结源、相同问题/模型、独立新运行和预登记的评估表比较原/新：关键事实与反证、重大缺口/冲突、引用可核验性、CIO 取舍、研究级输出，优先由人工或独立内容复核，不让关键词检查替代内容评价；再比实际输入、缓存、延迟和有观测范围的费用。差异无法归因、关键质量退化或信息/费用观测不足则不晋升；不假定模型输出逐字相同。Tiger 插件、私人账本及 ALB 失败包均不得复制到评测材料。

## Risks / Trade-offs

- [索引太短隐藏不利事实、索引太长不省输入] → 事先以冻结报告类型覆盖表与上限校验，结构不能安全表达则全文回退/停止；先以选中报告全文的低风险切片比较，不以固定收益目标冒险裁剪。
- [只记录报告选择而漏检正文引用] → 无可验证细粒度绑定时整份选中报告必读；独立校验实际 Evidence 查询与引用闭合，人工复核语义取舍，不把目录事件作阅读证明。
- [历史协议与活跃 ALB 接缝相互覆盖] → 新 invocation 显式版本、旧路径独立回归，待并行 Change 稳定后逐文件核对其最新代码与规格；冻结产物只读，不混写来源运行。
- [token 账单与准备字节口径混淆] → 分列准确可观测指标和参考估算，标示缓存与子调用缺口；缺证据不宣称总费用下降。

## Migration Plan

当前只交规划产物。后续如获实施授权，先在只读样本完成测量与验收阈值锁定，再等单股共享接缝稳定后实施显式新版本及确定性回归；默认保留旧交接。经另外明确的有界模型试运行授权与内容验收后才能决定是否启用新版本。启用后遇索引无法完整映射/校验时在新运行启动前选择原全文协议并记录原因；运行中出现身份、hash、权限或读取事件错误则失败停止，不在同一运行中静默换协议或重签产物。回退为对后续新运行选旧版本，已冻结新旧包各用自己的版本读取器，不改历史文件。
