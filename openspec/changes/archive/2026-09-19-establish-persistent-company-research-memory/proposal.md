## Why

当前普通股研究虽然能够冻结 SEC、Yahoo、Moomoo/公开补充资料并生成 Company Agent 报告，但资料、增量水位和报告分散在单次运行目录与请求级缓存中；数日后再次研究同一持仓时，系统仍可能按移动窗口重复获取和处理大量旧数据，也无法可靠复用已验证的历史研究。现在需要把个股公开研究资料升级为跨运行、可增量、可审计的 Research Memory，同时保持现有 Company Agent 调度、PIT Gate 和逐证券故障隔离不变。

## What Changes

- 新增仓库外的本地持久化 Research Memory，长期保存证券身份版本、标准化事实、公开文档引用、逐数据集 checkpoint、采集尝试、冻结研究视图和通过校验的 Company Agent 报告；原始大对象继续复用现有内容寻址缓存。
- 在现有 `collect-common-stock-data` 数据准备阶段按证券、来源和数据集生成确定性 `IncrementalPlan`：首次出现的股票执行有界初始化，已有股票仅补缺失、过期、新增或修订资料。
- Yahoo 日线按已完成交易日水位和有限重叠窗口增量获取；SEC 按新 accession、文档 hash 和事实版本追加处理。对于仍需重新读取汇总端点的数据源，明确区分网络检查、缓存命中、新增事实和历史文档获取，不宣称字节级增量。
- 只有经过身份、Schema、来源和 PIT 校验的数据才能在短事务中追加；checkpoint 仅在对应数据提交成功后推进。失败、并发和重复执行不得覆盖旧版本或产生重复事实。
- 从 Research Memory 为每次运行物化新的冻结 Gate/Data Preparation，继续使用现有 `prepare-common-stock-research`、Company Agent 有界派发、报告验证和覆盖归集，不新增第二套编排器或“持久化 Agent”。
- Company Agent 报告通过现有结构、Evidence Closure 和输入绑定校验后才进入报告历史。数据采集成功但 Agent 失败时保留已提交数据；报告写入失败时保留运行目录原件并显式记录持久化失败。
- 区分事实身份、内容版本和采集观察，避免获取时间、响应排序或整份响应 hash 变化造成伪新增；区分运行完整性 hash 与完整研究输入指纹，复用身份覆盖资料、附件、用户上下文、时效判断和模型/Agent/Skill/Schema/工具策略版本。
- 只有完整研究输入等价、当前时效检查通过且用户未明确要求重跑时才复用报告，并保留原报告截止时间；新研究使用当前完整冻结资料，首版不自动注入前序报告或增量摘要作为推理上下文。
- 将采集计划参考时间与采集完成后的共同研究 cutoff 分开；补齐日线缺口、复权修订的有界修复以及可选来源失败后的明确降级政策。
- 打通全复用零任务、复用与新研究混合、复用与失败混合的 launcher、父线程 Stop Hook、finalizer 和覆盖归集，保持实际新调用的终态证明。
- 长期保存可独立读取及验证的最小完整报告包；原运行目录不可用后仍可访问，保存失败后可只重试确定性补存，不重跑模型。
- Research Memory 不可用时在数据准备或指定证券边界内 fail closed，不静默退回全量抓取；单证券或单数据集失败不阻断其他独立持仓。
- 本 Change 不实现历史 Agent 重跑、传统策略回测、组合快照、Benchmark/绩效归因、Skeptic、CIO、向量数据库、远端数据库或新的 Replay 平台；仅保留未来所需的 `as_of`、`published_at`、`retrieved_at` 和不可变版本血缘。

## Capabilities

### New Capabilities

- `persistent-company-research-memory`: 定义个股公开研究资料、增量采集状态、冻结研究视图与 Company Agent 报告的跨运行持久化、查询、幂等和故障语义。

### Modified Capabilities

- `live-us-equity-data`: 将普通股真实资料准备从请求级缓存复用扩展为按证券/数据集规划的跨运行增量采集，并从持久化事实生成本次冻结数据包。
- `common-stock-holding-analysis`: 让现有 Company Agent 调度消费持久化层物化的冻结资料，按严格输入身份复用历史报告，并在有效新资料或显式重新研究时保存新报告版本。

## Impact

### 收口范围与当前证据边界（2026-09-17）

本次在原 Change 内补齐实际采集与持久化接缝，不新增基础设施或反证 Agent。现有 MRVL v3/v7 证明报告保存与同截止点冻结复用；对应验收库 `reports=1`，但 `fact_versions=0`、`dataset_state=0`，不能作为基本面资料入库或隔日增量的完成证明。已完成勾选和旧独立复核结论应按新增发现重新评估。

- 修复真实快照字符串缺口与内部结构化缺口的转换，以及修订后重新冻结的 Schema 兼容；保留待补区间直到有实际覆盖证明。
- 分离 SEC 汇总端点刷新与不可变 filing 文档复用，按实际数据集结果推进 checkpoint，记录真实网络请求、缓存命中和来源失败。
- 补齐 SQLite 写入异常在数据集、证券与共享库三个层级的处理，不让局部故障破坏其他已取得成果。
- 用真实生产数据契约的零模型双时点链路证明资料入库、重启、增量、Gate/附件/任务消费；补充有授权的 MRVL 数据侧真实验收，既有一次模型授权不得重复使用。
- 交付可复现的稳定外置目录配置及证据矩阵。报告持久化、资料持久化、增量获取和宿主运行分别判定，任何关键项未通过都不得宣布整体完成。

- 主要影响现有普通股宿主链路中的数据准备、live 采集/缓存接缝、PIT Gate 物化、Company Agent 报告终态保存和对应 CLI 参数；现有 Company Agent 拓扑、并发调度和投资职责边界保持不变。
- 新增仓库外 SQLite 与最小 Repository，按必要记录和查询组织存储，不预设十二张表；首版使用进程文件锁、短事务和 checkpoint revision，不建设租约续期服务。日常启动轻量检查，完整 integrity 检查用于迁移、恢复或明确诊断。数据库和私人报告包不得进入 Git。
- 需要为首次有界初始化、数日后增量刷新、无变化报告复用、新增持仓、部分来源失败、写入失败、并发重复、进程重启和旧运行兼容补充确定性测试及限定真实验收。
- 后续回测可以复用不可变事实与时间字段，但本 Change 不提供任何回测执行、绩效计算或历史投资结论。
