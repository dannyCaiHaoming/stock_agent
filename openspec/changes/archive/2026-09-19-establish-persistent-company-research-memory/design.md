## Context

动机见 proposal.md。现有入口为 collect-common-stock-data → Gate/Data Preparation → prepare-common-stock-research → Company Agent → finalizer。持久化接入这些接缝，Python 负责资料、计算、验证与保存，研究判断仍由 Agent 承担。

现有 SEC/Yahoo Evidence ID 包含获取时间和响应 hash，不能直接当跨运行去重键；当前请求还包含持有期限、用户 Thesis/问题及冻结附件。当前 finalizer 要求子 Agent 事件日志，零调用复用必须贯通 launcher、父线程 Stop Hook 和收尾。当前 live 采集完成后确定最终 cutoff，继续遵循这一时间顺序。

## Goals / Non-Goals

**Goals:** 完成新增股票获取并保存、重启后增量、当前完整资料研究、报告长期保存/严格复用及正常收尾的单机闭环。

**Non-Goals:** 不实现回测、历史 Agent 重放、远端存储、多主机协调、第二套调度或模糊复用；不自动将旧报告作为新研究输入。不新增实时轮询、后台刷新或来源；现有多维入口只做受影响兼容检查。

## Decisions

### 1. 最小 SQLite 与稳定外置目录

使用标准库 sqlite3、foreign keys、WAL、busy timeout 和事务迁移。配置优先级为 --memory-root 高于 RESEARCH_MEMORY_ROOT；缺少稳定目录时在网络前停止并给出配置指引。raw-cache 默认位于 Memory 内，兼容显式外置缓存位置，不回落到单次运行目录。

必要记录包括身份版本、事实/文档版本、采集观察、checkpoint/attempt、View、报告包索引及复用记录。使用 canonical JSON 加必要索引，可合并兼容记录，不预设十二张表，不建设通用存储框架或租约表。原始对象和报告包保存在外置内容寻址目录，数据库保存引用。

启动检查路径、权限、版本及必要表；完整 integrity_check 用于迁移、恢复或显式诊断，不每次扫描全部历史。共同库损坏/迁移失败停止自动链路，不覆盖重建。备份使用 SQLite 一致性备份并包含被引用对象，不能只复制活跃 WAL 库的主文件。

### 2. 事实身份、内容版本与获取观察分离

逻辑事实键包含 provider、dataset、稳定证券身份、指标、期间/交易日、单位、币种、口径和必要维度。内容版本包含数值、有效/公开时间、适配语义与来源披露身份；SEC accession 作为披露版本依据保留，不合并不同申报的来源。

retrieved_at、响应整体 hash、行位置与检查时间属于获取观察，不单独制造新事实版本。保留首次合格获取时间及后续观察到原始响应的映射。仅响应排列、获取时间或无关字段变化时复用已有 canonical live-fact/Evidence ID；真实修订追加版本，不重写历史 Evidence ID。不能确定语义等价时显式冲突，不能抹去血缘。

唯一约束保护同一版本 ID 内容不可冲突；同一逻辑事实的新合法内容允许作为修订。当前 live-fact 是生产权威，旧 JSONL FactEnvelope 保留兼容用途，不双写。派生计算绑定选中事实版本和计算器版本。

### 3. 两个时间边界与具体增量政策

网络前用 planning_as_of、交易日历和已提交 checkpoint 规划范围；响应按真实完成时间记录 retrieved_at。采集结束后沿用现有共同 decision_cutoff 机制，再物化 View/Gate。采集前参考时间不能作为最终 cutoff，不能为通过 Gate 伪造获取时间。后续附件补料继续走既有重新冻结契约；显式历史 cutoff 不自动推进，本 Change 不新增历史研究能力。

下表为首版默认政策，来源准入中更严格的预算/时效优先；最终参数写入 plan。所有分页、子请求和重试计入实际预算，Agent 不能放宽。

| 数据集 | 首次范围 | 刷新触发/范围 | 上限及失败边界 |
| --- | --- | --- | --- |
| Yahoo 日线及公司行动 | 最近 365 个自然日，截止计划时已完成交易日 | 新完成交易日、已知缺口或成功检查超过 24 小时；重叠 5 个交易日 | 每证券一次正常区间请求；有修订证据时可增加一次不超过已存 365 日窗口的修复请求，仍受来源总预算约束 |
| SEC 身份映射 | 现有映射及持仓身份 | 24 小时或身份变化线索 | 沿用 SEC 总预算；身份未确认则停止该证券 |
| SEC submissions/companyfacts | 现有筛选：财务历史最多 7 年度/24 季度，主研究选择沿用更窄窗口 | 成功检查超过 24 小时或已知新 accession 提示 | 汇总端点各一次逻辑刷新，历史分页最多 1 页；全响应检查只追加变化，失败不更新成功时间 |
| SEC 文档 | 现有 selector 的年报、季报、事件及附件 | 新文档身份或明确修订线索 | 数量遵循既有 selector 和 SEC budget；旧文档不因 TTL 重下，超预算记录待补 |
| 当前估值快照及现有公开补充 | 各 dataset 现有有界快照 | 每 dataset 默认 24 小时，低频公司简介默认 7 天；上游变化使派生结果失效 | 每 dataset 一次逻辑采集，内部请求受现有限制；缺失明确记录，不无限重试 |

检查频率与旧资料可用性分开：历史已公开财报不因一次查询失败失效；当前价格/快照仍须满足既有 Gate 时效上限。可选来源过期/失败时，排除不合格旧资料并记录缺口，基础身份和必要 Evidence 合格则继续。必要条件失败阻断该证券，不放宽 Gate。

checkpoint 保存覆盖及待补区间，不能以最大日期冒充连续覆盖。缺口按有限请求补齐，超预算保持未完成。发现拆股、分红复权或重叠区价格口径变化时，允许带原因的有界历史修复；不能确定一致性则禁用受影响序列的相关派生计算。不承诺发现来源未提供线索的任意古老修订，不自动全历史回填。

### 4. 单机文件锁与短事务

对 security_id/provider/dataset/scope 使用 OS 进程文件锁，默认最多等待 30 秒，进程退出后由 OS 释放，不以文件存在判断锁，不增加续租服务。取得锁后重新读取 checkpoint/更新计划。网络请求保持数据集锁但不持有 SQLite 写事务，其他数据集可继续。

验证后短事务原子提交资料、成功 attempt 和 checkpoint revision，以 compare-and-swap 和唯一约束防止陈旧提交。锁竞争超时明确可恢复状态，不退回全量抓取。所有入口遵循同一锁顺序，避免嵌套数据集锁。

失败事务回滚后单独尽力保存失败 attempt；数据库无法写入时保留运行包诊断，不声称已落库。原始对象先原子发布，再提交数据库引用；未提交事务遗留的无引用对象可保留，首版不建设垃圾回收系统。

### 5. 运行完整性 hash 与研究输入指纹分离

view_manifest_hash 覆盖运行、最终 cutoff、checkpoint revision、所选版本、覆盖/缺口和策略，服务审计绑定。research_input_fingerprint 覆盖实际研究输入：

- 证券身份、所选事实/文档内容版本、冲突、缺口、时效状态；
- 估值及其他交付附件、计算结果和工具语义版本；
- 问题、持有期限、用户 Thesis/问题等实际交付上下文；
- 模型及调用配置、Agent、全部 Skill、输出 Schema、提示/数据/适用风险策略、Adapter 版本。

仅明确列出的运行包装字段（run/invocation ID、检查时间、checkpoint revision）可排除；不能直接忽略整个附件 hash 或任意时间字段。实际传给 Agent 的时间派生量，如事件剩余时间、滚动窗口和资料年龄，必须参与比较。新增输入字段没有纳入/排除规则时拒绝复用。

cutoff 不同仅在当前来源检查满足 freshness、资料/时效状态/时间派生上下文等价、无未满足刷新或等价性疑问时允许返回旧报告。引用同时显示 checked_at 和 original_report_cutoff，原报告不改写，也不宣称模型已重新研究到今天。无法证明等价或用户 force_rerun 时创建新调用。

新调用读取完整当前 View 和附件。前序报告只供用户查看，不自动注入 Agent；确定性变化摘要仅用于采集审计。这样避免首版持久化同时改变研究方法。

### 6. 最小完整报告包与确定性补存

finalizer 完成既有报告对、绑定、Evidence Closure、计算和禁止动作验证后，保存报告 JSON/Markdown、原请求/绑定、选中 Evidence、引用计算、附件/图形、校验记录和闭合 manifest。对象可共享，但所有必需引用必须可在长期存储解析，原运行路径只作追踪。

先发布内容对象，再短事务提交有效报告索引，重复 finalization 幂等。原运行目录不可用后仍能按原绑定验证报告包，再判断当前复用兼容性；必需对象损坏或缺失则拒绝复用。必要私有上下文仅保存在外置受保护报告包内，与公开事实查询隔离，不保存不必要的组合信息。

报告保存失败保留原运行产物和独立状态。指定报告可走确定性补存，重新验证后幂等写入，不发 Provider 请求、不调用模型；原件缺失明确失败。模型失败不回滚数据。

### 7. 零任务与混合任务贯通宿主收尾

prepare 生成 RUN/REUSED 决策；dispatch-index 仅列真实 RUN，复用引用另存。全复用时 launcher 直接进入确定性 finalizer，不启动研究父模型。混合运行父线程 Stop Hook 只等待 RUN，但最终覆盖必须验证所有复用引用，不能把空任务集合自动判成功。

finalizer 仅在 RUN 为空且全部目标有有效复用证明时允许没有子 Agent 日志；有 RUN 时仍要求原 dispatch/start/stop 证明。沿用既有执行/覆盖/充分性字段，增加必要持久化状态，不复制第二套生命周期。

全部有效复用可完成阶段；复用＋新研究成功可完成；复用＋失败为部分覆盖；全失败仍失败；零目标不得伪装为全复用成功。资料不足报告保留原充分性。下游消费者解析不可变引用或明确不兼容，不改写原报告绑定。

现有 parent-stop 相关变更共享此接缝，实施时兼容最新规则，不将另一 Change 收尾作为额外前置阻塞。

### 8. 全流程验收

确定性测试使用临时外置 Memory、受控两时点数据和现有入口/收尾，断言实际请求范围、版本数量、checkpoint、Agent 输入和派发计数。覆盖首次闭环、进程重启全复用、数日后 delta、新增持仓、复用＋失败、响应排序/获取时间变化、缺口/复权修复、附件/用户上下文变化、Agent 失败、仅补存报告、原运行目录不可用和锁持有进程退出。

真实 Smoke 使用用户已确认输入，不得更换股票；当前有效授权决定模型及资料范围，旧一次性验收不自动授权本次调用。初次实施的一次 Company Agent 调用已完成；本轮按第 9 节复用其报告侧证据，新增数据侧验收默认零模型。再次运行仅当真实输入等价才预期报告复用，如附件变化则如实拒绝复用，不能伪装等价或擅自增加调用。受控数日后变化由确定性测试证明，不等待真实披露，也不将模拟数据称为 live。

覆盖 launcher → prepare → dispatch/零任务 → Stop Hook（适用时）→ finalizer → 覆盖与报告读取。Repository 单测不替代整条链路。Runtime Eval、Execution Replay、Regression、Calibration、Ablation、Promotion 仍由对应显式任务触发。

### 9. 本轮收口：生产接缝与完成门槛

#### 9.1 缺口、修订与重新冻结

在数据准备边界统一解析当前 live snapshot 的 JSON 字符串缺口；内部使用带证券、dataset、区间、原因的结构化记录，输出快照仍遵守现有 Schema，不能将字典直接混入只接受字符串的 gaps。兼容已有普通文本原因；无法解析或无法归属的缺口必须保留诊断，不默认视为无缺口。按锁定交易日历识别预期已完成交易日，休市日和未完成 session 不生成虚假待补。

旧 pending 只能按本次已验证覆盖消除；最大日期、请求成功或进入修复分支都不能自动清空。修订触发的有界修复若预算已耗尽则保留 pending 至下次计划；修复覆盖及价格口径一致性验证通过后才恢复依赖序列的计算。重新冻结必须通过真实 snapshot Schema、身份、PIT 和来源绑定检查。

#### 9.2 数据集执行与 SEC 文档复用

SEC submissions/companyfacts 的时效检查继续使用有界汇总请求；已验证的 filing 文档按 provider、CIK、accession、document URL、适配版本和对象 hash 复用，不因 24 小时到期重新下载原文。新 accession、显式修订线索或缺失/损坏对象触发带原因的有界获取；缓存命中保留最初 retrieved_at，不伪造当前获取。无需额外文档服务或新数据库。

既有采集器返回的成功、缓存、失败、截断和未尝试结果须映射到对应 dataset。不能仅按新增事实数推导所有数据集成功，不能给未采集的身份/简介或失败的可选来源写成功 checkpoint。SKIP_FRESH 应实际跳过该数据集采集；如因现有来源接口必须联合检查，计划和实际差异须明确记录，不声称跳过。逻辑采集次数与实际 HTTP/子请求/重试次数分开，实际计数来自现有 transport/cache 事件，不固定写 1。保留原 provider 身份，包括现有备用行情来源。

#### 9.3 故障隔离与完整资料物化

对局部 SQLite OperationalError/IntegrityError 等写入异常回滚当前事务，保留既有 checkpoint，阻止该失败证券派发，并继续可安全处理的其他证券；不把所有异常都标成 SOURCE_LIMITED。共同库损坏、迁移失败或持续不可写导致无法安全处理其他证券时终止批次，保留已提交成果及可恢复诊断，不承诺整库故障下继续。失败 attempt 无法写库时，运行目录仍保存明确失败阶段和代码。

T1 View 必须从已提交版本读取并保留 T0 所需历史。历史事实关联的原始对象与引用须仍可由稳定存储解析，新运行包满足既有来源闭包，不只携带本次增量响应而遗失旧版本血缘。最终 View 与共同 cutoff、Gate、当前附件和 dispatch packet 一致；明确区分基础事实与另行冻结的 sidecar，不扩展新存储平台。

#### 9.4 先零模型证明，再限定宿主验收

下列矩阵为完成门槛。测试可替换外部 transport 响应、时钟及模型进程，必须继续执行生产 normalize、freeze、Schema、身份/PIT、持久化、Gate、prepare 和运行包 validator。不能 mock 掉这些接缝后声称端到端通过；合成 Hook/报告只证明调度装配，不标作真实模型行为。

| 场景 | 必须观察到的结果 |
| --- | --- |
| T0 MRVL 首次获取 | 从空外置库经现有采集入口，事实版本及实际成功数据集 checkpoint 非零；选中文档对象可读取；View/Gate 事实可追溯到库中版本；生成合法 Company task |
| T0 重启无变化 | 新进程、新 run_dir、同一 memory_root；旧事实无重复版本；旧对象及首次获取时间不变；按 freshness 跳过或检查；严格等价报告零模型复用正常收尾 |
| T1 数日后增量 | 固定时钟跨过刷新期，响应含新增日线、新 accession 及重叠旧资料；实际 Yahoo 请求为有界 tail，旧 filing 原文请求数为零，新文档有界获取；新增版本数量与预期集合相等，旧版本保留，新 Evidence 可经实际工具查询交付 Company task，RUN 包可启动验证 |
| 缺口与修订 | 真实字符串 gaps 进入 pending；未补齐时 pending 保留、相关计算受限；完成有界修复后才恢复，真实 Schema/Gate 均通过 |
| 混合与故障 | MRVL 已有资料加一只明确标注的合成新股票，只新股票 BOOTSTRAP；局部写入/来源失败不推进该 checkpoint、不派发失败证券，其他成功项正常归集；共享库故障在适当边界停止 |
| 复用边界 | 同 cutoff exact replay、不同 cutoff 成功刷新后的等价复用、刷新失败转 RUN、附件变化转 RUN、全复用与混合收尾均通过运行包 validator；未触发模型时计数为零 |

真实数据侧验收使用已确认 MRVL Handoff、当前有效来源授权、现有宿主 launcher 与稳定外置 Memory，执行首次采集及另一个 run_dir 的再次读取/检查。允许为既有 launcher 补一个最小“仅准备、模型前停止”的选项，不新增 launcher/编排后端；停止结果标记 PREPARED，不能标记研究完成。当前一次模型授权已用完；优先复用 v3/v7 作为报告侧证据，只补零模型数据侧证据。如果必须再次真实调用模型，先提出具体新增授权及必要性，不能自动重试。网络受限时真实数据项标记 BLOCKED，不用合成数据替代 PASS；隔日新增由受控 T1 证明，无需等待真实新披露。

运行配置须记录实际解析的 memory_root、配置来源、Python/锁定依赖、数据库及对象可访问性，在新宿主会话仍可解析同一配置；通过既有宿主配置方式交付，不依赖当前开发进程临时变量。持久实例不放在 /private/tmp 或单次 run_dir；测试临时库允许。配置文件或外置目录超出当前权限时报告最小授权需求。

#### 9.5 验收记录与下一能力入口

交付一份有证据路径/hash 的矩阵，将资料持久化、增量获取、报告持久化/复用、宿主配置、独立复核分别标为 PASS/FAIL/BLOCKED/NOT_RUN。每条关联实际输入、命令、退出码、数据库前后统计、请求区间/计数、Gate/View 和 dispatch 结果。不能只用总测试数、报告文件或 reports 表非零证明资料已入库。

校正旧记录：147 为总运行数且含 1 skipped，应记为 146 passed、1 skipped；没有可定位成功产物的 self-check 不得记 PASS。旧全 Council trace 检查不适用于普通股专项时说明适用范围，以专项实际 validator/finalizer 证据补足，不修改旧原始产物或伪造 trace。现有 MRVL v3/v7 保留为冻结报告验收，其 fact_versions/dataset_state 均为零的限制明确列出。重开任务须有对应新证据才能勾选，并重新接受针对本轮增量的独立复核。

全部持久化门槛通过后，下一能力可读取现有冻结 Gate/View 和明确授权的报告。当前不实现 Skeptic、CIO 或历史报告广泛查询；后续 Skeptic 独立首轮仍不得读取 Analyst 结论。

## Risks / Trade-offs

- 本地锁不能支持多机 → 首版限定本地文件系统和单机。
- 复用较保守 → 记录拒绝原因，以内容/运行 hash 分离消除伪变化，不放宽真实输入约束。
- 数据库与对象跨介质不能单事务 → 先对象后索引，仅读完整对象，失败幂等补存。
- 来源不支持 delta 或无提示修订 → 如实记录完整检查与有限修复边界。
- 报告包含必要私人问题 → 外置权限保护并与公共事实分隔。
- 首次配置阻断启动 → 明确配置优先级和诊断，保留 prebuilt/fixture 路径。

## Migration Plan

1. 最小契约、Repository、稳定路径和事务迁移，不导入旧运行。
2. 稳定事实版本、具体政策、文件锁与增量提交，验证受控双时点。
3. 物化既有 Gate，接通 cutoff、附件及完整研究输入指纹。
4. 接入完整报告包、复用、补存和零任务/混合收尾，检查受影响下游。
5. 限定真实 Smoke、聚焦检查、独立复核和人工完成批准。

回滚保留数据库和对象，不破坏性降级；旧版本走明确支持的 prebuilt/fixture 入口。既有缓存仅在来源、请求身份、时间和 hash 合格时复用。
