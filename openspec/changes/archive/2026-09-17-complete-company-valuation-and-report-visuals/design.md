## Goals / Non-Goals

**Goals:** 最小可用版本在一个合格盈利样本上形成当前估值、至少 24 个有效月末 trailing PE 点及四类图表；同时交付本节第 6 项定义的基本面补充和有限同行对照。亏损与重组样本正确显示不适用/不连续，全部结果可复算和引用。24 点是核心历史交付下限，不代表五年覆盖或已满足 80% 分位展示门槛。

**Non-Goals:** 实时终端、交互式网站、自动买卖、完整 DCF、技术指标大全、全市场同行抓取、历史一致预期数据库。均线首版为 SMA20/60/200，RSI/MACD 暂不纳入；仅纳入有界同行对照，不建立全市场筛选器。不新增第四来源，不将未向 SEC 申报的 IR 网页、付费电话会库或完整供应链库纳入本次采集。

资料核对（2026-09-17）：[SEC EDGAR API](https://www.sec.gov/search-filings/edgar-application-programming-interfaces) 提供 Companyfacts 和申报历史，不承诺自定义标签/分部或预测；[yfinance history](https://ranaroussi.github.io/yfinance/reference/api/yfinance.Ticker.history.html) 与 [Ticker](https://ranaroussi.github.io/yfinance/reference/api/yfinance.Ticker.html) 提供行情、行动和当前资料访问界面，不是历史预期可用性保证。[OpenBB ratios](https://docs.openbb.co/python/reference/equity/fundamental/ratios/) 仅参考字段命名与期间表达，不引入 OpenBB 或其 FMP/Intrinio 来源。既有真实验证详见 `docs/development/sec-yahoo-moomoo-research-supplement.md`，其 AAPL 短窗口样本不作为本次五年历史证明。

### 2. 估值契约和运算

新增独立 `EquityValuationSnapshot`、`EquityValuationHistory`、`ResearchVisualBundle` 的版本化契约，作为现有研究包附件；不重写旧锁定报告。每个指标记录 security_id、valuation_at、price_at、financial_period、fiscal_basis、accounting_basis、currency/unit、source_id/as_of/retrieved_at、published_at 或 availability 状态、输入 evidence_refs、公式/版本、calculation_ref、status 和 reason。

保留 `PROVIDER_REPORTED` 与 `DERIVED` 两条记录；来源未给出统计发布时间时记录未知，retrieved_at 只证明当前首次观测，禁止伪造 published_at。当前统计首次观测之后才可用于 PIT；历史 SEC 原件可在今天检索，但需以原申报公开时间证明过去已可知。

明确两层时间：冻结研究包遵守其 run cutoff 和既有检索时间 Gate；包内历史重建点依据原始披露 public_at 不晚于 valuation_at 选择。不得要求今天检索的历史原件 retrieved_at 早于历史观察点，也不得借历史重建绕过运行包本身的 cutoff。输出标明“基于原公开版本的事后重建”，不冒充当时已保存的快照。

指标算术单独建语义输入，不放宽通用 ratio 的旧行为：PE = 同股本基准价格 / TTM diluted EPS；P/S = 市值 / TTM 收入；P/B = 市值 / 普通股权益；FCF Yield = (TTM OCF - TTM Capex) / 市值。市值用适用普通股流通在外股数乘价格，不使用 EPS 的加权平均股数。多股类、ADR 换算或币种不一致无法验证时拒绝直接计算。

EV = 市值 + 适用债务 + 优先股 + 非控股权益 - 适用现金；构成及租赁处理必须显式。缺项不能默认零；确认不适用才以零且给依据。负盈利 PE、非正账面权益 P/B、非正 EBITDA 倍数标 NOT_APPLICABLE；负 FCF Yield 可展示为负现金流，不标成便宜。输入不全、来源失败、冲突、历史不足与不适用分别记录。

TTM 从同主体、同会计基础的四个不重叠季度组装；可对可加总的收入/OCF/Capex 用 FY + 本年 YTD - 上年 YTD。累计季度差分须期间、单位及披露口径匹配。EPS 受加权股数影响，禁止直接套用累计差分；默认仅采用已披露、同拆股口径季度 diluted EPS 求和并标聚合方法，或可靠披露的 TTM EPS。TTM EPS 求和不声称等同于公司重算全年 diluted EPS；存在反稀释/重组/股类差异时保留缺口。

### 3. 历史观察点与分位

默认近五年，每月最后一个已完成交易日收盘，另含当前最后已完成交易日；按日期去重。财务 warm-up 至少覆盖首个观察点之前构造 TTM 所需期间，受有界预算限制。每点只选择公开时间不晚于该点的申报版本；同值后来重述保留版本，不用最新重述覆盖过去。只知道公开日期、不知道时刻时保守自下一交易日生效。

使用明确的价格基准：收益图可用供应商含分红调整序列；PE 必须用与 EPS 拆股基准一致、非分红复权的价格。Yahoo Close 本身也可能已拆股调整，必须实测元数据与行动核对，不把 auto_adjust=false 当作原始价保证。无法恢复一致股本基准的观察点留空。重组、新旧主体或证券身份变化形成分段，不跨段画连线或合并分位。

历史股数使用该观察点已知的最近适用披露并展示披露年龄及 ESTIMATED 标识；不得把当下股数回填历史。默认超过 180 天的股数不用于历史市值派生项，EPS/财务过期规则也需记录（默认期末距观察点大于 180 天则不视为有效当前 TTM，例外需显式政策）。

百分位使用当前有效同口径值在历史有效样本中的 mid-rank：100 × (小于当前值的数量 + 0.5 × 等于值的数量) / N；当前追加点不进入参考样本，月末去重。至少 24 个有效月末且所选窗口有效覆盖率不低于 80% 才显示分位；否则仅绘制有效点并标历史不足。显示窗口、N、排除原因、样本范围和公式；分位仅描述样本位置。历史 forward PE 不以今天预测倒算。

### 4. 图表与报告

首版四组固定可读图：① 日 K/成交量/SMA20/60/200（默认近一年，均线额外取 warm-up）；② 同起点相对基准表现与回撤；③ 同期间收入、利润率、OCF/Capex/FCF 和稀释股数趋势，分面显示不同量纲；④ trailing PE 历史及当前点/适用分位，条件支持其他倍数。200 日不足则仅隐藏该均线并解释，不能使其余价格图失败。

图表只由冻结的 chart-data JSON 确定性渲染，保留输入 Evidence/计算引用、单位、期间、价格基准、生成器版本和 hash。负值、缺失、断点和离群值保留；不能平滑或截断伪造趋势。重大事件仅标已核实的公司行动/披露，不推断涨跌原因。

输出 `report.html`、Markdown、研究 JSON、附件 manifest、chart-data 与 SVG/必要 PNG；静态 HTML 为无需服务器和外部 CDN 的默认完整视图。Markdown 中嵌图并有数据表/文字替代；对外回复在桌面使用绝对本地路径，移交目录内引用相对路径。中文字体、窄屏与打印视图需视觉验收；SVG 不执行脚本，来源文本转义，附件路径和 hash 校验后展示。

新报告展示层验证附件索引与报告/run/security/cutoff 绑定；原始报告保持内容同源，新增图表不生成新投资观点。旧报告无附件时使用原 renderer。渲染器只消费已验证报告和附件，不联网补数据。采用静态文件是为交付直接可见成果，暂不引入仪表盘服务或交互图框架。

### 6. 基本面补充与有限同行：具体范围

本次扩展是估值解释所需的研究输入，不增加投资/联网权限或单独建设财务数据库；第 8 节只收紧运行写入边界并接通已冻结只读数据。当前 `collection.py` 已列出 SBC、回购、资产负债、利息和债务期限等标签；`research_supplement.py` 已有指引候选与实际/预期比较器；`disclosure.py` 已接受代理声明等治理申报。标签/候选/比较函数存在不等于真实公司字段已可用。本次只补标准化、披露核实、缺项处理和消费链路。

| 补充项 | 来源与具体输出 | 成功与限制边界 |
|---|---|---|
| 指引与修订 | SEC 财报附件/10-Q/10-K；指标、目标财政期、上下限/点值、单位、GAAP 基础、发布时间、适用假设、前版本引用、维持/上调/下调/撤回/不可比 | 同一目标期与定义才能计算区间端点/中点变化；滚动到下一财政期不是上调；定性指引保留原文，不强造数值 |
| 盈利质量与资本分配 | SEC 财务与调节表；净利润、OCF、Capex、FCF、SBC、现金股息、回购金额、期末实际股数/加权稀释股数分列；GAAP 到公司 adjusted 指标的逐项桥接 | SBC 与回购不相减冒充“净稀释”；同比股数变化使用同类股数及拆股基准；调节项保留税前/税后、单位和符号，调节不平记录差额，不自造 adjusted EPS |
| 债务与流动性 | SEC 资产负债表/债务附注；现金及等价物、受限现金、短债/长债、到期年度/区间金额、利率/固定浮动属性、已披露授信额度及已用/未用额、重要财务约束与承诺 | 受限现金不能静默抵债；期限表记录本金/账面价值与租赁范围，无法与总债务调平时说明；未披露条款不等于不存在，不凭片段判断违约 |

| 治理与关联关系 | SEC DEF 14A/DEF 14C/10-K/8-K；控制权/投票权、董事与管理层角色、薪酬考核指标、关联交易及披露金额/期间 | 每项保留原文位置、报告期与生效日期；历史薪酬不冒充当前薪酬；不存在该申报的公司明确受限，不生成治理分数 |

合同结构：增加独立版本化 `CompanyFundamentalSupplement` 与 `PeerComparison` 附件，沿用现有 Evidence/Gate/索引，不增加通用平台层。基本面附件分为 guidance、earnings_quality、debt_liquidity、operating_kpis、governance、earnings_expectations、financial_ratios；每组有覆盖窗口、status/reason，每条有 security_id、source_id/as_of/retrieved_at、published_at/availability、报告期/目标期、原文定位（accession、section、页或文本 span）、定义/单位/会计基础、evidence_refs，数值派生再带 calculation_ref。候选摘录、核实事实、研究解释分开；LLM 按原文归一化并引用，Python 做身份/时间/算术校验，不把模型标签当自动证实。

默认覆盖近 8 季度/5 财年结构化财务；披露深化限定近 2 份年度报告、近 4 份季度报告、近 4 次已申报业绩发布、近 2 份代理声明及近 12 个月最多 8 份与上述主题相关的其他 8-K。按公开时间取最新、去重，原文附件最多 32 份/目标公司，每份附件计数；超预算记录截断与未覆盖主题，不静默宣称“未披露”。历史估值 warm-up 单列预算，不挤占本段披露数量。只有来源检索失败/权限限制/未找到/未核实/不可比分别留存原因，不能统一当零或“没有风险”。

比率定义：ROE = TTM 普通股归属净利润 / 期初期末平均普通股权益；ROA = TTM 净利润 / 平均总资产；期初期末须包围同一 TTM 窗口，缺期初不得以期末代替。流动比率 = 流动资产/流动负债；速动比率首版明确采用（现金及等价物 + 合格短期有价证券 + 应收账款净额）/流动负债；现金比率 =（现金及等价物 + 合格短期有价证券）/流动负债，均排除受限现金、禁止重叠标签累加。债务权益比 = 明确租赁口径的有息债务/普通股权益；利息覆盖 = TTM EBIT/TTM 利息费用，EBIT 定义与营业利润区别须明确；OCF/净利润仅在净利润为正时展示，非正 EBIT 的覆盖保留负值并标限制。ROIC 仅在 NOPAT、经营税率与平均投入资本能形成可核对计算桥接时提供；不默认法定税率或凭残缺字段补零。所有比率保留公式版本和输入期间；非正权益/非正应付利息等不适用分母不强算。

同行流程使用已有候选机制或用户指定清单：先限定最多 5 家候选及逐家可比性理由，再以固定清单采集/冻结，既有 industry-comparison 角色核实业务、市场、财政期与会计基础。候选不够时只在原清单内保留有效公司，不循环扩展全市场；LLM 的可比性解释不替代来源核实。默认每家仅取身份/业务依据、当前估值、构造 TTM 及平均资产权益所需财务，不递归抓其同行或完整披露包。采用复用角色与附件，是为了不新增 Agent、数据供应商或动态联网研究循环。

补充呈现：在四组核心图后增加指引修订表、GAAP 调节表、SBC/回购/股数分面图、债务到期柱图（财务趋势组内）、KPI 趋势或两期对照、治理证据卡及同行比较表。只有两个以上可比期间才画趋势；实际/预期按条件显示，缺失仍留限制卡；不同单位不叠成一条线，同行默认表格而非暗示优劣的雷达评分图。

### 7. 新增项验收与实施顺序

先完成 SEC 财务标准化/派生比率及当前估值，再做 PIT 历史；披露深化复用前两步契约，有限同行在单公司指标可用后接入，最后统一报告。无需先扩建底座或另接供应商。

新增核心验收允许由多个预先声明的真实普通股样本合计覆盖，复用有效冻结证据优先；不要求每只股票披露所有字段，也不允许所有新增分组都以 SOURCE_LIMITED 完成：

1. 指引：同一目标财政期的两次真实数值指引及可核对变化，另有跨目标期不得比较的负例。
2. 盈利质量：至少两期同口径 SBC/回购/股数事实，至少一张真实 GAAP–adjusted 调节表能复算；复算容差按原文显示精度推导并记录，不使用随意百分比容差。原文不完整或不平时保留差额，不能强行闭合。
3. 债务：至少一份真实到期表含两个未来期限桶，给出现金/受限现金处理依据和债务范围调节或明确差异；授信和契约条款属按披露条件增强，缺失不得阻塞其余有效资料。
4. 经营/治理：至少一个真实 KPI 的两个可比期间、一个有原文支持的集中度记录（允许匿名），以及至少一条真实代理声明中的薪酬/控制权/关联交易事实。
5. 比率：真实可复算 ROE、ROA、流动比率及 OCF/净利润；其余首版比率用完整输入确定性正例和缺项/非正分母负例检查。ROIC 真值不可得可明确条件受限，不伪装覆盖。
6. 同行：一个目标公司与至少两家经核实同行，同 cutoff 下至少三项适用且同口径指标，其中至少一项估值、一项经营指标；解释财政期差异，不强作排名。缺少合格同行则本项未完成，不自动扩展候选。
7. 实际/预期为条件项：真实结果只能是可验证事前版本的比较，或带具体来源/时间缺口的受限记录；两种分支均有确定性测试，无 vintage 拒绝历史比较。该条件项不能反向阻塞六项核心。

上述正例不得以合成数据替代真实来源；核心证据不足保留未完成任务，不以“解析器可运行”替代交付。专项研究仍共用第 5 节的一次已授权批次预算，不为每一分组新增模型运行。已有模型消费证据不覆盖新增字段时明确缺证据，申请所需宿主运行，不在开发自检中隐式启动。

需求到任务追踪：来源/契约对应 1.1–1.2、2.1–2.5；估值/历史对应 2.2–3.4；比率对应 3.5；冻结与解释对应 4.1–4.2；指引/质量/债务对应 4.3–4.5，KPI/治理对应 4.6，预期对应 4.7，同行对应 4.8–4.9；补充呈现对应 5.6；新增真实门槛对应 6.3，联合研究消费与最终验收对应 6.4–6.7。新增内容归入现有 equity-valuation-history 的估值支持材料，图表归入 equity-research-visuals，不另起第三套重复 Capability。

#### 8.2 修复目标与边界

**Goals:** 消除已经定位的 MRVL 确定性阻断：压缩实际启动上下文、接通真实附件读取、闭合事实与计算引用、保护当前开发工作区、有界清理本地进程，并让超时/异常退出不再残留 QUEUED。通过零模型门槛后，使用新授权完成一次真实 MRVL 图文验收。

**Non-Goals:** 证明任意模型或任意公司必然成功；更换来源/模型、扩建全市场研究、迁移历史 Replay、新增投资评分；新增通用目录分页、Coverage v2、权威 lifecycle store、跨文件事务/崩溃恢复平台；证明宿主远端模型请求已经停止或停止计费。无需把所有原文逐字传给模型，亦不要求所有派生结果重复计算。

#### 8.3 实施决策

##### 1. 先把实际启动上下文压到可控范围

当前未复核的压缩候选约为 300,150 bytes、568 条索引，证明 4 MB 启动包可大幅缩减，但尚不能证明模型必然完成。实现应测量真正写入 Hook `additionalContext` 的 UTF-8 JSON，而不是中间 Python 对象；MRVL 目标上限为 256 KiB。该数值是基于现有 300 KB 投影设定的工程门槛，不冒充模型上下文极限。

启动包只保留 identity、版本、核心问题、附件 manifest、工具说明，以及含 semantic_field、期间、单位和必要语境的紧凑索引。移除完整 Evidence 白名单、重复 Schema 枚举、逐日 OHLCV/volume 和可从工具 Schema 得到的元数据。完整 Gate 与引用白名单留在验证器侧。估值依赖的价格、公司行动、全部适用财务期间与冲突双方仍须能通过现有 `fixture_runtime.query` 查到；不能用 Python 投资重要性评分挑选事实，也不能扩大到其他持仓。

本轮不先实现 `catalog.list`、稳定 cursor 或通用分页预算。若零模型 MRVL 演练在保留可发现性后仍无法低于 256 KiB，或一次真实运行证明现有查询不足，再在同一 Change 内先记录证据和最小分页设计，更新 planning 后才运行模型；不得在运行中静默截断或自动放宽门槛。

##### 2. 接通现有附件查询并闭合实际消费

将已经存在的 `equity_research_attachments.query` 注册到实际 fixture MCP 工具发现、launcher 白名单和 Agent 可见工具中，不建立旁路服务。无模型测试必须走真实协议的 `tools/list` 与 `tools/call`，证明 `valuation_snapshot`、`valuation_history`、`fundamental_supplement`、`peer_comparison` 四类附件在 run/invocation/security/cutoff/Gate 约束内可读。`visual_bundle` 继续由确定性渲染使用，不进入模型上下文。

查询事件记录实际返回的事实 ID、附件 hash、绑定身份和时间。启动索引 ID 与附件中的裸 evidence_refs 只用于导航，不能冒充已经读取。计算引用继续分为 LIVE_CALCULATION（本 invocation 成功 calculate 事件）与 FROZEN_CALCULATION（实际交付且通过公式、输入、结果和 artifact hash 验证的冻结计算）。Hook 与 finalizer 复用同一验证入口；保持旧运行版本原规则，不新增通用交付账本平台。交付闭合只证明模型看到了可引用资料，语义复核另行判断解释质量。

##### 3. 保护当前开发工作区，并对本地超时负责

不再要求当前宿主证明父模型、子 Agent、Hook、MCP 和远端服务组成的“全进程绝对只读”。模型运行改用隔离、可丢弃的源码副本，或宿主已经支持的只读源码来源；只有指定 outputs/state 目录可写，冻结输入不与产物目录混放。当前开发工作区在运行前后计算受保护文件 hash，任何变化都使本次运行失败。隔离副本若被改动，保留诊断后丢弃，不把修改回写，也不靠恢复当前工作区来通过检查。

launcher 使用可监督的本地进程组；超时先 TERM，在有界宽限后 KILL 仍存活的本地进程树，并拒绝超时后的迟到报告进入正式产物。记录本地 PID/进程组、终止时刻和结果。杀死本地 CLI 不等于证明远端模型请求停止；当前宿主无法提供远端取消证明时记录 `remote_status=UNKNOWN`，不伪造 SubagentStop、不声称服务端停止计费，也不自动重试，但这项未知本身不永久阻断下一次获得明确授权的运行。

##### 4. 复用 Coverage v1 做确定性失败归集

不建立新的 lifecycle store、Coverage v2、revision 投影、崩溃恢复或迟到事件平台。为 common-stock stage 的所有退出路径建立共用确定性归集函数：成功、超时、非零退出、无 Stop、无报告、非法报告与引用失败都同步写入现有 Coverage v1、stage 和 process 文件。单个文件使用临时文件加原子替换；某文件写入失败即整体报告状态不一致，不伪装跨文件事务。

超时项的 Coverage v1 item 显式写为 `execution_status=TIMEOUT`、`research_status=FAILED`、`coverage_status=FAILED`，并保留 invocation、开始/结束时间、超时和清理原因；stage 按现有聚合语义在无成功项时为 FAILED、有成功兄弟时为 PARTIAL_RESEARCH，process 为 FAILED。用户取消使用既有独立状态。已完成的兄弟报告保留，未派发项维持既有未研究语义。已结束运行不得遗留 QUEUED。该修复直接解决本次 `process=FAILED` 而 `coverage=QUEUED` 的已知缺陷，不借机重做全运行时状态模型。

##### 5. 零模型门槛与一次真实验收

零模型准备沿用用户确认的 MRVL 身份、持仓和原冻结 cutoff；不得混入之后获取的新事实或用其他股票替代。运行包必须包含四类附件；MRVL 历史估值无法形成有效 PE 时允许 `LIMITED`/`NOT_APPLICABLE`，但附件文件、状态、原因和来源绑定不能缺失。同行仍只是参照，不加入持仓。

一次性门槛包括：实际 Hook 上下文不超过 256 KiB；真实 MCP `tools/list`/`tools/call` 能读取四类附件和关键事实；实际查询事件与事实/冻结计算/本次计算引用闭合；挂起本地子进程在时限内被清理且迟到输出被拒绝；timeout/nonzero/no-report 路径不残留 QUEUED；当前开发工作区 hash 不变。生成可审阅的运行清单，记录输入、版本、policy、四类附件和旧失败关系。本阶段不启动模型。

零模型门槛与 4.1/6.5 完成后，必须取得新的明确授权，才使用用户确认的 MRVL 冻结输入运行至多一次 gpt-5.6-terra 专项验收。实际输出需有研究 JSON/Markdown，并与冻结图表生成同源 HTML；保存 Start/Stop 或确定性失败终态、引用、限制、禁止动作检查和视觉复核。失败不自动重试，未运行 Runtime Eval 不标 PASS。该设计消除已知确定性阻断，但不承诺模型内容在运行前必然合格。

| 能力 | Input | Tool/Data | Skill/Reasoning | Structured Output | Eval |
|---|---|---|---|---|---|
| 有界公司研究交付 | 确认 MRVL、Gate、四类附件、256 KiB 启动门槛 | 现有事实查询/计算与已接通的附件查询 | 既有 company-research/valuation 等四项 Skill | 实际报告、查询/引用记录、图文目录 | 零模型门槛、一次授权真实消费、只读语义复核 |
| 运行监督 | 冻结运行、隔离源码副本及本地进程身份 | 现有 launcher、进程组、Coverage v1 | 不增加投资判断 | 三个一致状态视图、本地清理与远端未知记录 | 无模型故障注入及同次真实运行证据 |

Runtime Eval/Replay/Regression/Promotion 不在本次自动执行范围；语义复核不命名为 Runtime Eval PASS。

#### 8.4 风险与取舍

- [256 KiB 仍是工程目标而非已验证最优值] → 先用实际 Hook JSON 测量；若保留完整期间可发现性后仍无法满足，模型运行继续前置阻断，并基于证据更新本规划或补最小分页方案，不在运行中扩容。
- [压缩丢失关键旧期间或冲突] → 不做重要性排名，紧凑索引携带期间/单位/语境，现有冻结查询保留完整期间、修订、冲突及附件依赖负例。
- [隔离副本仍可能被运行修改] → 当前开发工作区不作为运行时可写来源；副本漂移使运行失败并被丢弃，前后 hash 证明用户源码未变。
- [远端取消状态无法证明] → 对本地进程树负责，远端未知如实记录、拒绝迟到输出与自动重试；不设无法实现的永久阻断。
- [模型仍可能超时或解释不足] → 新方案消除已定位接缝缺陷，但性能和内容必须由实际验收判定。

#### 8.5 同一需求内的实施衔接

先复核现有压缩 hunk，再完成小型启动包、附件工具接缝、实际引用闭合、隔离运行/本地清理与 Coverage v1 失败归集；随后用冻结 MRVL 完成一次零模型联合门槛，不先花模型预算。旧锁定运行保留读取与校验。共享 launcher 只对新估值普通股模式应用新策略。回滚可停止启用新执行模式，不能恢复直接暴露当前开发工作区为可写来源的方式继续验收。

本 Change 保留 6.4/6.7 和历史证据；实施阶段按新增运行修复更新其运行说明和验收矩阵，不改写旧失败事实。最终独立复核与人工批准后按开发流程归档；本次仅修订本 Change 既有文档。


## Risks / Trade-offs

- [五年免费字段不完整] → 请求五年但按实际覆盖交付；最小真实 trailing 样本仍须满足 24 点。
