## Context

见 proposal.md。现有 `research_input_topology.build_research_provider_coverage` 已把 provider 声明、采集观察和 Gate Evidence 计数分开，但准备期的 `actual_research_use_status` 固定为 `NOT_EVALUATED_AT_PREPARATION`。Company 的目录与字段查询、MCP 成功事件、正式报告引用和 CIO 消费证明分处既有运行产物；第五次 MRVL 实验表明“目录有事实”不等于“模型查询或引用”。普通股默认配置已回退为完整 Agent。`RESEARCH_REPORT` 的悬空观察条件引用仍在独立反证的源链路上。

## Goals / Non-Goals

**Goals:**
- 对一份真实冻结运行在同一证券与截止点上重建资料从来源到 CIO 的消费路径，找到第一个可证实的断点。
- 保持研究质量判断在 Agent/人工内容复核，确定性层只计算集合、校验引用和展示已存在的证据。
- 对 Company 与研报引用的真实故障做最小修正并验证现有失败/纠正机制。

**Non-Goals:**
- 不新增通用观测平台、模型评分规则、额外研究 Agent 或未授权的模型重试。
- 不以所有 provider 的所有字段齐全作为研究就绪条件，也不把当前研究级 CIO 改成投资建议。

## Decisions

1. **仅构建运行级消费核对。** 以既有 capture batch、provider coverage、Gate、dispatch packet、MCP 事件、正式报告及 CIO `consumed_reports` 为只读输入，在运行目录生成一份小型核对 JSON 与中文摘要。字段按 domain/dataset/semantic_field 聚合并保留可追溯 ID；避免为每个来源建立新 Agent、数据库或流水线。若原始事件缺失，报告未验证，不推断模型心理状态。替代方案“在准备期把交付数当实际使用”会误判，故不采用。
2. **用现有校验器挡住错误，围绕失败点修正研究输入或引用。** Company 优先核对完整财年等重要资料在 Gate、目录、查询、引用各层的位置；修正研究提示或信息呈现时不硬编码 MRVL/EPS 必查规则。无支撑 Claim 维持拒收，反馈记录具体路径；本次不新增 Company 同会话自动修复机制，需要再次研究时走明确授权的新调用与预算。当前多维纠正入口只接收 draft keys/schema 错误，本次将 `RESEARCH_REPORT` 的报告内 Claim 条件引用悬空窄化纳入现有一次原 Agent 纠正机会，返回错误路径及该报告合法 Claim IDs，随后完整重验；不扩大到 Evidence/PIT/权限错误，不删除条件或由 Python 生成 Claim。
3. **联调以同源内容为终点。** 先做零模型核对和定点确定性测试，再经宿主入口对受影响的真实节点运行一次明确预算的样本；只在版本、输入和截止点仍等价时复用旧的有效报告。最终检查 Company 事实适用性、Macro/Market 对该证券的传导、Skeptic 独立首轮及 CIO 对关键挑战的处置。不能把第五次失败报告与其他旧 PASS 拼成新链路 PASS。替代方案“每次全量重跑所有节点”增加成本且无法隔离故障。
4. **覆盖与正确性先于使用率。** 旧冻结样本只负责复现与回归，另通过现有采集入口检查当前来源，不自动触发模型。运行计划从已有数据拓扑和研究需求列出三域应有数据项、窗口及核心/辅助分类：Company 财务与披露、估值背景；Macro 利率、通胀、就业/经济活动；Market 标的和基准行情、相对表现及相关行业背景。缺失数据项也保留行，不要求所有 provider 全字段齐全。记录实际尝试时间、缓存命中、数据截至时间和失败/未尝试原因；缓存成功不证明远端当前可用。按关键事实抽查原始来源至规范化的值、单位/币种、主体、财务期间和发布时间，行情另查交易时段、复权及基准对齐。无原始依据标未验证；不新建统一数据质量平台。当前采集检查与旧回归分开报告，真实模型链路在执行前冻结选定资料和截止点，不把不等价旧报告混入新样本。
5. **消费按现有引用关系闭合。** 在 invocation 范围内区分取得、交付、直接引用、经 calculation/附件间接引用，再追踪正式报告至 CIO 的消费；复用现有父 Evidence 与报告引用关系，不构建通用图服务。计算输入或附件被合法引用时不能误报为未使用；Company 的查询不等于 Skeptic 的查询。没有可证明引用路径则保留未验证。交付但未引用本身不是失败，不要求所有事实被引用。核对在阶段结束后生成，只供开发验收，不向独立 Skeptic 首轮泄露正向结论。
6. **检查真实前置条件并限定收尾。** 运行前逐项确认现有 COMPANY_RESEARCH、TECHNICAL_STRUCTURE、FUNDAMENTAL_EVENT、INDUSTRY_COMPARISON、MACRO_CONTEXT、MARKET_STATE 及既有交接要求，列明复用、补跑、合法受限或阻断。合法 INSUFFICIENT_EVIDENCE/SOURCE_LIMITED 按既有规则流转且保持覆盖状态，不升级 COMPLETE。跨阶段 Gate 可以因合法导入/运行身份重绑定而 hash 不同，必须核对既有导入记录、来源 Gate、输入版本、截止点适用性及报告 hash，不能只要求字节相等或以不等为由放宽验证。

## Acceptance / Stop Conditions

- 交付三域覆盖与正确性表：应有项、实际来源、时效、抽查结果和缺口；关键错误未修复则不能声明资料正确。
- 交付按 invocation 可追溯的关键证据消费记录，覆盖直接/间接引用与 CIO 消费；资料多或调用成功不是通过依据。
- 交付一条 MRVL 冻结样本的真实正向、独立反证、研究级 CIO 链路及内容复核：关键依据、反证处置、三域限制传递必须有实质内容；合法空缺报告不能单独替代此验收。
- 交付聚焦回归与剩余缺口清单，区分可接受辅助来源限制、未验证项和阻断。必需报告失败、引用非法、关键标准化错误或缺真实执行证明阻止完成；预算用尽则报告阻断，不自动续跑或降低标准。保留人工完成批准，不把本次验收扩大为历史收益回测、Promotion 或所有证券认证。

## Risks / Trade-offs

- [事件记录只能证明工具交付，无法证明模型注意或内部采用] → 交付与报告引用分列；内容使用由正式报告和独立复核判断。
- [来源受限的辅助数据使三域显示不完整] → 保留 dataset 级 gap 与影响，核心报告是否仍可消费按既有门禁，不补假数据。
- [模型修正扩大成无限调 Prompt] → 每个观察定位一项具体原因，重跑仅受影响节点，明确预算/截止点；失败如实保留。
- [共享代码与 Tiger/Luna 未提交改动交叉] → 先识别受影响 hunk，测试与提交只纳入本 Change。

## Migration Plan

不迁移历史报告或来源缓存。默认研究入口保持原完整 Company 配置；只给新的联调运行增加消费核对，不修改既有历史运行终态。若新核对或定点修正失败，保留旧行为与原始诊断，停止声明该链路通过。
