## Decisions

### 1. 一份草稿契约，多个既有研究角色

在现有提交与envelope模块扩展显式协议，先修八维，再覆盖全部已实现的当前新写入入口。共享身份、引用解析及装配职责，不统一不同角色的研究/评分业务Schema。每种语义草稿的工具参数Schema、交付指导和检查从该草稿的同一结构定义派生；不建大而全“万能提交服务”。

| 字段 | 模型职责 | 程序职责 |
|---|---|---|
| 主张、解释、反证、假设、充分性理由、观察条件 | 生成并承担语义责任 | 校验结构、原样保存，不改写观点 |
| Evidence/Document/Calculation/外部Claim引用 | 从实际允许对象选择，说明用途 | 精确解析并检查任务权限、实际查询、依赖版本 |
| run/invocation/agent/model、来源时间/身份、路径、版本、hash | 不生成、不复制 | 从真实调度/工具/冻结来源装配 |
| 原值展示和派生计算 | 选用何值、提出计算、解释结果 | 原值填入或确定性运算；保留单位、期间、来源时间类型 |
| 是否执行成功、提交完成、可下游消费 | 不自认证 | 从实际产物和校验记录推导 |

对最终格式优先保持兼容；外部Claim重名需要限定引用时显式提升契约并提供读取适配。普通股、Skeptic、CIO和Eval当前新写入入口必须纳入实际迁移测试；历史只读模式明确隔离，不能将未修复的活跃分支称为兼容分支。Intake、Risk等不要求LLM转录的健康接缝以检查证明保留，不无故重写。

### 2. 计算只选择，不重建

工具由服务端生成当前任务唯一计算标识；保留旧调用参数的显式兼容分支。返回短引用与业务结果，审计保存完整收据。模型的 `calculation_selections` 表达使用哪次成功计算及关联主张、解释；程序从该次真实收据或批准的预计算产物装配 method/value/unit/input refs/artifact ref。

短引用绑定 invocation、对象类型和不可变对象内容；Evidence与文档、计算、依赖Claim不能互换。ratio等有顺序运算保留分子/分母角色，不能排序或当集合归一化。失败计算不提供“成功可选结果”。跨任务或上游计算只允许已声明依赖和原权限所允许的读用，不给研报新增任意calculate权限。

最新旧草稿只作反例：不得把 `evidence_refs` 自动重命名或补齐为期望字段后称旧运行通过。新契约消除这项输入负担；旧协议仍准确返回结构错误，不猜作者意图。

### 3. 提交与修订沿原边界完成

顺序：验证可信任务/访问凭据 → 原稿结构 → 短引用/选择 → 冻结原值与计算记录装配 → 完整Schema/身份/PIT/引用/事件血缘 → 保存正式报告与回执。新Schema用到的关键字必须实际执行，组合约束不能提前return而跳过兄弟约束；未支持的约束在准备时拒绝，不静默忽略。既有决策专用校验不删。

沿现有两次尝试上限：一次首稿、至多一次由原Agent完成的字段/主张局部修订。返回有界错误列表、路径和可选对象，不只吐首个含糊代码。格式错误与引用误选可修；篡改、凭据不符或不可信身份立即拒绝，未授权调用不得改变目标状态或消耗目标额度。修订明确基于当前已存草稿引用，仅允许声明路径；保留原稿，生成新版本，并完整再校验。两次已授权草稿尝试失败后停止，不通过无效草稿“不占存稿名额”形成无限尝试。

最终消息只携带服务端签发的短提交引用，绑定精确草稿版本及hash；Stop结合真实Start与本地私有索引解析，不要求LLM复述SHA256。不得按“最近一稿”猜选，也不能只按序号接受跨任务回执。任务bearer凭据仍仅是防误路由能力，不等于模型进程身份认证；现有可信Stop证明不可取消。

### 4. 上下文按需、内容不裁剪失真

沿既有紧凑目录及受限query。移除模型无需填写的重复技术字段；保留证券、文档类别、期间、单位、来源角色、可知时间与抓取时间的区别。任务最低问题、输入焦点、正文/脚注/反证保持可发现、可读取，不按“支持结论”过滤事实。

轻量计数直接复用交付事件/usage：分别记录初始上下文、工具返回、父/子usage、缓存及未观测项；字节不是token，父usage不是全批总量。用同一冻结输入比较旧/新表示，缺严格模型基准时不声称总成本下降。至少须证明机械重复字段移除与初始表示实际减量，不能靠省掉研究资料达标。

### 5. 调试按依赖闭包，最终验收标准不变

扩展现有 `--start-multidimensional-task` 的固定二任务限制，复用当前拓扑解析所选任务的最小依赖闭包。例如OPTIONS仅执行自身；RESEARCH_REPORT需要基本面；不启动无关六维。新调试run使用唯一run_id，与旧包分离；同一冻结资料不意味着继承旧执行身份。

依赖复用只接受输入、cutoff、Gate、允许集、实际相关Agent/Skill/Schema/工具契约及上游报告绑定等条件均可验证的有效报告。共享代码/角色指令变化必须保守识别影响，不能只看旧PASS或手工改hash。复用不改原run/version，以显式provenance进入本次调试上下文；不兼容就明确缺口，不暗中启动LLM补齐。

定点产物显示“能力/依赖链补验”，不显示完整新八维。原Change最终仍要求一次新同批八维内容8/8；本次只降低调试重跑范围，不把它替换成拼批验收。未来若用户选择逐维组合验收，须单独批准并同步原Change，不能在本次apply中暗改。

### 6. 四种结果分开

- 进程：退出码/超时/用户中止。
- 契约：哪些任务形成有效报告、哪些失败、哪些因依赖未启动。
- 研究：最低问题、出处/期间/单位、推理关系、反证是否足够；未独立复核为NOT_REVIEWED。
- Change/Promotion：人工完成批准与候选晋升分开，结构PASS不代表任一项完成。

现有状态值通过明确映射展示，尽量不另造总分。失败码给出阶段、对象路径、期望/实得类别、可否修订；凭据及许可全文不出现在公开诊断。

### 7. 当前规划不再当执行日志

### 9. 八类工程契约的具体决策

**H12 版本。** 沿用 `product/version-manifest.json` 作组件批准版本的权威源；profile、拓扑和生成Prompt引用它，文件内容hash由实际文件计算。对已有Skill/frontmatter版本等镜像给出明确派生关系和显式更新步骤，检查命令只读、不得自行改配置凑齐。CIO3.1.2/3.1.0本次必须核对生效内容和原批准版本后解决，不简单取更大数字；旧候选锁永不回写。涉及版本与资源hash的互相引用须明确排除自身字段，不能形成循环hash。模型标识锁定真实配置/调用结果，不承诺版本字符串证明模型真的加载。

**H13 hash。** 在现有hash模块中区分file-bytes、canonical-object、self-excluding envelope、fact-content、delivered-view；使用现有契约版本选算法，不新增全库通用对象仓库。新对象序列化明确UTF-8、键顺序、Decimal/时间/数值表示、非有限值拒绝和自身字段排除；不同语义类型不得只因长度均为64就互相比对。把重复实现接到对应同一算法；历史版本保留原测试向量/算法，不重新hash改写旧数据。诊断报告期望/实际的hash类型、版本与对象位置，不要求模型解释hash。

**H14 Memory。** 沿用现有事实、获取观察、Research View三层，不另建存储。新契约用显式字段投影替代任意深度按同名字段删除：事实value内部同名键不能误删；变化的retrieved_at属于新的观察，不能抹去观测时间/PIT信息；value、来源、单位、期间及更正改变时必须体现内容变化。Gate freshness只影响本次视图hash，不另造事实版本；现有 `view_compatible_fact_hash` 仅在可证明唯一匹配时复用，零或多匹配报缺失/歧义。历史fact key与content hash按旧算法读，不重建数据库或推进checkpoint冒充新取数。

投影算法变化须显式版本化：旧记录无算法标签时只按其已知旧Schema解释，不能猜测或覆盖旧键；新观察关联既有事实版本必须可证明语义等价，否则保留不同版本并报告差异。该迁移是双版本读取/新写入适配，不以全库重hash作为前置。

**H15 Schema。** 覆盖当前写入草稿、工具入参、正式报告、CIO动作与Eval契约，不只检查新八维。优先复用已有标准实现；若本地仅有目前不完整子集，则通过一个标准Draft2020-12验证适配器（`jsonschema`依赖）取代这些当前入口的结构验证，不手写第二个不断扩张的Validator。拒绝未知校验关键字/未知dialect，允许明确声明的注解关键字；本地受控引用、关闭远程Schema获取。验证allOf/if/then/else/not、$ref及组合旁的兄弟约束、bool与number区别、非有限数。MCP实参在函数副作用前检查；Schema不支持即准备失败。旧业务/权限/Evidence/PIT/Risk验证保留；NO_TRADE null/0用相同正反例证明Schema、Prompt与专用规则一致，不能删除后者凑统一。

**H16 历史读取。** 为现有Research Memory/网页、研究依赖和CIO source-inputs读取分出artifact-integrity和current-execution两种职责。完整冻结包只按包内版本、字节hash、关系闭合及兼容解析验证，原目录移动/当前仓库升级不构成内容篡改。运行时依赖的当前权限、资源和模型锁仍由current-execution严格检查；artifact通过不能放行执行。旧包无Schema/资源正文时仅使用已登记的对应版本读取器；缺失则准确UNSUPPORTED_VERSION/MISSING_DEPENDENCY，不下载最新替代或伪造旧文件。包内路径检查越界/符号链接，迁移只验证副本，不动原包；不增加Execution Replay能力。

**H17 映射。** 在现有holding-research-inputs/topology中统一已接入的dataset→domain→capability→允许消费者/工具关系，输出路由与coverage共用解析；规则描述事实能力而不是投资判断。一个dataset可服务多能力，不强迫唯一归属，也不把研究域数或四项现有主拓扑误当全部八维。未知项标UNMAPPED并说明是否阻断，禁止默认归COMPANY。source语义到dataset映射保留source差异；收集成功、Gate允许、实际查询、实际引用分别计数，不从配置推断已消费，不自动将所有来源给所有Agent。Skeptic独立首轮不得因此接收上游结论。

**H18 状态。** 使用现有状态字段及确定性投影，不造一个总分：CLI、浏览器、导出报告与下游适配读同一事实。SOURCE_LIMITED可以已执行但内容不足；FAILED即使部分报告保存也不能全体READY；未运行/未复核与失败分开。格式通过不代表观点正确，可信读取不等于Promotion，用户中断不伪报全部产品失败。

**H19 开发方式。** 角色边界留Agent定义，方法留Skill，样本/目标/期间/额度/阶段能力留任务或版本化profile；同一规则只在权威处维护。开发Reviewer不要求每个修复重跑产品，也不以文字匹配测试代替行为；按H01–H19记录producer、consumer、正例、负例、适用旧证据和真实验证缺口。任务清单不是固定开发优先级平台，产品长期方向不写入当前阶段。

### 10. 跨阶段元数据装配不得伪造消费证明

资料准备的queries/attempts/artifact路径来自实际调用日志，模型保留检索意图、文档选择和原因，不自行宣称未执行查询。Company/Skeptic保持独立上下文和任务允许集，统一引用并不共享结论。

CIO保留模型选择的报告/主张及决策语义；程序从被授予的报告目录装配身份/hash，另从实际交付/读取事件生成消费证明。授予列表不能直接冒称已阅读，更不能自动为模型选择哪些报告支撑投资判断；原要求必须消费的报告仍须证据齐全。fixture Council和predecision CIO各自执行范围、主线程/子上下文契约不变。

普通股Eval与Runtime Eval当前native draft只由模型生成原rubric要求的评分、理由及引用；input/prompt/rubric/model/result hash与执行血缘由实际记录装配。不得因移除机械字段而改评分阈值或假造独立评审。历史完整结果可读；仍能新写入的旧分支要迁移，或在已有规格允许的明确退役边界下拒绝新写入，不能暗删产品模式。

### 11. 验收预算和停止条件

2026-10-01 人工批准将 predecision 验收输入改为新生成的真实正反包。公司入口复用既有冻结 Gate 绑定，在原数据包验证中使用已证明对应的原 Gate，在本次执行中使用新 run_id；不得重签原来源包或改变任何事实。反证入口显式核心范围只选择其现有准入要求，默认仍全维；核心范围的缺失辅助维度保持 NOT_RESEARCHED，不宣称完整八维。仅增加既有准备/宿主入口接缝，反证隔离、六项核心准入和 CIO 研究级非动作范围不变。先检查接缝，再按批准记录生成真实公司/五项核心正向/独立反证/CIO产物；旧缺失包保持缺失，不替其补写历史。

### 8. 验收预算和停止条件

1. 本轮proposal：零产品调用，只校验规划文档。
2. apply的确定性阶段：冻结最新失败原稿的脱敏结构反例，真实producer→consumer接缝、并行隔离、篡改负例、局部修订及旧报告读取；不启动全量Regression/Gate。
3. 确定性通过后，提出一个整体真实补验预算供明确批准，不逐条请求“继续”：建议**最多3次子调用/2次父运行**，一个基本面→研报闭包、一个期权定点，失败计数；默认用已核实的gpt-6-luna，不自动换模型。剩余维度共享提交路径先用冻结/合成草稿验证，不伪称全维真实新运行。
4. 最终整批8子/1父属于原八维Change的独立收尾授权，不叠加旧额度。可在恢复原Change时一次核定；本Change机械修复和有限真实闭包完成，并不自动关闭原内容项。
5. 确定性安全失败停止模型准入；两次草稿仍错则任务终止；批次预算到达或新实质内容错误未解决则保存证据停止新增调用。不得自动循环“改一句提示→再8维”。

本Change完成需：H01–H19各有代码/既有机制复用及正负接缝证据，不得仅登记后续；每种当前入口有producer→consumer确定性验证；已批准的定点宿主真实证明、有限成本记录、独立差异复核及人工批准齐全。跨阶段本次默认不启动CIO/Skeptic/Eval真实调用，其结果明确为“确定性接缝已验证，真实运行未补验”，不能冒称研究质量已验证。若实施涉及这些入口的启动、权限或真实加载行为，必须提出对应最小Smoke缺口和一次预算批准，未补齐不得冒称该项完成，不借3子/2父额度运行其它阶段。原八维未满足8/8仍未完成，两Change可共用有效证据但不冒领完成。

## Risks / Trade-offs

- [跨阶段机械迁移影响现有消费者] → 按当前入口逐一适配，不强制统一业务Schema；旧包只读兼容，实际受影响消费者正反接缝检查。
- [短引用/回执误绑定] → 类型/任务/内容绑定，精确选定版本，跨任务、跨run、旧别名和篡改负例；不依赖Prompt保护。
- [研究含义仍可能错误] → 保留模型责任和独立内容复核，不承诺Prompt或装配保证8/8；实质错不降标准。
- [局部修改仍影响别的主张] → 全草稿/依赖闭合再验，正文其它位置不被程序自动改动。
- [少跑可能漏共享回归] → 显式依赖影响分析+共享确定性测试；无法证明未受影响的旧证据不可复用。
- [规划再次膨胀] → 19类问题全部纳入但共用已有机制，每类只做已定位接缝；不新增来源、Agent、编排、回测或全量门禁。

## Migration Plan

按P0→P1→P2→P3实施：固定工作现场和19项边界；修首错、版本、Schema和hash转录；迁移当前角色接口及工程读取/映射；再缩减输入与调试范围，固化开发方式。每步在相关接缝确定性验证，不先堆平台。旧写入模式迁移前保留明确兼容，回退只停止新run启用，不覆盖旧包或用户修改；当前新写入分支未覆盖则相应项未完成。归档、提交、推送仍等最终人工批准。
