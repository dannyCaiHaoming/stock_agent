## Context

动机见 Proposal。本地已存在普通股输入派生/冻结、Company Analyst 并行派发、EquityResearchReport、中文渲染及聚焦测试；`product/mcp/live/` 有 Yahoo/AkShare 行情路由、SEC 及缓存实现。现有 `catalyst-analysis` 明确只在公司研究中分析公司事件，不能把它的名字当成已实现市场/宏观能力。

本次只读盘点未运行任何网络采集或产品 LLM，因此以下来源类别是实施候选，不是免费可访问性承诺。参考已有 `docs/product/common-stock-holding-analysis.md` 后续 TODO。旧 live Change 保持暂停，未提交依赖需记录归属。

## Goals / Non-Goals

目标：先用免费非实时资料完成有限的多维研究，再开发 Skeptic；每阶段均可阅读、单独验收并交给后续 Agent。基本面、技术、行业与市场环境是核心；披露与期权/资金能力尽量实际实现，真实不可得项有明确受限终点。

非目标：全市场选股、实时盯盘、分钟级策略、完整历史期权库、付费预期数据库、ETF/期权持仓专项、情绪/政客/社区全量采集、订单、自动评分平台或新沙箱。公开研报自动获取、读取和对比纳入本次；批量研报仓库、购买数据库和突破登录/付费限制不纳入。

## Decisions

### 1. 一个分阶段 Change，逐段形成产品结果

用户请求有序需求，本次采用一个有终点的 Change，而非立即创建七个空 Agent/独立框架。以下顺序是交付顺序；获得 apply 授权后阶段汇报不要求逐项批准。外部限制只阻塞依赖项。

| 阶段/目标 | Input → Tool/Data | Skill/Reasoning → Structured Output | 完成证据 |
|---|---|---|---|
| P0 来源与范围 | 已确认持仓、核心问题与首阶段字段 → 现有适配器/缓存有限验证 | 资料语义核对 → 渐进来源能力表 | 首阶段实际响应/失败与字段语义；后续来源在对应阶段核对，不阻塞前序交付 |
| P1 价格成交量 | 股票、cutoff、基准 → 日线 OHLCV/公司行动、收益/波动/回撤计算 | 新技术结构 Skill → 逐股技术报告 | 真实量价解释、相对强弱、观察区域和失效信号；拆股、缺历史等负例 |
| P2 基本面与事件 | 已有报告及缺口 → SEC/公司公开披露与既有计算 | company-research、valuation、catalyst-analysis → 增强公司报告/事件地图 | 至少两份报告合计体现增长驱动、现金流/资本配置、适用估值及实质事件；逐项限定资料不足 |
| P2R 自动研报研究 | 持仓与核心问题 → 只读搜索/正文获取/解析及冻结 | 研报读取对比 Skill，由公司/行业研究角色使用 → 研报要点、差异表及研究关联 | 实际自动发现并读到正文；两份可比研报解释假设分歧或版本变化；单份只验证读取，资料受限单列 |
| P3 行业比较 | 股票、行业与同行候选 → 同行公开披露/行情 | 行业比较 Skill → 行业报告与逐股关联 | 至少一组有选择理由的两家同行比较；每个受测持仓有行业传导或具体缺口 |
| P4 宏观市场 | cutoff 与市场范围 → 官方经济统计/利率、大盘行情 | 宏观市场 Skill → 共享报告与持仓敏感性 | 有公开时间的宏观事实、风险状态及至少两家公司不同的传导解释 |
| P5 所有权披露 | 股票、发行人标识 → 官方机构/内部人披露 | 所有权披露 Skill → 所有权研究 | 可得时至少一组可比持仓变化和一项明确类型的内部人交易；否则实际受限证据 |
| P6 期权与资金 | 普通股、cutoff → 合格链快照/直接披露或明确代理统计 | 期权市场结构 Skill → 专项报告 | 可得时至少一个有期限与报价时间的实际结构解释；禁止伪造历史、方向或净流量；受限逐字段列明 |
| P7 多维交接 | 同一基础 run 的公司报告与多维产物、经重新验证的兼容补证 → 绑定/时间/引用检查和渲染 | 仅归集不代替 CIO → canonical 多维研究包 | 已确认持仓进入，每项有去向，中文与 JSON 一致；明确区分结构可解析与下游就绪 |

P2 不强求每家公司具备同一深度；WOLF 类型重点核对重组会计、稀释与现金需求，周期公司重点驱动和资本开支。专题的缺口不能否定已有独立结论，也不能用旧基线忽略资料中的新事实。

各公司先用已有资料形成精简核心研究问题清单，关联各维度主张，避免各写各的。P1 生成同源价格/成交量、相对表现图，标明日期、复权和数据范围；图表不引入新判断。P2 对资料中可得的管理层指引保留原值、版本及变化，不能冒充一致预期；P3/P4 根据公司问题选择相关需求、价格或产业周期变量，不强制所有公司统一清单。

### 2. 研究身份与运行方式

开发交付顺序不等于每次产品运行的串行顺序。运行时由现有 Codex 主线程按已知依赖派发：合格公司基础资料就绪后，各公司技术、基本面与共享市场任务可独立推进；同行比较等待候选核实和同行资料；研报分析等待合格正文；公司结论更新等待相关研报分析。沿用三槽有界并行、乱序按身份归集及取消/超时机制，不建设通用调度平台。无依赖任务不能因另一维度未完成而被强制串行；单项失败只阻塞真实依赖项，共同输入无效仍停止相关研究。每份产物通过既有校验后即显示路径及进度，最终归集结果与缺口。

自动获取的实际职责：Company Analyst 承担公司研报准备，runtime_market_catalyst 承担行业研报准备。它们在新阶段的显式资料准备 invocation 中使用研报 Skill，调用按该 invocation 授权的只读搜索、正文获取及解析工具；查询由 LLM 选择，网络/解析由工具执行。现有两角色禁用通用 Web，不可把 Prompt 中“搜索”当成工具已可用；实施需在现有宿主/MCP 接缝绑定必要工具并保存实际调用证明。旧 fixture/COMMON_STOCK_RESEARCH 的工具白名单保持不变，正式分析 invocation 不继承准备步骤的搜索权限。准备工具对候选先做可用的发布时间筛选，未知日期仅标为待核实线索，不用于形成观点；正文冻结及 PIT 后才进入正式研究上下文。不为获取资料开放 shell、账户写入或新沙箱层。

保留旧 `COMMON_STOCK_RESEARCH`。新增显式 `MULTI_DIMENSIONAL_HOLDING_RESEARCH`，从 portfolio-council 进入同一宿主 launcher；用户不用准备 Evidence。准备分成有限的选择和获取步骤：LLM 从已通过 Gate 的公司资料提出同行/基准候选及理由，确定性工具核实身份、按预算取回资料并冻结，通过 PIT 后再正式比较。候选不是事实，选择上下文不能接收未过滤资料；默认每公司至多三个同行候选，不构成持仓上限。沿用现有 Codex 调用和只读工具，不另建 Python LLM 编排后端。

Company Analyst 继续公司基本面/公司事件。已确认 `product/.codex/agents/runtime_market_catalyst.toml` 存在，但 `product/.codex/config.toml` 尚未注册该角色，且其当前契约只返回 CatalystMap；文件存在不能视为可调用或满足新维度。本次复用并扩展该角色的显式 capability 与专业 Skill 绑定，保留原 CatalystMap 模式，新模式返回 ResearchDimensionReport；无需新增 Agent。新增技术/行业/宏观等 Skill 用隔离任务上下文执行，不把宏观结论塞入 Company Analyst。每次 invocation 只承担一个明确维度及范围；共享市场研究只执行一次。技术/行业按证券或同行组执行，有界并行沿用默认三槽，数量不封顶。

报告禁止组合动作；新角色不接收账户盈亏、现金等无关私人信息。历史公司报告可作为带时间与类型的研究输入，不冒充事实。后续 Skeptic 第一轮仍只读原始合格资料，不读本次多维结论；CIO 后续可消费研究包。本 Change 不接这两者。

### 3. 数据选择有明确边界

默认非实时日线：近 20/60/约 252 个交易日多窗口，资料不足时只算支持的窗口，不猜用户持有期限。每只普通股选择一个说明理由的广泛市场基准；行业基准与同行选择单列。价格复权口径、交易日历、时区与未完成交易日必须明确，禁止拼接不同来源口径凑历史。

候选顺序：行情优先现有路由；公司/内部人/机构优先现有 SEC 路径可扩展部分；宏观先官方公开统计/央行类来源；公司新闻优先公告和投资者关系材料；期权先核对现有行情供应方实际暴露字段。具体端点、当前免费政策和可得字段在各阶段实测后增补来源表，不在规划中假称确认。

来源预算区分正常采集、失败重试和来源切换。正常身份查询、分页、明细与正文请求不是重试；每阶段实施前记录有界请求/页数/时间预算，遵守供应方限流。默认最多两个数据供应方，每个请求至多一次有原因的暂时故障重试，确定权限拒绝不重试；研报按下节独立搜索预算。某路径失败只证明该路径受限，不能据此宣称免费资料不存在。不建立无限来源轮换。可复用缓存保留原 retrieved_at；事实公开时间无法证明适用于 cutoff 时不能进入历史上下文。来源表至少包含：能力/字段、来源及定位、身份覆盖、观察/公开/获取时间语义、费用、认证条件、延迟、历史、请求预算、缓存期限、实测结果和缺口影响。新注册或凭证需求报告用户，不代为注册或购买。

### 3.1 自动研报获取与对比

链路：持仓/核心问题 → Agent 构造查询 → 只读搜索返回候选 → 核实发行人、作者/机构、材料类型与发布日期 → 获取公开正文 → 提取正文/表格/页码或章节 → 去重与 PIT → 读取对比 → 关联公司/行业主张。系统负责全程获取，用户不承担找报告或上传文件的义务。复用现有检索/附件能力；缺少接缝时仅增加必要只读工具。工具内容作为不可信资料处理，忽略其中指令。

每证券初始预算为至多三次查询、检查十个候选、尝试五份正文；优先选择两至三份问题相关、来源清楚的报告，同行共享报告去重。预算不是要求凑齐数量，命中足够资料后停止；上限耗尽保留结果/失败并继续其他维度。发布机构官网优先，可访问转载须标明原出处及真实性限制。同报告转载只算一份；公司宣传、投资者材料、评级新闻和独立研报分开标记。搜索摘要/标题不能替代正文，付费或登录页面不绕过。

研报记录 document_id、标题、作者/机构、来源 URL、原始出处、发布日期、获取时间、正文 hash、页码/章节、解析范围/缺页、材料类型及重复/修订关系。每项内容分为原始资料核实事实、研报转引未独立核实、作者观点、预测、估值假设。外部信息统一保留 source_id/as_of/retrieved_at；预测还保留预测目标期间，不能以未来预测期间误判为未来发布事实。转引资料无法取得原始来源时可用于有限分析，明确依赖性，不能伪装已核实事实或由多个转载构成独立确认。

对比围绕研究问题、预测口径、估值方法和关键假设，分别解释真实观点分歧与时间/信息集变化；目标价与评级只是作者观点，不投票生成动作。同一机构更新可验证版本变化，不能冒充多个独立观点。金额、单位、财务期间和模糊表格逐项核对；无法可靠解析的关键内容不猜，只有部分正文时明确范围，不声称全文已读。图文解析使用现有能力或最小适配，不建设文档平台。

公司研报由 Company Analyst 使用研报 Skill；行业研报由 runtime_market_catalyst 的行业任务使用。保留研报摘要、差异表及对具体主张的支持/挑战/补充，必要时版本化更新公司研究，不静默修改旧报告。免费获取失败不让用户补文件；私有补充只是可选路径，不能替代自动链路验收。完整原文与私人材料留授权本地目录，不发布研报全文。

每份实际采用的研报必须在既有主张关联中说明：支持、挑战、修订或无新增信息，以及具体依据与理由，不能只把摘要附在报告后。修订由对应研究 Agent 完成，保存旧/新主张和报告版本关联；渲染器不得修改结论，不强迫研报必须改变判断。报告更新的调用计入该阶段预算，受影响研究只做必要更新。

材料若明确披露发行人赞助、付费委托或其他利益关系，保存披露内容及页码/章节；没有相关可确认信息标为 UNKNOWN，不断言独立或不存在利益关系。Agent 解释其对来源使用的限制，不因关系标签自动拒绝报告或降低为固定分数。不额外开展作者背景调查。

### 4. 最小输出与文件范围

复用现有 EquityResearchReport；新的 `ResearchDimensionReport` 只承载新维度，不强改旧报告。包括 schema_version、run/invocation、Handoff/request 绑定、security_ids/scope、cutoff、capability、实际 Agent/Skill/model、input/output 引用、窗口/基准/单位、执行状态、充分程度、评价状态、摘要、主张/假设/依据/计算、限制、观察条件。每项事实通过引用解析 source_id/as_of/retrieved_at。

`HoldingResearchBundle` 引用公司、逐股、研报分析与共享报告，列出 coverage 与 unresolved_cross_dimension_questions，不生成统一投资分数。中文开头提供多维摘要，逐维列关键发现、依据、限制和观察信号，仅归集已有主张，不代替 CIO 消解冲突。失败项有状态/诊断，不以合法报告替换失败。报告引用与原始事实引用分开标识；哈希/执行证明沿用已有机制，不建立新锁平台。

#### 4.1 canonical 下游交接包与补证规则

最终交接包选择一个基础 run，并锁定其 PortfolioHandoff、研究请求、证券身份、decision cutoff 与 Evidence Gate。每只普通股已有且与这些绑定兼容的 EquityResearchReport 必须纳入 `COMPANY_RESEARCH` coverage；若报告缺失、版本不兼容或无法重新验证，必须逐证券说明原因，交接包最多为 `STRUCTURALLY_CONSUMABLE`，不得标记 `DOWNSTREAM_READY`。不能因为 JSON 可解析就把全部公司研究写成 `NOT_RESEARCHED` 后宣称下游可直接使用。

补充报告只有在证券身份、能力、输入绑定、时间口径及 Evidence closure 都针对目标交接包重新验证后，才能替换或加入 canonical 包。不同 run 或不同 decision cutoff 的报告保留其原始 provenance，可作为该能力已经运行的验收证据，但不得静默拼成同一次用户研究。当前证据整理时，以既有完整多维批次为基础；宏观补证仅在兼容性复核通过后纳入，后续 SEC 所有权补证若未与目标 Gate 统一绑定，则只作为能力验收证据。

`unresolved_cross_dimension_questions` 必须从已验证报告中的真实分歧、限制、观察条件或待证伪问题归集，并引用相关报告；归集器只复制和建立关系，不新增投资判断。若确实为空，必须给出明确的 `no_unresolved_reason` 或等价说明。存在实质分歧却输出空数组，不能满足 `DOWNSTREAM_READY`。

消费校验至少给出两个独立结果：

- `STRUCTURALLY_CONSUMABLE`：Schema、绑定与引用可被程序读取；
- `DOWNSTREAM_READY`：公司研究和适用多维报告已进入 canonical 包，补证来源合法，待反证问题或空值理由完整，下一 Agent 无需人工寻找散落产物。

收尾优先复用现有产物并做确定性重组，不启动下游模型。若需要形成新的语义判断而现有报告没有提供依据，应保留缺口，不允许 Python 根据规则代写研究结论。

公开研报正文深化、13F 两期机构持仓、期权链及可验证资金行为的真实数据能力，按用户批准延期到 `capture-futu-client-research-data`。当前包保留 `SOURCE_LIMITED`、影响及责任 Change；延期不等于该能力通过，后续 Change 的存在也不能替代实际数据证据。

拟交付位置：`product/skills/` 新研究方法；现有 runtime 派发与宿主参数接缝；`product/mcp/live/` 最小来源扩展与现有计算模块；`product/schemas/runtime/` 新维度及汇总契约；`docs/product/multi-dimensional-holding-research.md` 与来源表；对应 `tests/test_*` 聚焦测试；`reviews/development/` 限定验收记录。私人 Handoff、真实研究包、凭证及原始采集留授权运行目录，不提交 Git。

### 5. 验证预算与最终判断

以下是本次固定的最低研究问题，也是各阶段真实内容验收的对应表，不强制字段数量或统一篇幅。每个适用问题需有回答与依据，资料不支持时逐项说明缺什么、影响什么；不能用不适用理由替代核心样本实质标准。

| 维度 | 最低必答问题 | 条件适用项与缺口出口 |
|---|---|---|
| 技术结构 | 趋势、相对基准强弱、波动/量价是否支持解释、推翻条件 | 历史不足或价格断点时限定窗口，不能制造长周期信号 |
| 基本面/事件 | 核心驱动、盈利与现金流关系、估值依赖假设、关键未知和事件影响 | 估值不适用说明原因；指引变化需可比版本，不强制缺失资料量化 |
| 研报 | 作者依据、预测/估值假设、与其他资料的分歧、对本次判断的作用 | 单份可读但不能证明多报告对比；资料受限按 P2R 分支；利益关系未知如实记录 |
| 行业 | 相对同行位置、行业与公司因素、可比性限制及传导 | 指标或同业不可比则保留可用比较，不机械排名 |
| 宏观市场 | 与公司相关变量、作用机制、显式假设及反向情景 | 变量无可靠资料时限定其推断，不能复制通用宏观叙述代替持仓关联 |
| 所有权 | 实际披露变化、交易类型、滞后/覆盖、可推断及不能推断的内容 | 单期不能声称变化；部分来源受限只延期相应子能力 |
| 期权/资金 | 实际观察结构、数据时效/覆盖、直接指标与代理指标、推断边界 | 无历史/方向不虚构，受限按 P6 子能力记录 |

本次新增接缝用聚焦检查覆盖：准备/正式分析工具权限分开、旧模式不变；独立任务可重叠、依赖未就绪不启动、单项失败隔离、先完成先展示；研报关联能分别表达支持/挑战/修订/无新增信息，修订可追溯旧新主张；明确利益披露与 UNKNOWN 都可表达。真实证明复用各阶段授权批次的工具事件和报告，不为上述检查另起全量运行或额外评分平台。

开发先跑实际受影响的计算、身份、时间、引用、状态与并发接缝测试。包括：拆股/重组断点、历史不足、未来宏观修订、未公布事件、不可比同行、披露滞后、单期持仓、失效期权报价、空数据和伪资金流。语义解释由真实报告复核，不用关键词/长度或硬编码投资结果代替。

每个核心阶段默认一次真实研究批次，沿用已确认的普通股持仓，优先复用有效冻结资料；技术、基本面至少两只具有实质输出，行业和市场按上表覆盖。这是能力样本标准，不能替代当前批次每只普通股、每个维度的结果或具体缺口。实质研究按四项复核：回答具体问题、引用具体事实、区分因果推导与假设、给出改变结论的观察条件；不使用字数或固定措辞评分。

开发阶段证据允许各自 cutoff，证明各阶段能力，不冒充同一次当前研究。一次用户研究包使用统一决策 cutoff，不同资料的观察日期可不同，但公开时间不得晚于 cutoff，并满足各维度明确时效。汇总复用历史报告需确认证券、方法、关键事实和窗口仍适用；不适用项仅更新必要部分或留缺口。历史截止点无期权快照时不得补造，记录该维度受限；需要当前期权研究可另建当前时点产物，不混作历史同批结果。P7 复用兼容阶段产物，不要求全部模型再跑。

P2R 默认一次授权研报研究批次，从实际持仓自动搜索并获取两份可比较正文，验证读取、观点/预测分类、差异及接入研究；两份同机构不同版本须如实标记。只有一份时只验证读取与单报告接入；单份/正文不可得需分别记录对比缺口。上传样例只证明解析，不证明自动获取。负例覆盖标题摘要冒充正文、转载重复、预测冒充实际、时间差异冒充冲突、模糊金额及未来公开报告。

LLM 研究默认 gpt-5.6-terra，用户可显式选择受支持模型；实际生效型号记录，评分模型独立。真实运行须通过现有宿主入口并遵守已有预算授权；计划次数不等于允许静默反复调用。失败保留证据，范围内确定性修复后仅补必要受影响项；额外模型批次先说明具体缺口与预算。

最终限定验收：渐进来源表 + P1/P2/P3/P4 核心实质报告 + P2R/P5/P6 实质或 SOURCE_LIMITED 证明 + P7 一次组装/消费检查 + 一次独立差异和内容复核 + 人工完成批准。复核抽查每个已声称通过的维度的关键事实、推理、限制及产物绑定，错误不能用平均分抵消。交接消费检查只解析并追溯，不启动下游模型。验收分别记录实现状态、研究验证和外部来源状态，不把 IMPLEMENTED、RESEARCH_VALIDATED、SOURCE_LIMITED 混成同一成功状态。不运行完整 Gate/Regression/Replay/Calibration/Ablation/Promotion。

用户已接受专项受限可延期并在其他研究完成后进入 Skeptic 的原则。条件任务有两条明确完成路径：资料可得，提交实现/实测结果；资料不可得，提交限定尝试、受影响子能力、未实现/未验证部分与后续 TODO，标记“受限分支完成，能力延期”。只有该项写明的受限交付实际完成后才能勾选，勾选不代表功能实现。实现错误、未执行或预算未声明不能冒充外部受限；有部分资料只延期受影响子项。最终批准核对具体延期清单，不逐项反复请求原则批准。核心能力缺实质证据仍未完成；专项延期不无限阻塞后续规划。

## Risks / Trade-offs

- 免费来源不稳定 → 有限尝试、缓存和具体受限状态；核心项无法实质交付则保留未完成。
- 维度多导致工作膨胀 → 固定 P1–P6 问题清单，额外指标进入 TODO，不自动增加 Agent 或平台。
- 指标齐全但解释空泛 → 每项要求公司/市场特定主张、因果依据、替代解释与观察信号。
- 官方披露具有滞后、修订和统计覆盖偏差 → 保留多种时间及覆盖限制；无历史版本不能宣称历史可重现。
- 活跃旧 Change 与未提交依赖混杂 → 仅记录和修改本次必要增量，归档前按实际依赖审查提交范围，不重开旧 Change。

## Migration Plan

新增显式阶段和输出版本，旧入口/报告继续可用；阶段失败可退回已有公司研究，清楚保留未完成维度。实施更新 PRODUCT.md 方向与说明；撤销新阶段只影响新调用，历史产物不重写。新规划不授权现在修改实现或生产指针。
