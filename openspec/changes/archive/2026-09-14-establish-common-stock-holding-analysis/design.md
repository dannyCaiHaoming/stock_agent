## Context

参见 [proposal.md](proposal.md)。当前 Intake 已能产生确认后的 `PortfolioHandoff v3`，Council 规划可识别普通股、ETF 和期权的能力需求；产品运行面也已有 `runtime_company_analyst`、`runtime_skeptic`、相关研究 Skills、Gate-scoped Evidence MCP 和通用 `AgentResearchReport 2.0.0`。

Change 初始基线中 Company Analyst 的角色边界正确，但输出主要是通用 `claims/assumptions/data_gaps`，估值产物和公司事件接入尚需实现。当前已有 AAPL/MSFT 研究样本；本次更新针对样本暴露的内容具体性、报告一致性、状态关联以及真实持仓入口继续完善，不将历史测试通过等同于增量要求完成。现行完整 Council 在混合资产能力不齐时必须停止，本阶段不放宽完整组合完成标准。

暂停中的 `us-equity-live-advisory-slice` 已产生可复用的行情、SEC、PIT、来源选择和单股真实研究基础，但其股票池、Provider 治理、三股批次和未完成验收不属于本 Change 的完成条件，也不得被改写为本 Change 的新证据。

## Goals / Non-Goals

**Goals:**

- 让现有 Company Analyst 提供有公司特异性的基本面、财务、估值和公司事件研究，而不是通用 Claims 生成器或完整持仓决策者。
- 从已确认 Handoff 与 CouncilRequest 派生逐证券、最小化、可追溯的研究输入。
- 对任意数量普通股复用一个 Agent 定义和独立 Invocation。
- 输出供 CIO 消费的 `EquityResearchReport` 和同源中文报告；第一轮 Skeptic 保持独立 Evidence 输入。
- 允许混合资产组合先完成普通股部分研究，同时明确不构成完整组合决策。
- 复用两只普通股的既有并行证据，补一次已确认真实持仓输入的受影响研究链路与聚焦 Eval，明确新旧证据的适用范围。

**Non-Goals:**

- 不新增 `Holding Analyst`、Valuation Agent、Catalyst Agent 或按 ticker 命名的 Agent。
- 不完成 ETF、期权、Market、Macro、Sector、技术图形、新闻情绪、资金流或机会挖掘能力；不为这些方向预建空 Agent。
- 不新增或更换真实行情 Provider，不扩大网络、沙箱、Replay 或 Promotion 平台。
- 不让 Company Analyst 输出动作、目标仓位或订单。
- 不把普通股部分研究称为完整 Portfolio Council 或完整 Risk 结论。

## Decisions

### 1. 复用 Company Analyst，而不是增加中间 Holding Agent

普通股公司研究由 `runtime_company_analyst` 承担；每只证券创建独立 Invocation。Company Analyst 负责“公司是否存在可辩护的持有 Thesis”，主线程 CIO 负责“该 Thesis 放入完整组合后应如何处理”。另加 Holding Agent 会重复研究或侵入 CIO 的组合决策边界，因此不采用。

备选方案是一个 Agent 同时研究全部普通股。该方案调用更少，但会导致公司上下文互相污染、单只失败影响整批且难以逐股重试和评价，因此不采用。

### 2. 新增普通股专属报告，保留历史通用报告

新增版本化 `EquityResearchReport`，以普通股专属研究区块承载内容，并保留既有 Specialist 的状态、证据、假设、缺口、置信度和 Artifact 引用语义。新版运行显式锁定新 Schema；历史运行继续按 `AgentResearchReport 2.0.0` 验证，不迁移、不补写。

研究内容归为六组：公司与核心问题；业务、竞争和财务；Thesis 与估值；催化剂和反证；失效条件与观察指标；数据缺口和置信度理由。每组可组合相关 Claims，不再要求十多个重复填表区块。每项输出 `equity-research.json` 和同源 `equity-research.md`，后者展示来源及时间。程序根据实际调用封装技术元数据，LLM 不负责复制或计算 hash。动作字段由 Schema 限制，文字越权由语义评价识别，不以 BUY/HOLD 单词扫描误伤引用。

不选择继续依赖自由排列的 `claims`，因为它不能保证研究覆盖；也不把研究质量编码为 Python 条件分数，语义完整性仍由 LLM Eval 判断。

### 3. Company Analyst 组合四项 Skills，但不拆成四个 Agent

Agent 固定加载：

- `evidence-grounding`：事实、假设、冲突与数据缺口；
- `company-research`：商业模式、财务质量、竞争与资本配置；
- `valuation`：方法、假设、情景与不确定性；
- `catalyst-analysis`：仅处理公司特定且在 cutoff 前已知的事件。

这些方法共享同一公司上下文，拆成多个 Agent 会增加重复 Evidence、协调成本和冲突，首版没有可测收益。独立 Skeptic 继续单独运行，因为其价值来自上下文隔离，而不是技能分类。

### 4. 输入按研究职责最小化

由 Handoff/Council 绑定层产生单证券 `HoldingResearchRequest`。输入包含证券身份、问题、期限、cutoff、允许 Evidence、数据缺口和必要 Mandate；默认不向 Analyst 暴露成本、盈亏、现金和其他持仓。可选 `user_thesis` 与 `user_questions` 作为用户陈述单独标记，不作为 Evidence。

用户输入是上一层已确认的持仓结果与自然语言研究意图，不要求用户准备研究请求或证据文件。系统从当前确认结果自动构造并绑定研究请求。为避免旧 `CouncilRequest 1.0.0` 强制要求组合字段，新增其显式版本及 `stage=COMMON_STOCK_RESEARCH` 分支：`benchmark_id`、`mandate_artifact_id`、`holding_horizon` 可为 null，问题由用户意图生成；期限未知时只作当前公司研究并展示限制，不猜测期限或比较基准。完整 Council 分支继续要求其既有必要字段；旧版本保持原校验。不得把阶段信息写回中立持仓交接对象。

这样既保留“这是已持有证券”的研究目的，也避免 Analyst 因浮亏或成本价产生组合动作和锚定。完整 Portfolio 仍由 CIO/Risk 独立消费。

用户 Thesis 缺失不阻断研究，首次运行建立本次研究基线。可选历史研究仅在显式提供且绑定与时间有效时比较，不增加自动历史检索；历史解释不能替代当前事实。LLM 选择通常两至三个核心问题，形成事实→假设→业务影响→推翻条件的因果链，按公司特征关注现金流质量、债务与融资、稀释、一次性项目和适用业务指标。

### 5. Evidence 按可用性表达，不伪造全维度完整

资料准备由现有宿主入口接续完成：确认持仓→按证券复用合格缓存或现有只读适配器获取公司资料→核实证券身份→冻结并执行时间过滤→派发研究。用户无需额外上传资料；持仓截图中的成本与报价仍是账户观察事实，不自动充当最新行情或财报。研究开始后只读本次固定资料，资料缺口进入报告，不新增循环联网补料流程。已有来源权限、请求预算和时效规则保持；实际资料准备失败按证券记录，公共配置失败如实报告。

身份核实复用现有映射，核对发行人、股类及必要的时间关系；更名、重组、调整后不能只用相同代码连接旧公司财报。无法确认的证券停止自身研究，保留在覆盖清单；其他独立证券可继续。首版不建设完整公司行动数据库。

普通股输入准备不得直接沿用 `build_live_specialist_inputs` 对 `value_portfolio` 的强制依赖：后者需要完整组合每项资产价格，可能因未支持的期权价格阻断普通股。复用其中公司资料和身份校验的适用部分，为本阶段构造证券级输入，保留完整持仓引用但不运行完整组合估值。ETF/期权价格、购买力、保证金缺失不阻断公司研究；完整组合核算和硬风险校验仍属于后续决策阶段，原规则不放宽。

采集失败与分析失败一样按证券隔离。资料准备在既有请求和时间预算内结束，各项得到成功、缺口或失败状态后确定共同截止时点并冻结可用资料；不要求所有证券采集成功，不等待失败项无限重试。有可用资料且身份有效的证券按既有规则进入研究，无可用资料的证券保留资料不足，身份或完整性错误如实记录失败。共用配置或输入完整性错误仍停止受影响批次，不把它们伪装成单股数据缺口。

普通股研究复用现有冻结 Evidence 和 PIT Gate。优先使用证券身份、合格价格、最新及可比 SEC 财务事实、业务/风险/MD&A 披露片段和确定性计算产物。Schema 要求每个研究维度有结构化状态，但不要求每个维度必须有结论；缺证据时必须以数据缺口、低置信度或证据不足表达。

这避免为了满足模板而编造估值、事件或公司事实。新的 Provider、分析师一致预期和新闻不作为首版门槛。

### 6. 估值和财务数字只由确定性工具计算

在既有只读数学工具上补齐研究实际需要的可审计操作和估值产物，输入只能引用 Gate 合格 Evidence 或显式假设。工具输出公式、输入、单位、期间和 hash；LLM 选择方法并解释，不由工具产生“便宜/昂贵/应持有”等判断。

若首版 Evidence 不能支持 DCF 或可比估值，报告应如实返回估值缺口，不以完成某种估值模型作为强制条件。

首版优先复用比率和期间比较，按样本实际需要补充有限算术/情景操作，不建立通用估值平台。LLM 解释当前价格隐含预期及假设的可辩护性；不强制输出目标价。真实验收样本至少展示一种有确定性计算依据的估值视角，缺口状态不能代替该能力证明。

价格隐含预期是条件性分析，必须说明增长、利润率、倍数或折现等所用假设；单个市盈率不能直接证明市场预期。报告首段 `research_summary` 由公司研究 Agent 生成，概括经济逻辑、证据和推翻因素，可作业务质量、盈利可持续性与估值敏感性判断，但不指定用户交易动作。它复用六组内容中的主张和引用，不新增一套研究体系。

`confidence` 仅表达当前资料对研究判断的支持程度，说明主要依据和不确定性；不表示上涨概率、盈利概率或预期收益率，不新增概率校准系统。摘要通过稳定的主张标识关联正文，正文继续关联假设、反证、计算产物与失效条件；引用在同一报告范围内必须闭合。CIO 消费完整报告及引用资料，不能仅接收摘要。复用现有主张和产物标识，不创建额外交接文件或知识图谱。

### 7. 混合资产使用“完整规划、部分研究、禁止完整决策”

CouncilRequest 继续声明 `ALL_INPUT_POSITIONS`，Research Plan 继续列出全部资产。新增执行阶段只消费其中 `company-research=AVAILABLE` 的普通股项，并生成：

- 每只普通股的 `HoldingResearchRequest` 与 `EquityResearchReport`；
- 全持仓 `ResearchCoverage`，区分排队、运行中和各终结状态，包括低置信度、超时、失败、证据不足及能力缺口；只有有效研究产物才可标记 RESEARCHED；
- 与原 Handoff、CouncilRequest、Portfolio hash 的绑定。

只要 ETF/期权尚未覆盖，阶段终态必须是部分研究，不进入完整 CIO 决策发布。这样既能先交付普通股研究价值，也不偷偷降低现有全组合安全边界。

### 8. 验收只证明本次新增能力

原两股样本证明范围仍是输入绑定、逐股隔离、真实 Agent/Skill、并发和对应输出评价；执行区间重叠以真实子会话事件为据。研究质量仍要求两份报告具有业务理解、可比财务解释、Thesis 因果链、公司特定反证与重评条件，合计至少一种有计算依据的估值视角。旧证据只能支持未受影响的结论；被修改的 Prompt、报告内容及模型绑定不能直接继承旧质量 PASS。

本次只补一次用户已确认真实 Handoff 的宿主研究批次：自动准备资料、按普通股独立派发、输出报告及全持仓覆盖清单，并对新有效报告执行既有聚焦 Eval。未知身份或缺资料的证券保留原因，不能换成容易成功的证券；ETF/期权保留未覆盖。资料不足可证明链路正确处理缺口，但不能充当研究质量通过。若本次批次不足以证明受影响的质量要求，只报告具体缺口，不自动追加模型批次或扩大来源。

验收分开记录“输入链路”和“研究质量”：前者要求全部输入均有可追溯去向，成功、资料不足和身份错误都按实际结果保留；后者仍按两份实质研究与至少一种计算估值视角核对。逐项注明旧证据是否受本次修改影响；受影响的内容只能由新证据证明。如果新批次仅有一份实质报告、其余旧证据对相应质量要求不再适用，则仅该质量项保持未完成，已通过的输入链路不随之判失败。一次批次是本轮执行预算，不是必然通过的保证，也不是自动补跑授权。第 8 节是本次验收与证据复用的统一口径，任务中的原两股记录仅描述历史证明。

新增确定性检查仅覆盖模型参数传递、自动资料准备接缝、同源报告及引用一致性、Eval 结果绑定和状态关联；其余有效测试复用。不先做额外单股 Smoke，不启动真实 Skeptic/CIO、完整 Council、Execution Replay、12-case Regression、Calibration、Ablation 或 Promotion Gate。真实持仓和原始产物只保存在仓库外，验收记录脱敏；不改写旧版本锁或历史报告。

### 9. 通过现有 Codex 调度实现多持仓有界并行

默认目标 `max_concurrent_analysts=3`，有效上限取配置、实际环境能力和预算允许值。主线程通过现有 Subagent 派发/等待接口维护待处理、活跃和已结束项目，空位出现即补充下一项；Python 仅准备输入、记录事件和归集产物，不创建独立 LLM 编排后端。对照全持仓清单核算所有状态，按证券和 Invocation 绑定归集，输出目录互不覆盖。

同一批使用冻结且经过 Gate 的资料和共同 cutoff；Agent 只能读取各自许可范围。资料可共享只读存储，Provider 采集预算独立于 LLM 并发。单项非法输出保留 FAILED，其他独立研究继续；共同输入完整性错误停止相关派发。串行回退必须显示 SERIAL 和原因，并行验收仍未满足。不承诺固定加速倍数或 token 降低，不为性能结论额外运行串行对照实验。

宿主 launcher 复用现有启动与认证路径，增加显式研究阶段选择，进入既有 Codex 主线程后仅派发 Company Analyst，停止于研究报告集。默认完整 Council 路径保留；本阶段无论输入是否全为普通股都不自动启动 Skeptic、CIO 决策或 Risk。Skeptic/CIO 本次只做交接兼容验证，实际升级留给后续需求。

### 10. 结果逐项可见，执行与质量分别表达

复用现有产物和进度输出：每只报告通过结构和引用检查后立即提供中文报告路径，不等待最慢项目；注明语义质量“未评估”或已有结果，不能以进程成功替代质量通过。进度包含总数、排队、运行中、已完成、失败及未覆盖项，最终按证券身份稳定归集。

普通产品研究不隐式启动语义 Eval；结构、绑定和引用检查仍为必要条件。只有显式验收或用户请求才启动独立评分模型，未评分报告可按本阶段边界输出并显示未评估，不冒充质量通过。本次验收的评分属于第 8 节明确的授权范围，不是日常研究的默认成本。

执行状态回答是否结束，研究状态回答资料充分程度，评价状态回答是否实际通过质量评价，覆盖状态回答哪些持仓得到处理；不得合并为一个 PASS。两股验收仅证明样本及本切片，不宣称所有普通股或特殊公司均已覆盖。

任务超时与批次预算沿用现有明确配置并在运行开始记录有效值；缺少时使用显式阶段配置，不无限等待。单项超时停止该项并保留诊断；批次预算耗尽停止新派发并终止剩余任务，已完成报告保留。用户取消同样停止派发并结束活跃任务，记录取消状态。模型默认不自动重试、不静默修复报告；用户重试时仅针对失败项创建新调用并保留原失败。现有数据传输层的有界重试规则不变，不建立自动重跑平台。

| 组合综合 | 跨研究冲突、持仓暴露、期限、机会成本和动作 | 后续 CIO 综合，确定性核算与硬约束归 Risk/工具 |

上述是问题分工，不承诺一个方向一个 Agent。只有研究问题、上下文或独立判断确需隔离时才考虑拆分；指标以 Skill/Tool 组织，后续仍须具备 Input → Tool/Data → Skill/Reasoning → Structured Output → Eval。Company Analyst 可解释合格披露中行业变化或内部人事件对本公司的影响，不据此声称完成行业、资金或交易时点研究。第一轮 Skeptic 仍独立；未来专业结论供 CIO 综合，不要求本轮搭建动态路由或第二轮辩论。

报告用现有研究范围与缺口结构说明“本阶段未研究”和“范围内资料不足”。前者不阻断公司研究、不意味着没有风险；后者必须说明哪些公司判断尚不能成立。即使全部资产是普通股，COMPLETE 也只表示本阶段执行/报告状态，不能表示完整持仓分析。

### 12. 提高研究密度，不增加重复填表

沿用六组报告与现有 Claim/假设/反证/观察引用，不新增大型报告体系。对核心 Thesis 显式写出尚未证实的前提，关联业务影响及最强反证；事实本身不强制附虚构假设。风险需区分已经观察到的负面事实与可能发生的风险机制，指明挑战哪条主张。

关键观察项提供已有指标基线、单位和比较期间，并说明后续何种可观察变化会触发重评。缺少数值基线或合理阈值时明确未知，可使用具体的定性披露条件；不由 Python 设置投资触发阈值。现金流质量不能仅用收入/经营现金流增长概括；按公司问题解释资本开支、自由现金流、营运资本、融资和一次性因素，缺资料则限定结论。历史财年 P/E 保留方法限制，不能直接断言市场增长预期。

数据缺口分别说明未获取、尚未披露、来源不支持或原因未知；“尚未披露”等状态须有支持依据。冻结包没有后续财报，不足以断言已有更新但未获取；没有事件资料也不等于不存在事件。

中文报告从通过校验的 JSON 生成，检查最终落盘文件的研究内容与引用一致。已发现的 AAPL 中文编号差异需在 apply 中定位，不能先假定是模型或渲染器错误；原始包保留，新修正产物另行记录来源。CIO 消费完整报告及可解析的证据和计算引用，不靠人工转抄。实际 Eval 与报告身份/hash 绑定后，覆盖清单关联其真实状态及路径；旧报告的评分不得移植到新报告，没有评分仍显示未评估。

一致性失败须定位到产物：JSON 或其引用非法，禁止下游消费；仅 Markdown 偏离合法 JSON，禁止将该 Markdown 标为有效报告，报告对的一致性验收未通过，但不自动否定已验证 JSON 的研究内容。纯渲染错误只需由原 JSON 生成新的修正版并验证，无需重跑研究 LLM；原始文件及差异记录保留。

用户入口是 `portfolio-council` Skill，承接已有确认持仓和自然语言研究意图；宿主 launcher 是当前真实运行和测试的执行承载，不是替代 Skill 的独立产品形态。Skill 使用已确认 Handoff，内部复用现有资料准备与启动接缝，不要求用户手工转换文件、构造或传入 Gate；冻结 Gate 可保留为显式开发样本入口，但不能替代用户路径验收。本轮不新增界面或编排后端。不重复确认未改变的账户事实，不将新研究时间写回持仓观察时间。并发上限不是输入数量上限。

现有宿主入口增加显式研究模型参数，作用于本批 Company Analyst；未指定时仍使用既有默认路由，本轮选择 `gpt-5.6-terra`。宿主父运行使用其有效配置并单独记录，本轮可以同用 Terra，但不建立父运行与 Analyst 模型永久相等约束。按有效配置/执行证据记录各自实际模型，不只在 Prompt 中自报。评分模型独立选择，未指定沿用其原配置，当前同为 Terra；改变研究模型不自动改变评分模型。不可用或不支持的选择明确报错，不静默回退或扩大预算，不修改开发主会话选模、全局路由策略或历史运行锁。其他模型的参数接缝可用确定性样例验证，无需多模型实跑比较。

### 14. 本次追加：准确性修正与有限研究深化

本节对应用户在报告复核后明确要求写入需求的优化，新增工作由 Tasks 第 8 组承接。它补充第 8 节及原收尾终点，不撤销历史完成记录、不继承旧质量 PASS，也不扩大 Agent、Provider 或平台范围。既有六组报告、四项 Skills 和完整 JSON 交接不变。

1. **金额与口径准确性。** 保留来源原数值、币种、数量级、税前/税后及期间语义。单位换算复用确定性工具/格式化能力；例如合成样例 `$1.8 billion` 必须显示为 `18 亿美元`，不是 `1.8 亿美元`。不能将税前出售收益直接从税后净利润扣除。数字和引用都正确才支持相应事实；引用存在不证明语义正确。不增加基于证券代码的修补或投资判断规则。
2. **最新事实与可比基线分开。** 在当前 Gate 允许资料内识别同指标的较新重要事实，按实际期间、主体和单位呈现。旧资料可因可比性保留，但必须说明用途，同时呈现较新事实及其限制；不把累计流量当成季度，不将重组前后仅因天数相同就视为可比。最新资料仅指本次冻结可用集合，不能据此宣称全市场最新或自动联网补料。
3. **经营驱动与有效反证。** 围绕核心问题，把已有价格、销量、产品组合、成本、利润率、营运资本、稀释或一次性因素连接到盈利和现金流影响；无拆分数据时明确只能定性解释。现实反证需引用可观察事实、说明挑战对象、机制和可比性。披露风险清单只能说明潜在风险；不可比期间的亏损减少不能包装为有效经营改善反证。没有可靠现实反证时如实说明，保留具体风险/待验证条件，不为填栏目编造对立结论。
4. **有限条件情景。** 对最重要的未决问题，用现有假设、主张和失效条件表达基准判断及向好/向坏条件，解释什么会改变结论。按实际资料形成定性情景，不强制每家公司三个数值模型、概率、目标价或买卖动作；量化情景仍需有依据的输入及确定性计算引用。
5. **中文可读性。** 正文优先显示核心判断、关键事实及简短引用，完整 canonical ID、来源与时间、单位和实际期间在同源附录可追溯；JSON 保留完整引用。不得通过删除依据或更改判断换取简洁；不要求 LLM 再生成一套独立 Markdown。纯渲染问题只重渲染，不启动研究模型。

#### 14.1 解释与选择规则

“较新”先核对相同指标定义、主体/合并范围、币种、期间性质与会计基础，再分别看报告期间结束日及披露/修订时间；不得按 retrieved_at 或单一最大日期机械覆盖。季度、年初至今和全年分别保留；同期间修订须说明适用版本及来源，冲突不能判明时保留冲突并限制结论。上述只在 Gate 合格集合内进行，不绕过截止时间。重要性由 LLM 围绕核心判断解释，不增加确定性重要性评分。报告不要求罗列所有资料，但对当前用作论据或观察基线的指标，不能无说明遗漏包内较新且适用的事实。

“有效反证”指已有事实对某条核心判断形成实质挑战，不等于任何负面词语。对悲观判断的反证也可以是有依据的积极事实。没有可靠反证时，明确其缺失、已检视资料范围及可观察的验证条件；这种诚实缺口可通过“不编造”检查，但不能单独证明既定的反证研究能力。原两份实质研究的反证标准保持不变，不能用风险清单或缺口替代；有效旧样本只证明未受影响部分。

情景沿用现有字段，不新建情景协议：每个适用条件应能关联“依据/显式假设 → 经营或现金流影响 → 哪条判断改变 → 观察信号”。没有依据支持某一方向时说明原因，不强凑三套叙事。不同期间长度、金额单位或会计基础的错误属于事实准确性问题，不以低 confidence、免责声明或平均分抵消。

#### 14.4 fresh-start 可比性与数值基线补充

WOLF 的最终复核暴露出一个比期间长度更深的边界：现有确定性 SEC 比较器校验同指标、单位、期间结构、同一披露与算术差额，但这些条件不能证明重组前后会计基础或每股分母可比。比较产物因此显式声明 `accounting_basis_status=UNVERIFIED` 和仅限算术比较的范围；Agent 必须结合冻结披露识别 fresh-start、重组、前后继主体、重述或重大处置。跨结构断点且没有额外可比证据时，只能分别呈现原值和限制，不能称为经营趋势或现实反证。Python 不从披露关键词生成投资判断，也不替 Agent 判定商业重要性。

同一轮补齐两个展示要求：采用大幅百分比变化时同时给出起止原值和绝对变化，并解释低基数、负基数或一次性因素；观察指标在引用数值 Evidence 时优先保留实际数值基线、单位和期间，只有数值不适用或无法可靠展示时才使用定性状态并说明原因。这些规则进入同一 Company Analyst、Skill、派发包和 Rubric，不新增 Agent、Provider 或报告字段。

验收只重跑受影响 WOLF：ALB、MRVL 报告及 Eval 保留原结论；新 WOLF 必须不再把跨 fresh-start 的 EPS 差额当作可比恶化或反证，仍能以断点后经营现金流、流动性、客户集中及其他可靠事实形成有限研究。新报告绑定自身聚焦 Eval，并由独立 Reviewer 只读复核。旧 WOLF 报告和 PASS Eval 原样保留并明确降级为已发现语义缺陷的历史证据。

额外采集后的分部驱动桥接、正常化盈利与完整 FCF、同行竞争/成本曲线、客户订单跟踪、融资稀释专项和定量情景模型继续作为后续 TODO，注明资料依赖与预期价值。这些能力仍优先增强同一 Company Analyst 的 Skills；图形、宏观、板块、期权和资金流不纳入本次。

**有限验收：** 先以脱敏已有样例做单位/期间/引用/同源渲染的受影响确定性检查，用既有 Rubric 定点审阅事实解释、反证及情景，不增加评分平台或逐字中文断言。新方法的真实推理证明只在明确 apply/运行授权及既有预算内按受影响证券安排一次有界宿主研究与显式聚焦评价；先列明复用项和必要新输出，不自动重跑成功且未受影响证券、完整 Council 或全量 Gate。若旧预算已耗尽或需新运行授权，报告具体缺口，不以本次文档更新视为额外调用授权。历史错误原件和评分不改写，新输出与评价独立绑定。已证明的输入和并发能力不重复验收；第 8 组闭环后仍由 Task 5.4 承接最终人工批准。

## Risks / Trade-offs

### 收尾补充：合格首版与优秀深度研究分开

#### 当前分析与后续深化的分界

当前冻结资料已包含且会显著影响公司判断的信息，本次必须解释。后续 TODO 中的现金流、一次性项目、资本配置等指额外资料获取、系统化拆解或专项建模，不能成为忽略已有事实的理由。例如已知出售收益应解释其盈利持续性影响；完整正常化盈利模型可以后续完成。LLM 按公司问题选择深度：成熟公司侧重现金创造与资本配置，周期公司侧重价格/销量/成本，困境公司侧重融资与恢复；不编码成 ticker 路由或固定评分。

缺口沿用现有 `data_gaps.impact`、区块状态及报告状态说明，不新建评级系统。缺同行资料仅限制相对竞争结论；缺资本开支限制自由现金流判断；期间不明时暂缓依赖该期间的比较，仍可保留独立且有依据的其他分析。证券身份无法核实或必要输入非法仍按现行契约停止对应研究。历史重组样本首版须准确解释已有期间及其限制，但不强制补完融资重组专项。

`research_summary` 用自然中文说明当前最有依据的判断、最重要的未决问题及该问题可能改变的结论；不存在关键未决问题时如实说明，不强造问题。沿用摘要到主张、假设、缺口的现有内容与引用，不新增交接文件。CIO 读取完整报告，第一轮 Skeptic 继续隔离。

#### 本轮收尾终点

Task 7.4 检查四项：实际财务期间与比较口径；已有关键事实的解释及现实反证/假想情景区分；摘要中可用判断与未决问题的影响；中文/JSON及覆盖状态一致。合计仍须满足既定两份实质研究和至少一种有计算依据的估值视角，不重复计数、不新增篇幅或统一财务模型门槛。

已完成的输入与并行证据按未受影响范围复用。当前方法的内容证明需绑定实际新输出，不能继承旧质量 PASS；具体补跑仍按第 8 节预算和明确授权执行。发现一般深度增强时记录到后续 TODO；事实错误、关键结论缺依据、交接不可用或违反既有安全/规格要求时保留对应未完成项，指出具体问题，不启动泛化 Gate。闭环后转 5.4 人工完成批准。

当前报告须回答核心问题、判断及依据、因果解释、最强反面因素和改变判断的条件。事实准确是底线，信息密度与解释力是质量目标，篇幅、栏目数和固定结论不是目标。完整成本曲线、正常化盈利模型、客户/订单跟踪、融资重组专项依资料逐步增强同一 Agent 的 Skills，不新增深度研究 Agent。

财务期间读取实际 `period_start/period_end`，区分期间流量、时点余额和发布时间。`FY`/`10-K` 不证明十二个月；重组、业务出售或前后继主体的不可比性进入解释与观察基线。确定性层只传递/展示资料，不按证券代码改写结论或通过关键词生成评级。派发保留期间并补齐单位和来源定位，研究 Skill 与既有语义 Rubric 明确口径审阅。

中文渲染显示 JSON 中的完整假设及理由、主张类型、反证/失效关联，以及资料实际期间、单位、发布时间和可用来源链接；未知不猜测。不新增研究结论，不修改 JSON 凑齐展示。新的渲染格式由新产物证明，不声称历史 Markdown 符合新格式。

产品说明维护三层 TODO：本次补齐、公开资料后续深化、额外资料依赖。后两类不进入本轮完成计数，不授权新增 Provider/Agent/平台或循环采集。现金/长期债务不等于现金跑道，税前一次性收益不能直接从税后净利润扣除，单一 P/E 不能证明市场隐含预期。

本轮仅做渲染、上下文字段、已有状态映射及方法指令的聚焦检查和一次独立差异复核。旧运行包只读保留；历史重组样本的旧期间错误、覆盖状态差异和中文变化不得通过代码更新被宣称已修复。真实新输出未验证时保留质量待办，沿用第 8 节不自动补跑的预算边界及原 5.4 人工批准。

- [普通股报告更丰富可能增加上下文和输出长度] → 对 Evidence、披露片段和各区块设置明确预算，逐证券运行，超限时保留缺口而不是把全部原文塞入 Prompt。
- [四项 Skill 在一个 Agent 中可能出现方法混杂] → 用专属报告区块和 Skill 输出约束分隔职责，通过 Eval 检查每部分是否有证据或明确缺口。
- [部分研究容易被用户误解为完整建议] → 在机器产物和中文展示中同时标记 `PARTIAL_RESEARCH`、未覆盖资产和“未形成完整组合决策”。
- [估值数据不足导致报告看似不完整] → 允许合法 `INSUFFICIENT_EVIDENCE`，并把需要补充的数据写成具体重评条件，不以模型记忆补齐。
- [与暂停的 live Change 文件区域重叠] → 实施前按文件归属复核未提交修改，只复用稳定接口；不改其 Tasks、历史证据或三股验收状态。
- [公司研究也主动寻找反证，与 Skeptic 有内容重叠] → Analyst 记录研究中发现的反证，Skeptic 仍以隔离上下文独立形成 Counter Thesis；二者不共享第一轮输出。
