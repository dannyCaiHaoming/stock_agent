## Why

当前系统已经能够把截图和手工输入转换为确认后的 `PortfolioHandoff v3`，也已有 Company Analyst、Skeptic、CIO 与真实只读 Evidence 基础，但 Company Analyst 的输出仍偏通用 Claims 容器，尚不能稳定形成一份完整、有研究价值的普通股持仓报告。现在需要先把“已确认持仓 → 普通股专业研究”接通并做实，而不是继续增加机会挖掘输入、空 Agent 或工程平台。

## What Changes

- 本次用户确认继续优化公司研究能力，新增第 8 组任务承接最新报告复核发现：金额数量级错误、遗漏包内较新重要事实、期间比较表述错误与弱反证。历史完成项及原产物保留，不把旧技术/质量 PASS 当作新增要求已完成。
- 用户复核 3.0.15 批次后进一步确认：验收“本轮输出可交给下游”时，必须逐份评价本轮实际产物；同一证券的历史 PASS 只证明当时产物，不能替代本轮新生成报告。本轮 WOLF 暴露的跨 Evidence 期间合并和弱反证因此继续由第 8 组定点关闭。
- 第 8 组完成判定集中在 Design 14.1–14.3：明确资料选用、反证缺口与能力证明的区别、逐任务交付/证据/不通过条件及停止点；复用现有记录，不新建验收平台，不用一般深化建议无限延长收尾。
- 在现有资料内提高经营驱动、反证和条件情景的解释力，并减少中文正文的重复技术信息；具体边界见 Design 第 14 节。金额/单位、最新资料选用及有效反证属于本次准确性与研究质量要求；额外采集、完整预测/估值模型和跨公司深描仍留后续 TODO。
- 首版深度以资料是否已经可用及是否影响核心判断为界：本次冻结资料中已有的重要事实必须分析；需要额外采集、跨公司比较或专项建模的深化进入后续 TODO。后续 TODO 不豁免本次解释已有事实的职责。
- 资料缺口按影响范围限定结论：缺少同行、资本开支等资料时说明哪些判断不能成立，保留其他有依据的分析；身份或必要输入不合法时沿用原拒绝规则。研究状态由 Agent 根据实际资料表达，不新增确定性投资评分。
- 综合研究结论明确当前最有依据的判断、最重要的未决问题及它可能改变的结论，复用现有摘要、主张、假设和缺口字段，供下游继续推理。
- 收尾按既定研究质量要求和本轮具体缺陷闭环；一般深度增强记录到 TODO，不持续追加验收目标。准确性、依据、既有安全契约和交接有效性要求继续适用。

- 用户入口仍是 `portfolio-council` Skill，承接已确认持仓与自然语言研究意图；宿主 launcher 只是当前真实运行和测试的执行承载，不要求用户手工转换持仓、准备 Gate 或理解内部命令。
- 普通使用只执行必要的结构、绑定与引用检查并输出报告，不隐式调用语义评分模型；聚焦 Eval 仅由显式验收或用户请求触发，未运行显示未评估。本次验收包含 Eval，不把它变为每次产品研究的前置条件。
- 本阶段定位为“普通股公司研究”，不等同于完整持仓分析。公司基本面、财务质量、估值与公司事件仍由一个 Company Analyst 使用四项 Skills 完成；图形、市场/宏观、板块、期权、资金与持仓结构、新闻情绪及 ETF 专业研究仅列出后续职责，不创建对应 Agent 或实现这些能力。
- 同时表达“本阶段未研究的方向”和“公司研究范围内资料不足”，不能把未开展研究解释为没有风险，也不能把未来专业能力齐备设为公司研究的前置条件。
- 强化报告的实际可用性：核心假设显式关联主张，反证说明挑战对象与影响机制，观察条件提供已有基线、期间与重评方式；未知阈值不编造，经营现金流增长不替代资本开支与自由现金流分析。资料缺口区分未获取、尚未披露、来源不支持及原因未知，分类须有依据。
- 修复中文与 JSON 同源输出、可解析引用以及实际 Eval 与覆盖状态的关联；保留历史原始产物，不通过改写历史报告掩盖差异。
- JSON 或其引用非法时不得进入下游；仅 Markdown 与合法 JSON 不一致时，报告对的一致性验收失败，错误 Markdown 不得有效展示或消费，但不得自动判定 JSON 研究失效或重跑 LLM。纯渲染修正从原 JSON 生成新产物，保留原件。
- 在现有宿主研究入口提供显式模型选择，当前选用 `gpt-5.6-terra`；未指定时沿用既有默认路由，评分模型独立配置并记录实际生效值，不新增自动路由或静默回退。
- 直接承接上一层识别并确认的持仓资料，用户提出“分析普通股持仓”即可进入研究；研究请求由系统生成，用户无需再次录入持仓、准备证据文件或填写技术字段。公司资料通过现有数据适配器和有效缓存准备，账户事实与公司资料保持来源区分。
- 普通股研究请求明确采用研究阶段语义，比较基准和组合授权约束可为空，未知持有期限如实记录；完整组合决策仍检查其必要输入，不以假值补齐。
- 报告开头增加有证据支持的综合研究结论，说明核心经济逻辑、支持依据与最可能推翻它的因素；估值的隐含预期必须说明假设。
- 核实公司与当前持有证券的对应关系；逐项展示已完成报告和中文进度，区分执行状态、研究质量与覆盖状态，限定超时、取消和重试行为。
- 普通股研究不依赖完整组合估值、其他资产价格或保证金；资料准备按证券隔离失败，有界准备结束后，对资料合格的证券继续并行研究。
- 置信度仅表示资料对研究判断的支持程度，不表示上涨或盈利概率；同一研究报告保留摘要与正文依据的稳定引用，供 CIO 追溯假设、反证、计算和失效条件，无需新增交接文件。
- 将现有 `runtime_company_analyst` 明确作为普通股持仓研究 Agent；复用同一 Agent 定义为每只普通股建立独立调用，不按股票创建 Agent，也不增加 `Holding Analyst` 等重叠角色。
- 建立普通股持仓研究的完整 Capability Contract：`PortfolioHandoff v3` 与 `CouncilRequest` 派生的单证券研究请求 → 冻结且通过 PIT Gate 的行情、SEC 披露及确定性财务计算 → `evidence-grounding`、`company-research`、`valuation` 和公司级 `catalyst-analysis` → 结构化 `EquityResearchReport` → 聚焦研究质量 Eval。
- 将 Company Analyst 输出归并为六组：公司与核心问题；业务、竞争和财务；Thesis 与估值；催化剂和反证；失效条件与观察指标；数据缺口和置信度理由。同时生成同源中文研究报告，技术 hash 和执行元数据由程序记录。
- 补充核心问题选择、事实→假设→业务影响→推翻条件的 Thesis 因果链、盈利质量与生存能力、公司适用指标、价格隐含预期及首次研究基线；可选用户持有逻辑缺失不阻断研究，不要求新增数据源。
- 多持仓通过现有 Codex Subagent 有界并行研究，默认目标并发数为 3，受实际环境能力和预算约束；空位即时补充下一项，保留全部持仓、独立上下文和逐项结果，不能把串行执行称为并行。
- 保持 Company Analyst 不输出 `BUY/ADD/HOLD/TRIM/EXIT`、目标仓位或组合决策；完整成本、盈亏、现金和跨持仓配置由 CIO 使用，Risk Engine 继续只负责确定性硬约束。
- Independent Skeptic 继续在隔离上下文中独立研究同一 Gate 合格 Evidence，不读取 Analyst 结论；本 Change 不新增 Skeptic 类型或第二轮辩论流程。
- 对含 ETF、期权的完整 Handoff 保留全部持仓和完整 Portfolio hash，但本 Change 只执行普通股研究，并在产物中逐项标记覆盖状态与 ETF/期权能力缺口；不得声称完成全组合研究或将不支持资产交给 Company Analyst。
- 保留既有 AAPL/MSFT 两股并行样本及其实际适用证据；本次调整补一次从用户已确认 Handoff 出发的真实输入链路验证，不再手工提供 Gate，不替换失败证券或遗漏任何持仓。该次同时验证受影响的启动、模型选择、报告改进与聚焦质量评价；未受影响项复用旧证据。两份有效研究及至少一种有计算依据的估值视角仍是研究能力标准，资料不足只证明缺口处理正确。不重复追加单股 Smoke，不重跑完整 Regression、Replay、Calibration、Ablation 或 Promotion Gate。
- 不新增行情 Provider、股票池、机会搜索、ETF/期权研究、Market/Macro/Sector Agent、券商连接或真实交易能力；不修改暂停中的 `us-equity-live-advisory-slice` 历史证据和未完成状态。

## Capabilities

### New Capabilities

- `common-stock-holding-analysis`: 定义从已确认持仓派生普通股研究请求，由现有 Company Analyst 并行使用专业 Skills 和冻结 Evidence 形成供 CIO 消费的 `EquityResearchReport` 与中文报告，并透明报告多资产覆盖缺口；第一轮 Skeptic 不接收 Analyst 报告。

### Modified Capabilities

- `specialist-research`: 将 Company Analyst 的专业输出和实际 Skill 参与要求扩充为普通股专属研究结构，并接入公司级催化剂分析，同时保持不作组合动作的边界。
- `portfolio-council-orchestration`: 允许 Council 在保留完整混合资产 Portfolio 和能力缺口的前提下执行受支持的普通股研究阶段，但不得把部分研究标记为完整组合研究或发布完整组合决策。

本次调整保留两股样本的既有证明范围，额外仅补一次已确认真实持仓的受影响纵向切片，输入数量不设上限，研究并发仍受现有预算限制。优先用中文描述方法、状态、进度和结果，代码标识符及协议字段保留英文。

## Impact

### 本轮收尾：研究深度分层与 TODO

用户已授权先更新需求再继续实现。本次以“合格公司基本面研究员”为完成目标，而非完整投研部门或顶级机构深度研报。当前 Company Analyst 必须解释关键公司判断，不把基本面解释推迟给 Skeptic/CIO；后续专业能力增加不同视角。

- 修正实际财务期间的使用，禁止因 `FY`/`10-K` 标签把不足一年的期间写成全年；补齐假设正文、主张类型和来源期间的中文展示。
- 用既有 Skill 强化经营驱动、盈利现金差异、现实反证与假想风险的区分、缺口对判断的影响；不要求无资料支持的计算、精确目标价或统一模板。
- 产品说明维护三类 TODO：本次补齐、公开资料后续深化、额外资料依赖；注明归属、依赖和价值，后两类不作为本 Change 门槛。
- 历史重组样本的期间口径、旧覆盖状态与中文差异按原件记录，不补写旧结果、不继承不适用的质量 PASS。本轮先完成聚焦检查与差异复核；新推理质量缺证明时仅报告具体缺口，不自动追加模型批次。

- 主要影响 `product/.codex/agents/runtime_company_analyst.toml`、现有公司研究相关 Skills、普通股研究请求与报告 Schema、Handoff/Council 规划到 Specialist 的派发接缝、专业报告验证和聚焦 Eval。
- 复用现有 Portfolio Intake、只读 live/fixture Evidence、PIT Gate、MCP 查询、确定性计算、Independent Skeptic 与 CIO 消费边界；不另建 Python LLM 编排后端。
- 可能新增或版本升级 `EquityResearchReport`、普通股研究批次/覆盖状态等契约；历史 `AgentResearchReport` 与已有运行产物保持可验证，不回写历史版本锁。
- 真实用户持仓、截图、账户信息和运行产物继续保存在仓库外，仓库仅保留合成样例和脱敏验收记录。
