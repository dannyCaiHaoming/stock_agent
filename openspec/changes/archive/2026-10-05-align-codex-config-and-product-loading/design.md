## Context

动机与范围见 [proposal.md](proposal.md)。2026-10-04 只读检查确认：

- `product/.mcp.json` 默认启用两个研究服务，fixture shell 要求两个解释器环境绑定，而插件声明未提供；桌面当前会话有 fixture 握手失败记录。缺少服务器 stderr，尚不能证明唯一根因。
- `product/runtime/nested_codex.py` 已按 run 构造 transport、环境及工具白名单，但 fixture override 没有显式 `enabled=true`；部分新阶段使用 `--ignore-user-config`。不能假定所有层级合并后都会自动启用。
- 仓库 Council Skill 为 3.8.0，分发和安装版为 3.4.0；交易记录发布代码明确保留其他基线文件。这是有意的局部发布结果，不是整包更新失败证明。之前的 16 项差异只覆盖选定 Skills/Agent/核心文件，不是完整 runtime 依赖清单。
- `product/trading_journal/packaging.py` 的 overlay 白名单仅允许两个交易 Skills 和 `trading_journal`，实际私人写入保护绑定安装来源、缓存 hash、恢复基线及合成哨兵。直接改缓存会使凭据失效。
- 当前默认 Python 缺 `jsonschema`；项目已声明基础依赖并忽略 `.venv/`。桌面内置与终端 CLI 版本不同，暂未证明版本差异造成故障。
- 工作树有其他 Change 的未提交修改；历史配置优化 Change 已归档且最终范围很小。本 Change 独立规划，不扩写旧归档或改排其他任务。

## Goals / Non-Goals

**Goals:** 让普通会话发现 Skills 而不启动无运行身份的研究服务；让受权宿主运行保留原有阶段工具；使指令、解释器和批准安装内容可核对。完成状态区分文件发现、配置检查、真实加载。

**Non-Goals:** 不建立统一插件管理平台或第二套研究后端，不拓宽交易记录打包白名单，不用配置修复替代投研内容验收。其他排除项沿用 Proposal。

## Decisions

### 1. 研究 MCP 默认禁用，宿主显式启用

在 `product/.mcp.json` 中保留 transport 声明并将两个研究服务设为默认禁用；沿用现有宿主 override，对合法所需的 `fixture_runtime` 明确设置 `enabled=true`。核对完整 fixture 与各研究阶段的命令生成路径，保留阶段白名单、身份绑定、Hook、原生沙箱与 run-scoped 状态。`live_runtime` 继续在现行研究启动路径中禁用；不恢复已退役的 live 完整 Council。

拒绝方案 B 的全局常驻研究服务，因为用户已选择 A。也不以用户全局硬编码机器解释器补救项目插件。若宿主对插件默认禁用的合并语义与预期不同，只能在相同“普通会话不启动、合法宿主明确启用”契约下调整声明方式，并提供实际有效配置证据。

依赖失败检查放在已有准备/启动边界，不引入常驻健康探针。当前脚本的缺绑定拒绝保留，补充零模型可测的环境缺口报告；不能以模型调用检测安装是否完整。

### 2. 指令按产品入口和阶段限定

| 文件 | 拟变更 |
|---|---|
| `AGENTS.md` | 根规则引用产品入口各自的授权条件，明确仅 Council 的相应阶段赋予 CIO 职责 |
| `product/AGENTS.md` | 独立入口、持仓/单股研究、显式综合与完整 fixture 分开；通用 Evidence/只读要求继续共用 |
| `product/.codex/agents/runtime_cio.toml` | 明确完整 fixture 兼容角色，不用旧 live 默认表述覆盖主线程研究综合 |
| `product/.codex/config.toml` | 按实际角色用途核对描述，修正仅写 Fixture 而被多阶段使用的描述；不新增角色 |
| `product/.codex-plugin/plugin.json` | 展示文案与已批准入口匹配，不将所有产品输出承诺为动作或 Risk 结果 |
| `docs/development/environment.md`、`README.md` | 长期规则采用条件式授权与验证说明，历史状态留在既有证据中 |

只消除与已有契约的冲突，不改变研究语义、动作枚举、阶段晋级条件和 Risk 实现。不靠新增提示字符串测试证明研究质量。

### 3. 项目环境使用已有依赖声明

使用符合 `requires-python` 的现有解释器创建 `.venv`，在此环境安装 `-e .`；操作文档明确先选择该环境，再运行确定性检查或宿主脚本。宿主现有 `python3` 调用通过显式选定环境的 PATH 解析，MCP 继续由 `sys.executable` 和依赖目录绑定，不向版本化源码写入用户绝对路径。只有证明存在绕过该选择的调用点时才作最小修复，不先引入新环境管理器。

保持可选 `live`/券商依赖按任务安装，不改变系统 Python、不自动升级 CLI。记录实际解释器、基础依赖和所用 Codex 路径/版本；真实任务仍检查对应可选依赖。Python 兼容性以本次聚焦检查为准，不仅以版本号判定。

### 4. 洁净研究基线与交易记录安装流程衔接

先制作逐文件清单：现有安装版本、候选来源 commit/批准差异、必要 runtime/schema/Skill/配置依赖、排除项及来源证据。对未完成 Change 的内容不因版本更高而自动发布。形成闭包困难时保留旧安装并列明具体缺口，其他文档和环境工作仍可完成。

将经审阅的研究基线物化到仓库外临时本地目录，排除私人目录、开发状态与无关变更。必要时只添加一个开发侧准备入口，复用现有哈希/路径校验，不把准备职责加入 Runtime。将此基线及已批准交易 overlay 交给既有 `prepare_clean_source` 流程；保持其固定 overlay 范围及恢复语义。新的隔离凭据来自既有验证流程，不手工改旧凭据，也不扩宽 `OVERLAY_ROOTS` 来混入研究改动。

发布前保留现用完整插件与其注册/恢复依据；重新生成受影响当前资源哈希与版本镜像，准确区分内容版本、安装包标识与历史候选身份，不为通过校验回写历史锁或推进生产指针。安装标识须覆盖本次基线及 overlay 内容，验证新源码/缓存身份；既有交易打包标识只基于 overlay，若同名版本复用会覆盖不同基线，则在开发准备层使用不同基线版本前缀，使安装标识唯一，不修改交易研究逻辑。

安装切换后核对实际注册及缓存；用既有合成隔离验证恢复安装有效状态，不执行真实账本写入、行情采集或券商同步。仅安装注册通过不等于 Skills/MCP 的真实运行加载通过。

### 5. 用户级配置单独维护

只对实施时仍存在的已移除 `js_repl` 项作限定清理，保存可回退的最小差异，解析检查通过后再确认；全局文件与原始配置不进入项目。Guardian `thread_context` 当前不存在，不为消除历史提示修改其他功能。全局 Git 放行规则按用户决定保持不变，其他 MCP/插件、开发模型及权限配置不纳入清理。

### 6. 验证分层且预算独立

- 配置/文档：TOML/JSON、引用路径、版本镜像、阶段适用关系；运行现有 `test_product_config`、`test_development_environment` 中受影响检查。
- 命令/transport：扩展现有启动与 MCP 测试，覆盖默认禁用后合法宿主显式启用、缺绑定/缺依赖拒绝、阶段工具白名单、错误 run 身份拒绝。经 apply 明确包含的零 LLM 合成 stdio 测试不访问外网或真实产品资料，复用已有合成夹具。
- 安装：批准文件闭包、来源/缓存一致性、唯一安装标识、合成隔离和恢复；使用现有交易打包测试，不通过真实私人数据测试。
- 实际加载：新普通会话确认 Skills 可发现且两研究 MCP 不启动。产品启动/加载行为改变仍按主规格需要受影响真实 Smoke；先明确场景、调用上限、是否涉及外部数据和有效授权，再经宿主执行。用户选择 A 不是模型预算授权。没有真实证据则保留相关任务未完成，不将配置测试或零模型 transport 当作真实 Smoke。

本次实现的真实模型调用数为 0；既有研究质量/Eval/晋升验收不由本 Change 替代。

### 7. 新运行及评分默认 Luna，历史锁保持原样

用户已选择模型方案 B。当前 `runtime_repeated`、新产品 manifest 的模型与 `dev_eval`、聚焦 Eval 和 Calibration 默认统一为 `gpt-6-luna`，普通股、多维与反证已有 Luna 默认沿用。模型路由政策升级为 1.1.0，当前候选以新身份记录，不修改旧候选/运行包或生产晋升指针。主开发会话仍尊重用户手动选择；Sol 开发与 Astra 显式争议路由的条件保留。显式受支持模型请求如实记录，不静默回退；保留已冻结 Terra 包的显式历史消费能力。

新评分准备由确定性层冻结 `grader_model`，Runtime Eval 输入升级为 1.1.0、聚焦 Eval 作业升级为 1.2.0；新版本缺锁拒绝，不能通过删字段回退旧模型。草稿装配、实际父/子模型、执行证明、局部修订和最终结果必须与该值一致，模型不抄录身份字段。历史未含此字段的 Runtime Eval 仍按原 Terra 契约读取，聚焦 Eval 历史结果按其已记录模型读取；历史证明仍需原冻结资源，不放宽 hash/身份门禁以适配当前源码。已有 Regression 的新准备与消费从当前候选读取模型，Promotion 仅接受与候选声明及 hash 一致的已知政策版本；只修改模型消费者，不触发真实 Regression 或 Promotion。Calibration 的新评分契约使用新 grader 版本，原版本只读兼容，不改写历史人工标签或产物。

验证覆盖新默认、CLI/Hook/真实事件装配接缝、错误模型在发布或调用前拒绝、历史原字节与模型身份保留。重新准备唯一标识的洁净插件并核对注册/缓存；开发 `dev_eval` 留在开发配置，不混入产品角色注册。真实 Luna Smoke/评分仍需另行有界预算，零 LLM 测试不证明账户可用或评分质量。

### 8. 已授权 Regression 交接补修

用户已确认纳入阶段 B 扩展检查暴露的旧 `validated_reports` 消费缺陷。开发 Regression 合成器复用现有 fixture MCP 报告读取入口及引用映射，提交 native CIO 语义草稿；报告身份、hash、Skill 由现行 finalizer 装配，未知引用、报告漂移和读取身份错误仍拒绝。固定 HOLD 仅验证既有动作契约和 Risk lineage，不形成证券研究结论。

相连的零 LLM 评分旧身份也同步修复：仅显式声明且绑定 authenticity=false、regression_deterministic_injection、valid-action-contract 审计记录的作业，允许使用既有 deterministic-not-applicable / model=none 结果生产与重验。普通及真实运行保持原评分、模型锁和执行证明门禁；不把合成夹具重标为 Luna，不修改历史包。实现准备、最终校验和只读重验使用相同判断，非法模式或声明不匹配拒绝。这里只运行单元测试中的确定性装配及消费者检查，不启动真实 Eval、Regression、Promotion。

### 9. 已授权 Promotion 拒绝记录修复

2026-10-05 用户已确认继续修复阶段 C 的四个 Promotion 反例异常。现有消费者在评分证明重验收到 ValueError/OSError 时未捕获，导致悬空 Evidence、缺 Trace、未来 Evidence/PIT 与 Risk lineage 破坏无法落盘失败报告。将证明 hash、重验和 Eval 身份匹配统一置于现有错误收集边界，错误写入 runtime_eval 的 verification_errors；原校验仍执行，任何拒绝使原硬门禁失败，不补造证明、不修改产物或评分、不放宽模型和风险条件。继续保留无法解析输入等现有前置错误行为。

仅改开发 Promotion 工具和针对性单元测试，不更新安装插件、模型默认或生产指针。复用阶段 C 已通过的未受影响检查；补跑四个失败反例和正常有效证据图，确认 FAIL 文件、报告和拒绝原因落盘，同时正常 PASS 不变。真实模型调用、真实晋升仍为 0/未执行。

## Risks / Trade-offs

- 默认禁用可能被配置继承保留 → 宿主显式启用并测试实际加载链，不只检查字符串。
- 新投研文案引用安装版不存在的 runtime 能力 → 发布清单按依赖闭包审阅，未经批准不打包。
- 更新破坏交易记录安装凭据或复用缓存标识 → 使用既有重新验证流程、唯一基线版本及可恢复副本。
- 当前 Python 与可选依赖不兼容 → 先完成基础环境及零模型检查；需要换解释器时报告实际兼容失败，不全局升级。
- 无真实 Smoke 授权 → 源码/静态检查可继续，加载验收明确待完成，不能归档为全通过。

## Migration Plan

1. apply 后记录当前受影响文件及本机配置差异边界，先修指令/默认 MCP/宿主显式启用，准备基础环境并做聚焦确定性检查。
2. 审阅研究分发清单与依赖闭包，结合已批准交易内容生成新洁净包；保留现用插件、注册依据与恢复凭据。
3. 校验通过后按获授权范围进行安装切换和合成隔离复验；普通会话观察与产品真实 Smoke 分别记证据。
4. 切换失败恢复旧注册和完整旧包，并通过既有安装验证恢复其有效凭据；不覆盖真实私人文件，不把旧默认常驻行为称为新方案已验收。
5. 符合范围的用户级配置维护单独落地；最终验收、人工完成批准、归档和限定提交沿用现有流程。

### 10. 后续 CLI 锁与实际执行绑定

用户明确选择更新后续候选为 codex-cli/0.160.0，不升级或替换系统 CLI。新增候选身份，当前源码和洁净安装基线同步；旧候选、已完成 Smoke 和历史锁保留原字节。所有当前宿主模型启动沿用共享命令构造：实际解析所选二进制并仅执行 --version，记录路径、文件 hash、退出状态、实际版本及锁来源；不匹配、未知版本或缺二进制在 exec 前拒绝，不回退其他 CLI。完整 fixture 从冻结 run 锁核验；尚无运行 CLI 字段的阶段从选定产品 manifest 取得明确批准值，并记录来源，不伪称该阶段已有冻结 CLI 锁。

新的 ephemeral 完整 Council 证明必须消费宿主测量记录并绑定 hash，不能再从 run 声明推断父/子 CLI。子 Agent 使用同一 Codex 进程的嵌入运行时，该来源明确标记为宿主进程版本测量；不声称 Hook 自带 cli_version。历史已保存证明只读，新的证明构造缺测量即拒绝。

新普通会话采用桌面内置 0.160.0 的 app-server thread/start（ephemeral）和真实 skills/list、mcpServerStatus/list，未调用 turn/start；普通项目配置和安装插件原样加载，SQLite/logs 只放外置临时目录。不读取其他会话或私人数据库。该证据证明新普通引擎会话加载，桌面 GUI 操作因工具限制保留 UNVERIFIED，不将它视为 GUI 观察。

验证只包含实际 --version 正反例、无 exec 启动、命令共享入口、测量证明拒绝与版本镜像/安装核对。原 Luna Smoke 不重跑，仍是旧候选运行；新增候选的真实 Smoke 和 Promotion 不宣称通过。
