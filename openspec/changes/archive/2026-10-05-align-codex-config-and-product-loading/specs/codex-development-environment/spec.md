## ADDED Requirements

### Requirement: 产品研究 MCP 必须按授权运行启用
产品插件 SHALL 保留 Skills 的可发现性，在普通开发会话中不自动启动 `fixture_runtime` 或 `live_runtime`。研究任务 MUST 经现有宿主入口显式绑定所选产品根、解释器、运行身份和阶段工具范围后启用所需研究 MCP；插件默认禁用不得阻止合法宿主运行。缺少绑定或依赖时 MUST 在模型调用前报告具体缺口，不回退到全局研究服务或其他解释器。该要求不禁止已授权的零 LLM 合成 transport 测试，也不限制无关平台工具。

#### Scenario: 普通会话发现产品插件
- **WHEN** 用户打开普通开发会话且未启动具体产品研究
- **THEN** 产品 Skills 可发现，两个产品研究 MCP 均不自动启动；其他全局插件及 MCP 的配置不因本项迁移改变

#### Scenario: 宿主覆盖插件默认禁用
- **WHEN** 已授权的研究任务通过宿主启动，输入及运行绑定有效
- **THEN** 仅所需研究 MCP 被显式启用，实际 transport 使用绑定的解释器和产品根，工具发现与阶段白名单一致，不继承普通会话的无任务研究权限

#### Scenario: 运行绑定或依赖不完整
- **WHEN** 所需解释器、依赖或运行绑定缺失
- **THEN** 启动在模型调用前失败并区分环境错误与研究证据不足，不自动安装、不改变沙箱、不调用模型试错

### Requirement: 开发与宿主解释器必须能够明确复现
开发安装说明 SHALL 提供项目隔离环境及已有基础依赖的可重复安装和使用方式，确定性检查与宿主入口 MUST 能明确选用同一项目环境。运行记录 SHALL 区分 Python 路径/版本、Codex CLI 路径/版本和实际依赖状态；桌面与终端 CLI 版本不同不自动触发升级或改写历史锁。可选数据依赖 MUST 只在对应授权任务需要时安装。

#### Scenario: 基础环境准备完成
- **WHEN** 开发者按说明准备并选择项目环境
- **THEN** 已声明基础依赖可导入，版本镜像检查不再因缺少该依赖中断，宿主及其 MCP 可追溯至所选解释器

#### Scenario: 使用缺依赖的其他解释器
- **WHEN** 检查或启动误用了未安装基础依赖的解释器
- **THEN** 报告实际解释器与缺依赖事实，不把未完成校验标成产品断言失败或通过

### Requirement: 产品插件更新必须关联批准来源与实际安装
产品插件更新 SHALL 依据明确的已审阅来源、依赖闭包和版本清单制作洁净分发物，保留可恢复旧基线。版本较新或仓库文件存在 MUST NOT 自动视为已批准发布。更新 MUST 保留既有交易记录/复盘功能及私人数据隔离，并重新验证实际注册、缓存内容与相应安装隔离凭据；未经验证不得宣称安装完成或恢复私人写入能力。发布副本 MUST 排除凭据、私人状态及无关 dirty 内容，不修改历史运行和生产晋升指针。

#### Scenario: 仓库含并行修改
- **WHEN** 投研文件与安装版不同且工作树包含其他未完成 Change
- **THEN** 仅纳入来源明确且依赖完整的批准变更，记录保留旧版的理由；无法证明闭包或隔离时停止安装切换，保留原可用插件

#### Scenario: 分发物与安装缓存不同
- **WHEN** 洁净分发物已准备但实际注册或缓存尚未匹配
- **THEN** 只报告准备完成，不报告加载成功；安装隔离凭据不得沿用旧内容 hash 伪造新版本验证

#### Scenario: 研究基线与交易记录功能一起更新
- **WHEN** 新研究基线通过发布检查并进入既有交易记录安装流程
- **THEN** 交易记录与复盘的批准内容被保留，其他基线文件按本次清单核对；合成隔离验证通过且旧基线可恢复，不读取或改写真实私人账本

### Requirement: 开发 Regression 必须消费当前报告交付契约
开发零 LLM Regression MUST 使用当前冻结报告目录、实际读取记录及引用映射提交 native CIO 草稿，由既有 Runtime 装配技术身份并校验完整报告消费、Evidence 与 Risk lineage。MUST NOT 恢复旧嵌入字段或补造报告读取证明。仅显式绑定零模型契约夹具的评分作业 SHALL 使用确定性 NOT_APPLICABLE，agent 为 deterministic-not-applicable、model 为 none；普通与真实评分 MUST 保留模型锁与执行证明门禁。历史产物保持原字节。

#### Scenario: 合法动作契约夹具贯通消费者
- **WHEN** 已授权零 LLM valid-action-contract 夹具通过当前报告读取、native CIO 装配和 Risk 校验
- **THEN** 可准备、完成及重验契约检查，五维语义评分均为 NOT_APPLICABLE，不表示研究质量、模型执行或晋升通过

#### Scenario: 报告引用或交付身份不合法
- **WHEN** 报告内容漂移、未知引用、遗漏读取或调用身份错误
- **THEN** 原有消费者拒绝，不能用目录元数据代替实际读取记录

#### Scenario: 普通运行冒充零模型评分
- **WHEN** authenticity、触发来源、审计夹具声明不满足契约检查条件，或不适用作业提交模型评分结果
- **THEN** 拒绝跳过语义评分，普通作业未提供模型评分仍失败，真实作业执行证明仍必须验证

### Requirement: Promotion 评分证明拒绝必须形成可审计失败
Promotion 工具 SHALL 保留现有评分证明 hash、实际执行、模型及 Eval 身份重验；重验产生的 ValueError/OSError 拒绝 MUST 收集到现有 runtime_eval 校验错误，使硬门禁和总结果为 FAIL，并保存错误原因与失败产物。MUST NOT 将异常转成通过、补造证明或改写输入。正常有效证明 SHALL 沿原通过路径处理。

#### Scenario: 不完整或漂移的证据包
- **WHEN** 已读取的证据包因悬空 Evidence、缺 Trace、未来 Evidence/PIT 或 Risk lineage 破坏使评分证明重验拒绝
- **THEN** 原拒绝原因进入失败报告，总结果与相关硬门禁为 FAIL，FAIL 标记和结果文件被保存，不产生 PASS 标记

#### Scenario: 正常评分证明
- **WHEN** 证据图及评分证明有效且原全部晋升条件成立
- **THEN** 保留原门禁判定和通过产物，异常处理不影响正常证明消费

### Requirement: 宿主 CLI 必须在模型前核验实际版本
当前宿主模型启动 SHALL 对所选 Codex 二进制仅执行 --version，保存真实路径、文件 hash、实际版本、退出状态和批准锁来源。实际版本 MUST 与运行锁或所选产品 manifest 的批准值一致；缺失、不支持或不匹配 MUST 在 exec 前拒绝，不自动升级或回退。新 ephemeral 完整 Council 执行证明 MUST 绑定真实测量记录，不以声明代替观测。历史运行、锁和证明 MUST 保留原字节。

#### Scenario: PATH 解析到其他版本
- **WHEN** 后续候选要求 0.160.0，但所选 CLI 为 0.159.3 或版本未知
- **THEN** 保存拒绝原因且不启动模型，不替换系统 CLI 或改写候选锁

#### Scenario: 合法 CLI 与 ephemeral 证明
- **WHEN** 所选二进制测量为冻结批准版本且原真实运行证据有效
- **THEN** 按原宿主入口执行；新证明引用测量及 hash，缺失或漂移测量拒绝

## MODIFIED Requirements

### Requirement: 版本与模型配置必须以可验证能力为准
系统 SHALL 在使用新的参数和配置键之前记录本机 CLI 版本、帮助或配置解析依据；已验证且未改变的能力依据可以复用，不将重复兼容性检查作为普通开发前置。开发 SHALL 保留 Sol 常规开发、Astra 复杂分析的分工；产品 Agent 开发期真实测试默认固定为 `gpt-6-luna`，实际覆盖普通股、多维研究和独立反证宿主测试入口。用户明确指定主会话模型时尊重其选择，不要求产品 dispute_id、争议说明或批准凭证，不强制根开发默认模型与产品 development_default 一致。开发子 Agent SHALL 按职责和已有配置选模；Reviewer MUST 使用自身实际生效配置，不承诺自动跟随主会话，实际模型未知时如实标注。系统 MUST 尊重用户选择，不通过 Prompt 声称已切换模型，也不自行修改用户模型配置。

新产品运行（完整 fixture、研究阶段和重复 Runtime）及新 Runtime Eval、聚焦 Eval、Calibration、`dev_eval` 的默认模型 SHALL 统一为 `gpt-6-luna`。新评分准备 MUST 冻结评分模型，可信装配、实际执行事件、局部修订和完成校验 MUST 使用同一模型；不匹配必须拒绝，不把 Terra 结果重标为 Luna。当前路由与新候选 SHALL 使用新政策/身份记录此选择；历史运行、旧候选、密封 Replay、人工标签及旧评分结果 MUST 保留原模型与字节，历史读取不能视为新执行授权。新默认不得覆盖生产晋升指针。显式指定其他受支持模型时 SHALL 记录真实请求和实际选择，若无法支持/不可用则失败，不静默回退。实际执行模型 MUST 由配置及运行事件验证；仅文档/配置检查不得宣称账户模型可用或已运行。

#### Scenario: 参数或模型不可确认
- **WHEN** 所需配置不被当前 CLI 支持，或所选模型无法确认可用
- **THEN** 系统报告不支持或待确认，不静默替换模型，不启动付费试错循环；帮助中存在 model 参数不等于某模型已获账户授权

#### Scenario: Hook 信任受限
- **WHEN** 当前 launcher 依赖 Hook 信任豁免但本机政策不允许或来源未核验
- **THEN** 系统报告所需的精确信任范围并停止，不自动增大信任范围或关闭权限控制

#### Scenario: 用户手动选择开发模型
- **WHEN** 用户为开发会话选择可用模型，包括 Astra、Sol 或其他模型
- **THEN** 开发规则和 Reviewer 不要求额外架构争议证明才能继续授权任务；保留平台实际可用性限制，不修改产品 Runtime/Eval 路由或其版本锁

#### Scenario: 产品仍使用原路由
- **WHEN** 后续按另行有效授权准备新的产品运行或评分
- **THEN** 默认请求并冻结 `gpt-6-luna`；真实事件不一致或模型不可用即失败，不静默回退 Terra，显式争议路由保留原授权条件

#### Scenario: 开发测试入口未显式选模
- **WHEN** 宿主普通股、多维研究或独立反证开发测试未提供 `--model`
- **THEN** 冻结运行准备请求 `gpt-6-luna`，真实运行记录实际模型；若不可用则停止，不改用 Terra

#### Scenario: 历史 Terra 评分只读
- **WHEN** 读取旧评分或密封 Replay 的 Terra 模型身份
- **THEN** 保留原结果、模型和 hash，按原冻结资源核验，不改写为 Luna，不因历史可读而允许新的隐式 Terra 评分

#### Scenario: 新评分实际模型偏离冻结值
- **WHEN** 新评分收到其他模型的事件、草稿身份或结果
- **THEN** 调用或发布前明确拒绝，不补造身份、不修改研究语义、不产生合格评分结果
