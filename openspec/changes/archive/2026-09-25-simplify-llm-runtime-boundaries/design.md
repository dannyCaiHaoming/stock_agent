## Context

见 [proposal.md](proposal.md)。当前 `build_predecision_cio_prompt` 把 `product/AGENTS.md`、Portfolio Council Skill、`runtime_cio.toml` 全文和十份已验证报告放入同一输入；`_model_execution_proof` 重建整个 prompt，并核对三份源文件、prompt、模型命令和输出 Schema 的 hash。现有产品说明中同时包含研究级、旧 fixture、Eval 和完整建议规则，其中 `NO_TRADE`/Risk 规则不能直接作为本次非动作研究指令。MRVL 真实运行及独立内容复核已提供历史基线，但已有运行不能替代改动后的锁定版本验收。

## Goals / Non-Goals

**Goals:**

- 缩短交给研究级 CIO 的**有效指令段**，而不是裁剪冻结研究报告或放宽证据门禁；在相同来源包下可观察到无关阶段说明被排除、指令段及总 prompt 大小下降。
- 让运行清单和终态检查既能追溯产品源文件版本，也能核对实际交付的阶段有效指令；保留真实内容验收而非只比较字节数。

**Non-Goals:**

- 不重写十份报告、压缩 Evidence、迁移 Schema、替换模型或引入 Agent/编排器/通用 prompt 框架。
- 不借本任务退役 fixture Council、Eval、旧历史运行或修改 Research Memory、PIT Gate、Risk；不处理 Tiger/Luna 活跃 Change 的共享文件改动。

## Decisions

### 1. 在现有 CIO 装配入口生成显式阶段投影

从现有产品指令、Portfolio Council Skill 和 CIO Agent 协议中选取适用于 `PREDECISION_CIO_SYNTHESIS` 的段落，并加入当前动态请求规则。使用少量显式成对标记，不依赖普通标题文字、段落顺序或模糊关键词匹配；提取逻辑留在现有 CIO 装配路径。准备阶段检查标记完整、唯一、有序和内容非空，错误时给出具体源文件及原因，在启动模型前拒绝，不静默回退到全文或空规则。保留完整源文件 hash、最终投影内容 hash 与完整 prompt hash，终态以重建的**有效投影**比对实际输入。共享文档其他阶段的规则原文保持有效。

备选的“新建统一指令编译器/配置 DSL”增加维护面；“只写一句忽略旧规则但继续送全文”不降低输入且保留冲突；“直接删旧 fixture/Eval 文本”会破坏现有兼容入口，均不采用。

### 2. 安全与研究语义采用白名单保留，机械重复采用逐条证据审计

先列出源段落与本阶段必须保留的规则映射：只读与无交易、工具及报告内容不作为执行指令、禁止编造事实或修改产品文件、来源 cutoff、当前账户未知、Skeptic 取舍、双侧事实引用、MD&A 冲突、Macro/Market 证券特定传导、Evidence 查询闭包和输出结构。机械规则去重后保留一处完整简短说明，包含模型正确选择引用、查询身份、输出字段所需的信息；注明保留位置及已有 Schema/Gate/工具事件/finalizer 的拒绝路径。已有负例覆盖则复用，不为每句文案新增测试。校验器能拒绝非法结果只能证明安全拦截，不能证明模型可稳定完成；因此不删除必要操作指导，也不得通过新增 Python 主观评分来替代研究规则。

Company、Market、Skeptic 仅做一张定点只读审计表，记录重复位置、现有校验及后续建议。本 Change 不修改它们的派发说明、Agent 行为或运行实现；旧上游报告不被当作修改后 Specialist 的验收证据。

### 3. 比较固定输入与实际运行，但不把两者混为一谈

以已存在的冻结 MRVL 正反研究包记录旧版 prompt 字节数、有效指令段字节数，以及可读取的模型用量；新版本用相同来源包、同一显式可用模型及新 run 目录记录对应数据。报告全文不裁剪，避免用输入减少换取事实损失。总运行 token 可能受缓存、工具往返和输出长度影响，只作观察值；主要可控指标是有效指令段和总 prompt 的确定性缩短。无预设百分比门槛；如果没有可观察缩减或独立研究内容复核失败，本 Change 不算完成。

验收聚焦 `PREDECISION_CIO_SYNTHESIS` 的确定性测试、真实宿主 Smoke 与只读内容复核；不隐式触发 Runtime Eval、Regression、Ablation、回测或 Promotion。

真实运行记录所有本轮尝试的引用错误、工具错误、验证失败、重试及等待时间，不只保留最后一次成功。因指令消减造成的新错误须修复并重新验证；外部模型或环境错误单列，不据此无界重跑。单个 MRVL 样本用于发现本次退化，不宣称证明统计成功率。

### 4. 成套更新资源并先验证兼容性

`discover_product_resources` 会核对 `product/version-manifest.json` 的资源 hash，CIO 终态也会重验当前源码。因此指令、提取实现与必要版本绑定作为同一改动更新和回退；更新版本清单不代表候选晋升。修改前确认没有使用同一源码的受影响运行；如仍在运行，等待其自然结束，期间仅继续只读工作，不强行终止进程，也不引入热更新或新锁服务。

模型调用前完成四项确定性检查：共享资源发现成功、旧 fixture 指令与入口配置可加载、Company/多维/Skeptic 的既有停止点不变、原 MRVL 来源包仍能准备为新的 CIO 输入。后者使用零模型准备验证，不重写来源清单或放宽 hash 检查。历史报告继续可读取，但旧完整运行按原版本解释，不要求新代码认证旧锁。

## Risks / Trade-offs

- [摘取阶段段落时遗漏安全规则] → 源段落映射与正/负向测试同时维护；投影标记缺失即模型前失败；真实内容复核检查非动作与来源边界。
- [修改锁定 prompt 使历史运行无法按新代码重算] → 历史产物与 hash 原样保存，明确它们只证明旧版本；新版本使用新 run_id 和新验收，不改写旧清单。
- [纯机械去重误删语义约束] → 每条删除都要有确定性拒绝路径；多期间可比性、MD&A 和市场传导留给 LLM 与内容复核。
- [共享文件含 Tiger/Luna 未提交改动] → 逐文件、逐 hunk 审阅；不整仓暂存、不覆盖用户改动，必要时只调整 CIO 独占路径。

## Migration Plan

没有数据迁移。先保存基线与规则映射，确认受影响运行结束后再成套修改阶段投影、必要版本绑定和聚焦测试；资源发现及 MRVL 零模型准备通过后才进入真实 Smoke。通过新 MRVL 宿主运行和独立复核后申请 Change 收尾。失败时在无受影响运行使用的前提下成套撤回本次指令、实现与版本清单改动，保留用户无关修改和所有运行证据；不自动改写来源报告、旧运行清单或账户资料。
