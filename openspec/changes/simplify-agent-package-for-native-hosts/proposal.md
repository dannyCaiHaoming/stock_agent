## 原迁移规划（历史范围，不作为第9节执行清单）

## Why

用户需要的是可在 Codex、Claude Code、OpenCode 中使用的投研 Skills、Agents 和业务工具，而现有正常研究路径依赖自建 Codex CLI 启动、阶段串联、Hook 提交和事件状态重建。该控制层增加维护与测试负担，并把宿主执行协议混入研究契约；当前优先纠正架构边界，随后再调整其他需求。

## What Changes

- 建立一个共享自有 Skill/角色正文与确定性业务工具的原生 Agent Package；三个宿主各使用自己的会话、委派、权限和上下文能力，只保留必要的原生注册/安装配置，不建设统一 Agent Runtime、模型 API/SDK 后端、调度器或宿主事件转换平台。
- **BREAKING**：正常产品研究使用用户当前宿主会话，不再由 Python/Shell 创建额外宿主模型进程。Company、多维、独立 Skeptic 与显式 CIO 的研究阶段及停止点由现有 `portfolio-council` 的共享方法和宿主主线程承载，不能把业务 Stage 清单再次实现成 Python 派发循环。
- **BREAKING**：新原生研究的业务提交/消费不以 Codex `SubagentStart/Stop`、JSONL、`process-result.json` 或特定 CLI 版本为必要格式；服务端继续验证可信任务授权、输入/Gate/引用/计算/报告绑定。业务产物验证、实际宿主执行观察与研究内容裁定分别记录，不伪造模型或作者身份、不把访问凭据当调用方认证。
- 从混合模块中拆出必要的数据准备、计算、引用/Schema 校验、报告提交/归集、Memory 与历史读取，替换实际消费者后退役正常路径中的 CLI 启动和重控制代码；不能只重命名目录、只改指令或长期维护两套正常入口。
- 共享研究正文不携带某一宿主的私有工具参数；原生配置分别提供角色、Skills 发现、受限 MCP 和权限设置。原生工具加载、独立首轮上下文和服务端隔离必须实际验证，宿主能力或证据不足时明确阻断对应能力，不通过启动另一宿主或放宽权限兜底。
- 原生安装须同时交付主线程可加载的短宿主操作指引，避免把可选worktree隔离或调用级模型覆盖误当普通研究前置；指引由精确审阅源随包展开，不建设参数执行器，静态交付不替代实际原生验收。
- Claude Company调用端在指引已加载仍复发后，使用宿主自带`context: fork` Skill固定绑定现有Company角色；主线程仅交付本次问题与精确任务授权，不再生成Agent的隔离/模型参数。该入口仅是Claude原生配置，不新增角色、Hook、参数改写程序、派发/等待控制器或自动回退；共享方法、其他宿主及安全边界不变。
- Claude Company项目角色显式引用已有`company` MCP连接，避免仅依赖父会话隐式继承；精确工具白名单、共享正文、五Skill和模型继承保持不变。原生工具解析失败与业务授权失败分别记录，不用通用工具、通配白名单、新连接进程或插件字段假设绕过。
- 修复实际原生Company暴露的SEC结构化金额→既有计算接缝：只从已授权的已知SEC财务事实读取amount，并保留来源、单位、期间及原事实hash；同框架金额比率和USD数量级换算沿既有数学工具执行，任意对象、不同框架/单位或非金额不放行。旧默认计算行为和冻结记录不改，不重派已停止研究。
- 修复原生query的事实交付字节预算：对模型已明确选择的精确ID按完整事实返回有界页和下一偏移，保留64KiB上限并先校验整组授权；只把实际返回的事实记为已查询。小请求原响应保持，单事实超限仍拒绝，不截断或自动选择证据，不加入模型重试/宿主停止控制，不回签已停止窗口。
- 对本次实际统计截断和Skeptic误参作同边界修复：计算目录有界交付精确引用/真实值/单位及血缘摘要，精确引用可显式分页读取完整输入ID，服务端完整计算和提交装配不变；已有MCP精确回读对大型报告提供按字符偏移的无损JSON页，小报告及内部完整读取保持原样，不以摘要替代报告。Claude的Market/Skeptic复用Company已有原生fork Skill结构及本角色MCP连接引用，不再构造Agent隔离/模型参数。共享角色要求实际加载所需Skill、使用本角色工具名并遵守当前窗口首错停止，不增加停止控制器、来源或通用工具权限。修复及检查归入现有6.1–6.4，不把配置通过当实际验收。
- 测试随保留职责收敛：保留数据/数学/PIT/引用/授权/隐私/持久化及实际业务接缝检查，迁移混合测试，移除仅服务于已退役控制机制的测试；旧报告与失败证据按原版本只读，不要求保留旧执行器才能读取。
- 本 Change 是当前唯一优先需求。其他活跃 Change 的修改、任务和证据保持原样；完成本 Change 后再由用户安排其新架构调整，不自动合并、关闭或实施它们。配置与产品加载对齐已由用户声明完成，本 Change 不重开该验收。

## Capabilities

### New Capabilities

- `native-agent-package`：共享 Skills/角色/业务工具、三个宿主的薄原生配置、当前会话研究、能力诚实披露及控制层退役验收。

### Modified Capabilities

- `portfolio-council-orchestration`：以当前宿主主线程承载现有研究阶段，分离业务完成与宿主执行观察，保留独立反证、完整覆盖、显式 CIO 和非动作边界。
- `research-handoff-contracts`：脱离 Codex Stop Hook 的任务授权、精确回执、可信技术装配与历史只读；不放宽来源、引用、计算或语义门禁。
- `common-stock-holding-analysis`：原生有界委派与确定性报告归集/复用，不依赖自建 launcher 和父线程 Hook；保留完整持仓输入及现有研究方法。
- `multi-dimensional-holding-research`：原生主线程处理现有依赖/停止点，保留受限取证、计算和输入可读性，不新建状态接口或第二调度器。
- `single-stock-research`：使用当前宿主原生研究入口而非桌面/CLI嵌套隔离；单股身份、时点、专业范围和禁止账户动作不变。
- `codex-development-environment`：正常研究与显式历史执行维护分离；研究 MCP 按任务授权、原生模型选择及实际加载观察不绑定通用 Codex CLI 执行锁。
- `three-plane-governance`：开发/产品边界按宿主可执行权限隔离；正常研究不执行开发收尾，开发验证不隐式运行模型，其他需求延后且不改历史批准。

## Impact

受影响范围以 Design 的逐文件职责矩阵为准：`product/skills/`、自有角色正文及原生配置、`product/runtime/` 内混合的准备/提交/读取代码、`product/mcp/`、模型与版本声明、包分发边界、根/产品规则和相关测试。关键退役候选是 `nested_codex.py` 的模型启动、各研究 Stage 的 `launch_*`/父进程函数、`codex_hook_recorder.py` 的新运行控制及 `run-product-smoke.sh` 的正常研究串联；先替换其业务消费者，不能整目录删除。

不扩市场、资产、Provider 或账户权限，不新增列表刷新、历史建议、评分平台或后台运行。独立交易记录/复盘、只读券商隔离、现有数据/金融计算/硬 Risk、历史报告与私人账本保留。旧 Eval/Replay/Regression/Calibration/Ablation/Promotion 不自动迁移或执行；只读历史消费者与显式旧维护工具不能成为新原生研究的依赖。
