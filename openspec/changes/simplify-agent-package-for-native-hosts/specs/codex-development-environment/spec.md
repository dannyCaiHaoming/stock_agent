## MODIFIED Requirements

### Requirement: 执行入口必须复用统一启动契约
正常产品研究 SHALL 使用所选宿主当前会话的原生 Skill/Agent 能力，项目业务工具不负责模型启动、派发、等待或跨宿主事件转换。Smoke SHALL 按受影响宿主的原生交互验证实际加载与业务结果，预算和执行必须另获明确授权。历史 Execution Replay/Regression 等专项维护仍按其冻结契约与显式授权执行，不自动迁移或开放，不能作为普通研究依赖或回退。确定性验证、Artifact 读取和合法资料复用 MUST 保持零新模型，不要求历史包新增原生字段。

#### Scenario: 三类入口启动新运行
- **WHEN** 请求正常原生 Smoke 或另获批准的旧执行维护
- **THEN** 明确区分当前原生会话与对应冻结维护入口；不得将旧 launcher 恢复为日常研究必经路径或新建统一调度器

#### Scenario: 无需模型的操作
- **WHEN** 执行历史 Artifact 校验、确定性案例或有效引用复核
- **THEN** 不启动模型，不把旧包伪装为当前加载证明，不强迫新增 launcher 字段

### Requirement: 产品研究 MCP 必须按授权运行启用
产品包 SHALL 保留 Skills 发现，普通开发会话不自动启用研究权限。用户在当前宿主明确请求产品任务后，原生配置及已有确定性工具 SHALL 绑定产品来源、解释器、业务输入/Gate、角色与允许工具，服务端每次调用重验授权；不要求 Python 创建新的模型进程或使用全局无限制研究服务。缺绑定、依赖或实际工具隔离必须在事实返回/副作用前拒绝，拒绝与研究资料不足分开。原生配置不能自动扩大用户权限或改变无关 MCP。

#### Scenario: 普通会话发现产品插件
- **WHEN** 用户打开开发会话且没有具体产品任务授权
- **THEN** 可发现产品 Skills，但无任务研究能力默认不可用，其他用户插件及 MCP 不被改动

#### Scenario: 宿主覆盖插件默认禁用
- **WHEN** 当前宿主的产品会话已获任务及必要工具启用授权
- **THEN** 仅连接所需受限业务工具并使用正确产品根/解释器，真实工具发现与调用可核对，不启动另一宿主或解除全局限制

#### Scenario: 运行绑定或依赖不完整
- **WHEN** 工具缺解释器、输入/Gate 或角色范围
- **THEN** 报告环境/授权缺口并在取证或保存前拒绝，不安装依赖、切换模型或扩大权限试错

### Requirement: 宿主 CLI 必须在模型前核验实际版本
只有明确授权且确实要求冻结 CLI 的旧执行维护 SHALL 按原锁核验二进制、版本及身份，历史字段与证明不改写。正常原生研究 MUST 使用用户所选宿主的实际能力和配置，不由项目探测/启动另一 CLI，也不因缺 Codex 二进制或版本不等于旧锁而拒绝合法业务工具。宿主版本、模型和执行信息按实际可观察来源记录，缺失明确未验证；严格版本锁或晋升仍不能以未知值通过，不伪造测量或修改用户安装。

#### Scenario: PATH 解析到其他版本
- **WHEN** 当前原生宿主已具备必要能力，而 PATH 中 Codex CLI 与旧锁不同或不存在
- **THEN** 正常研究不启动该二进制，不以其差异阻断业务；另行请求旧维护时仍按原锁拒绝不匹配

#### Scenario: 合法 CLI 与 ephemeral 证明
- **WHEN** 显式维护旧 Codex 包且原测量、权限和冻结资源有效
- **THEN** 仅在其原批准范围执行，证明不冒充当前三宿主原生验收；缺证据不补造

### Requirement: 执行模式必须分离且不隐式启动
系统 MUST 分离当前环境确定性开发检查、当前宿主原生产品执行、独立证据复核及显式历史维护。正常原生 Smoke 不通过项目启动另一模型进程，不创建额外项目沙箱；原生审批/保护由用户选择的宿主执行，项目不得关闭或扩大。旧冻结维护只有单独有效授权才按原执行边界处理，旧 probe/preflight/review 启动保持退役。缺授权、依赖或最低隔离能力明确停止，不以外部沙箱声明、配置存在或历史PASS自动降级。

#### Scenario: 自检与旧入口
- **WHEN** 请求确定性自检或退役的review/probe入口
- **THEN** 自检仅执行声明检查；退役入口在任何模型/网络探测/状态写入前拒绝，不静默转为原生产品运行

#### Scenario: 独立 Reviewer
- **WHEN** 按需复核当前Change
- **THEN** 读取差异、规格和已有证据，缺证据仅提出具体补验需要，不自行启动模型或沙箱

#### Scenario: 绕过薄入口调用历史流程
- **WHEN** 经底层CLI或直接接口请求已退役探针/项目review启动
- **THEN** 同样明确拒绝，更换调用层级不能恢复旧行为

#### Scenario: 历史沙箱参数不能触发降级
- **WHEN** 旧接口收到externally_sandboxed或preflight声明
- **THEN** 不读取其内容作为权限授权，不关闭原生保护，不创建模型运行或回退分支

#### Scenario: 正常宿主命令保留原生权限
- **WHEN** 用户在当前宿主执行获授权产品请求
- **THEN** 保留该宿主实际审批/权限约束与产品工具范围，不由项目生成关闭审批、沙箱或Hook信任的命令；配置/事后hash仍不证明全进程OS只读

### Requirement: 资源发现与实际加载必须分别验证
系统 MUST 区分共享正文/角色/MCP的静态发现、安装配置与真实原生加载/调用。必要实际执行或隔离证据缺失不能只凭文件hash、报告存在、模型自报或工具保存成功认证完整验收。新原生观察使用宿主真实可得材料，不要求Codex Hook或另一CLI事件；未知单列且不补证。旧冻结包按原证明读取，合法前置终止的未调用角色按阶段不适用处理，不伪造加载。

#### Scenario: 配置存在但未执行
- **WHEN** 模板和文件可解析但没有必要原生委派、Skill或工具使用观察
- **THEN** 只报告静态检查和缺证项，完整执行验收保持未完成，不把preflight称为加载成功

#### Scenario: 完整正常 Smoke
- **WHEN** 获授权的原生场景完成实际研究与适用校验
- **THEN** 分列正文/角色来源、原生委派、受限MCP、报告业务验证和内容裁定，只有场景实际包含的CIO/Risk记录相应证据，不自动调用Eval或伪造Hook

### Requirement: 版本与模型配置必须以可验证能力为准
新增宿主配置和参数 SHALL 依据已安装版本的可验证能力，已验证且未变化依据可复用，不把CLI兼容反复检查作为开发前置。开发模型分工和用户手动选择保持原边界，主会话选择不要求产品争议凭证；Reviewer实际模型未知如实标注，不承诺随主会话变化。正常原生研究使用宿主与用户的实际选择，公共方法/工具不强制gpt模型或CLI身份，也不通过Prompt声称切换。独立新评分与仍获授权的旧维护继续按其原批准默认和模型锁运行；当前旧路由的Luna默认、历史Terra/Replay字节及晋升门禁不改写。显式模型不支持或不可确认时说明具体限制，不静默回退、不付费试错或修改用户模型。

#### Scenario: 参数或模型不可确认
- **WHEN** 当前宿主不支持所需角色/工具参数或无法确认显式模型要求
- **THEN** 报告限制与实际观测范围，不以参数文件存在证明能力，不切换模型试错；严格身份用途仍拒绝缺证

#### Scenario: Hook 信任受限
- **WHEN** 另获授权的旧维护需要原Hook而用户政策不允许
- **THEN** 明确最小信任需求并停止，不扩大信任；正常原生研究不通过旧Hook信任豁免恢复执行

#### Scenario: 用户手动选择开发模型
- **WHEN** 用户选择合法可用的开发主模型
- **THEN** 尊重选择，开发不要求产品争议说明，不改变旧Runtime/Eval锁

#### Scenario: 产品仍使用原路由
- **WHEN** 后续另获授权的旧维护或独立评分按现有Luna默认准备
- **THEN** 冻结请求并重验真实执行，不把旧结果改成Luna；当前原生产品会话不因此被强制换模

#### Scenario: 开发测试入口未显式选模
- **WHEN** 准备原生Smoke而用户尚未确认该宿主模型与预算
- **THEN** 只记录宿主声明和所缺授权，不自动运行；旧维护默认仍按其原路由和锁

#### Scenario: 历史 Terra 评分只读
- **WHEN** 读取旧评分或密封Replay的Terra身份
- **THEN** 原模型/hash/结果不变，历史可读不授权新的模型调用

#### Scenario: 新评分实际模型偏离冻结值
- **WHEN** 另获授权评分的实际执行与评分锁不同
- **THEN** 原评分门禁拒绝，不用原生模型自由选择规则豁免或改写身份

## ADDED Requirements

### Requirement: 正常原生模型选择必须属于宿主和用户
正常原生研究 SHALL 使用宿主实际生效的用户选择或该宿主的合法默认模型，不由公共研究正文或业务验证器强制统一成某个厂商模型。显式模型要求不能通过 Prompt 自报实现切换；不支持或无法确认时明确说明。实际模型及原生能力按可观察证据记录，未知不当真实身份。历史模型锁、独立评分路由、专项维护与生产晋升条件保留，不隐式评分、换模型或增加预算。

#### Scenario: 使用非 OpenAI 模型的原生宿主
- **WHEN** Claude Code 或 OpenCode 以用户选择的可用模型执行获授权任务
- **THEN** 公共业务工具不要求 gpt 模型名或 Codex 事件；保存可观察的真实模型信息，业务校验不替代模型身份和内容裁定

#### Scenario: 只能看见配置模型而没有执行证据
- **WHEN** 模型声明存在但没有实际执行观察
- **THEN** 只报告声明值与未验证状态，不能声称已调用或通过严格执行/晋升门禁

#### Scenario: Claude宿主别名与批准的映射目标不同
- **WHEN** 用户确认当前CC Switch的别名到目标映射，实际转录模型与批准目标吻合
- **THEN** 保留宿主声明、用户映射来源和转录观察，不仅按名称不同阻断合法原生研究；专业模型沿inherit，不调用模型适配器或读取CC Switch凭据，Provider wire未知及严格维护/晋升锁仍不得补证

### Requirement: 原生验证必须聚焦业务而不复制宿主框架
开发检查 SHALL 优先复用现有数据、数学、授权、PIT、引用、持久化及历史读取的真实生产者消费者接缝；宿主配置检查与实际原生验收分别执行。与已退役启动/Hook/事件控制仅有关系的测试 SHALL 随职责退役，混合测试须先迁移业务负例，不以旧测试要求保留第二套运行层。不得为三宿主建立模型 mock 编排平台、全仓快照前置或自动评委；确定性通过不宣称实际加载、token 节省或研究质量。

#### Scenario: 测试只固定旧 CLI 参数
- **WHEN** 该旧启动能力已被原生使用替代且无历史读取消费者
- **THEN** 移除对应测试与代码，不要求新产品继续生成旧命令；保留相关业务安全负例

#### Scenario: 实际宿主环境暂不可用
- **WHEN** 确定性检查可做但某宿主缺实际验收环境
- **THEN** 完成不依赖环境的授权工作并记录最小补验要求，不启动另一宿主或额外沙箱模拟该平台通过
