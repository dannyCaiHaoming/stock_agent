## MODIFIED Requirements

### Requirement: Macro 与 Market 验收必须使用可重复的既有宿主启动路径
Macro 与 Market 等现有任务 SHALL 在当前所选宿主原生会话中，通过共享角色/Skills 和受限业务工具执行；方法、输入范围、依赖及输出契约不因宿主变化而改变。实际加载与调用必须可核对，不以安装配置代替执行。正常研究 MUST NOT 依赖项目创建另一宿主进程、临时认证链接、复制认证或关闭原生权限；宿主能力不足时明确阻断。历史 Codex 启动证据按原版本只读，不重新标记为原生验收。

#### Scenario: 用户 Desktop 配置含宿主 CLI 不兼容字段
- **WHEN** 当前原生宿主会话合法可用，而另一 CLI 无法解析其配置
- **THEN** 不为日常研究启动另一 CLI 或修改用户全局配置；仅检查当前产品角色和业务工具的实际原生能力，缺必要权限仍停止

### Requirement: 研究所需计算必须通过实际授权工具验证
基本面、技术、市场与机构等任务 SHALL 使用各自既有受限计算能力；服务端核对可信任务、证券、cutoff、允许 Evidence 和实际成功收据。模型只选择并解释结果，数值、单位、窗口和血缘由确定性工具装配。新原生计算不要求 Codex Hook 才能授权，实际工具权限及服务端范围仍必须一致；不得统一开放任意公式或跨任务结果，Python 不形成投资判断。

#### Scenario: 基本面金额表达与机构两期计算
- **WHEN** 授权任务需要现有 monetary_scale 或 institutional_period_change
- **THEN** 以允许 Evidence 实际调用并保留成功血缘，跨任务/未授权事实/未结束期间拒绝

#### Scenario: 原生SEC结构化金额进入既有计算
- **WHEN** 原生任务明确选择已授权SEC财务事实，其value为已有结构化amount及单位/期间对象
- **THEN** 工具仅读取已知格式的有限amount；ratio要求同证券、accession、taxonomy、单位及起止期间框架，USD金额换算沿既有数量级工具执行，并保留来源三字段、原事实hash和value.amount血缘；任意对象、非金额、不同框架或未实现结构化运算写成功记录前拒绝，不让模型填操作数、自动选证据或改Gate。旧默认调用及冻结计算保持原行为，开发通过不回签停止后的原生报告

#### Scenario: 技术统计目录只交付有界精确选择
- **WHEN** TECHNICAL_STRUCTURE允许事实集为空但本任务已准备合法统计对象，完整计算目录含重复的大型输入血缘
- **THEN** 既有计算工具提供有界精确k引用、真实数值/单位/方法和血缘摘要，并支持按精确引用显式分页核对完整输入ID；目录不是原始OHLCV query，不开放原始事实或让作者自填计算身份。提交仍从可信完整目录装配作者明确选择，不以响应截断或空计算选择证明统计已完整消费

#### Scenario: 请求工具不支持的运算
- **WHEN** 请求超出当前计算方法
- **THEN** 不因原生迁移伪称支持、不让模型补造收据，使用原合格资料或准确披露限制

### Requirement: 材料准备输入必须按任务有界交付
资料准备 SHALL 保留完整 Gate，通过任务限定的目录/正文读取与共享方法按需使用资料；仅为搜索选择的角色不得接收不必要的完整逐日日线包装。当前宿主的实际上下文/工具响应限制必须核对，超过限制时明确阻断或按已实现的精确分页读取，不截断 JSON、删除事实或以目录冒充正文。旧 Hook 的 256 KiB 格式边界仅用于其历史产物解释，不作为所有原生宿主的统一能力上限；不新增通用 token 控制平台。

#### Scenario: 长行情历史使市场准备目录膨胀
- **WHEN** 冻结目录很大而任务只需发现正文与候选
- **THEN** 交付任务相关的可发现目录与授权查询，完整事实仍可经合法工具取得，不注入全部重复日线包装

#### Scenario: 其他材料任务输入仍超过上限
- **WHEN** 实际输入或响应超出当前宿主可确认限制
- **THEN** 报告具体限制并停止相关交付或使用已验证分页，不新开另一模型进程、不静默删正文

## ADDED Requirements

### Requirement: 原生多维业务契约必须与历史宿主包装分离
当前原生多维研究 SHALL 保留现有全部能力范围、Company/资料/研报真实依赖、证券/Gate/cutoff、计算/引用、一次原作者修订、覆盖和停止点，由当前宿主主线程原生组织并消费业务回执。既有要求中的launcher、Hook、Start/Stop、SAVED事件及专属输入字节格式仅作为冻结旧版执行包装读取，不成为新原生业务产物格式前提；其代表的授权、实际查询、完整报告和失败保护不得删除。任务依赖由合法业务成果验证，不由目录存在或模型自报放行；Python不得另建任务生命周期管理器。旧未解决内容问题仍披露，不以迁移回签质量PASS。

#### Scenario: 在另一宿主执行现有多维任务
- **WHEN** 正文与必要上游业务报告合法且原生角色/工具能力可用
- **THEN** 按同一专业方法和依赖执行，保存原生提交及实际工具记录，不要求伪造旧Hook事件或新增父进程

#### Scenario: 原生角色只完成部分维度
- **WHEN** 必需任务未运行、失败或无合法提交
- **THEN** 保留完整覆盖和原成果，不能将最小切片或部分报告标记为完整多维研究/下游就绪

## REMOVED Requirements

### Requirement: 八维协调父线程必须能读取绑定运行的可信任务状态
**Reason**: 当前正常研究由宿主原生任务机制承担执行，不再由业务 MCP 从 Codex Hook 重建第二套生命周期状态。
**Migration**: 当前主线程使用原生任务结果/句柄；业务工具继续核对已提交报告、真实读取、依赖与完整覆盖，不能由保存回执推导作者/内容 PASS。旧冻结 task-bound 状态记录保留只读，不改写事件；正常工具面和调用路径不再暴露该旧控制接口，不另造跨宿主状态服务。

#### Scenario: 正常原生研究请求旧状态控制接口
- **WHEN** 新原生任务请求由 Codex Hook 重建的执行状态
- **THEN** 明确报告旧接口退役，不能回退启动旧 launcher；合法业务报告验证仍可独立进行
