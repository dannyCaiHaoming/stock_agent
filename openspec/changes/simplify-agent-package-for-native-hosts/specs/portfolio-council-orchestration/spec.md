## MODIFIED Requirements

### Requirement: Portfolio Council 必须由 CIO 主线程主持
用户通过 `portfolio-council` 提交有效输入并明确选择综合/决策阶段后，当前所选宿主主线程 SHALL 承担该阶段 CIO 职责；仅研究阶段的主线程负责组织专业任务，不自动取得 CIO 或账户决策权限。研究判断 MUST 来自真实原生 Agent/主线程，不由 Python callback、固定模板或外层模型进程替代。系统 MUST 记录所用共享产品指令、Skill 和角色来源，区分实际加载观察与静态发现；全局同名资源不得静默替换验收对象。旧 Codex 冻结产物按原版本只读，其宿主命令不得成为新正常研究的入口。

#### Scenario: 启动 Codex-native fixture 组合评审
- **WHEN** 用户另行授权在当前宿主使用有效 fixture 验证已实现完整 Council
- **THEN** 当前主线程建立业务 run、问题、能力计划、cutoff 与产物位置，原生委派后执行适用 Risk，不由项目代码额外启动模型进程

#### Scenario: 启动组合评审
- **WHEN** 用户提交有效持仓并调用 portfolio council
- **THEN** 主线程建立问题、能力需求、证据时点和委派计划；未开放的完整组合建议仍明确拒绝，不因宿主迁移扩大能力

### Requirement: Fixture Council 必须通过 Codex-native 入口端到端执行
已实现fixture完整Council的确定性输入、Gate-scoped查询、Company/独立Skeptic、主线程CIO、硬Risk、最终产物及Trace业务契约 SHALL 保留。当前原生能力包的该场景由用户所选宿主主线程和原生角色执行，不强制Codex CLI、不额外启动模型进程或Python编排后端；真实账户完整建议入口仍不开放。旧Codex执行包按原版本只读，专项发布/评估不得从原生Smoke继承通过。

#### Scenario: 正常 fixture 完成固定链路
- **WHEN** 用户另获明确授权在当前宿主执行正常fixture场景
- **THEN** 同一业务run绑定真实专业报告、CIO原稿、Risk与最终产物，受限工具记录与原生执行观察分列，不用模拟角色或固定结论冒充实际研究

### Requirement: Smoke 运行必须可重复调用并留下可核验产物
Smoke SHALL 在选定宿主的当前原生产品会话中执行明确样本、模型与调用/时间预算，使用新的业务输出位置并保存来源/版本、实际委派/工具、原报告及验证结果。新原生Smoke不要求项目生成codex exec命令或进程退出文件，不创建另一宿主运行；真实调用必须另获授权。源码和历史产物的保护及实际观察范围必须准确记录，缺必要加载/隔离证据不认证通过，事后hash不等同OS强制只读。旧命令及历史证明保留其原时点，不回签。

#### Scenario: 评审者重复执行 Smoke 命令
- **WHEN** 用户另行批准同一业务样本在选定宿主的新的原生验收
- **THEN** 使用新的产物身份/位置并重验合法输入、报告/引用、实际原生执行及适用Risk，不覆盖旧结果、不自动评分或重跑、不把模型自报当真实证明

### Requirement: 并行研究必须隔离初始结论
Company Analyst 与 Independent Skeptic SHALL 使用宿主原生角色及独立输入上下文完成首轮研究；资源允许且该能力计划要求并行时，两项委派 MUST 在等待任一报告前发出，环境仅支持串行须明示。Skeptic 的首轮输入 MUST NOT 包含 Analyst/CIO/其他 Agent 的结论、摘要或内部报告引用；宿主工具与服务端任务范围必须验证。CIO 仅在必需报告通过业务验证且首轮隔离可证后比较共识、冲突与依据。

#### Scenario: 两个 Agent 独立形成相反判断
- **WHEN** Company 与 Skeptic 对同一允许 Evidence 独立形成实质冲突
- **THEN** 保留各自输入范围和原报告，主线程说明冲突及判断影响，不依赖 Codex 特定 Hook 证明格式

#### Scenario: 两个 Agent 给出相反判断
- **WHEN** 两报告对关键 Thesis 的证据或解释不同
- **THEN** CIO 记录双方具体依据、未解决部分和适用阶段的判断影响，不由 Python 计算观点分数

#### Scenario: 宿主不能证明独立首轮
- **WHEN** 原生子任务可能继承正向历史或拥有可读取正向报告的未经隔离工具
- **THEN** 阻断独立首轮能力，不以同一上下文改角色、提示词禁止或访问凭据替代实际隔离

### Requirement: 研究任务终止与报告成功必须分别识别
当前宿主主线程 SHALL 使用原生任务结果/句柄识别任务是否仍在执行，业务工具仅判断实际提交的报告与依赖是否有效，不另建宿主生命周期状态机。失败或结束任务不因缺 Codex Start/Stop 格式持续空等；格式修订继续使用原作者及既定上限。报告文件存在、模型自报、访问凭据或业务保存回执 MUST NOT 单独证明实际作者执行或内容通过。未完成/超时/失败保留已验证成果和剩余清单，不自动派发重试。

#### Scenario: 草案缺身份且全部子任务已结束
- **WHEN** 原生宿主返回已结束，而报告技术装配缺少必要可信任务绑定
- **THEN** 按结束与业务失败分别归集，不继续等待已结束任务、不补造身份，核心依赖失败阻断下游

#### Scenario: 子任务尚在格式修复或缺终止证明
- **WHEN** 原生任务仍在修订或必要执行观察缺失
- **THEN** 不声称完整执行验收；按授权等待/停止条件处理，业务报告合法性与宿主观察分列，不重建另一套任务状态工具

### Requirement: 正反交接包必须通过显式独立阶段进入研究级 CIO
系统 SHALL 保留 PREDECISION_CIO_SYNTHESIS 的显式业务阶段，从重新验证的 PreDecisionResearchPackage、来源绑定和研究请求进入当前宿主主线程综合。持仓分支绑定来源 Handoff，非持仓分支绑定 SINGLE_STOCK_RESEARCH；新业务 run 与独立输出目录保持 source_run_id/package_hash 和新请求身份，但不要求新建宿主模型进程。准入目标仍是来源包已研究的受支持美股普通股，只输出 RESEARCH_SYNTHESIS，PORTFOLIO_ADVICE 仍在综合前拒绝。原研究停止点及原产物不变；不得新增 CIO 子 Agent、外层编排器或自动重派专业研究。

#### Scenario: 用户研究已清仓的 MRVL
- **WHEN** 用户明确请求综合合法历史正反包
- **THEN** 当前主线程综合来源 cutoff 的判断，保留新的业务产物身份，不伪造当前持仓或重启另一宿主

#### Scenario: 请求本阶段未发布的持仓建议
- **WHEN** 调用方选择 PORTFOLIO_ADVICE
- **THEN** 工具在综合准备时拒绝该级别，不生成动作、Risk 通过或建议文件

#### Scenario: 只运行研究阶段
- **WHEN** 用户只请求多维或独立反证
- **THEN** 停止于原研究产物，不自动进入 CIO/Risk，不因缺最终决策报告而失败

#### Scenario: 新 ALB 正反研究进入 CIO
- **WHEN** 同源 ALB 包通过原证券、身份、PIT、报告和阶段门禁且显式请求综合
- **THEN** 当前主线程读取目标约束与合法完整报告，不注入 MRVL 样例或创建额外模型父进程

#### Scenario: 综合面对上游已保存但局部内容有误的报告
- **WHEN** 上游缺口理由、正文引用或计算关联有疑点
- **THEN** CIO 核验最终采用主张的合法依据并说明影响；不由程序修正来源或改变研究状态，未采用疑点继续披露，核心依据与重要反证仍须内容裁定

### Requirement: 研究级成功检查必须核对宿主进程结果
历史 Codex 模型进程包 SHALL 按其冻结版本重验原进程结果、终态与身份，原要求不得回填或豁免。新原生研究 SHALL 独立检查可信业务请求、Gate、实际查询/报告读取、提交回执、Schema/引用/计算闭合及完整覆盖；可观察的宿主委派和模型执行另列。它 MUST NOT 要求不存在的 Codex 子进程结果文件，也不得由合法业务报告推导进程 exit=0、模型/作者身份或执行 PASS。完整产品研究成功仍须具备该业务阶段要求的完整依赖、实际原生执行和内容核对证据。Agent Package 迁移的有限验收 SHALL 按 native-agent-package 执行；有限验收不豁免完整研究要求，也不将未运行的阶段记为完成。Risk、回测和 Promotion 不自动通过。

#### Scenario: 有研究报告但缺进程结果
- **WHEN** 新原生报告没有 Codex process-result，而业务记录完整
- **THEN** 依原生业务版本验证，不伪造旧文件；必要执行观察缺失仍保持对应验收未验证。旧 Codex 包缺该必需文件仍拒绝旧执行证明 PASS

#### Scenario: 宿主失败与研究终态矛盾
- **WHEN** 真实宿主观察显示失败、未结束或资源被修改，而交付声称成功
- **THEN** 拒绝完整执行验收和发布，保留报告及矛盾，不用业务保存结果覆盖失败

#### Scenario: 合格进程与研究证据一致
- **WHEN** 适用版本的业务、实际宿主执行和内容证据均满足本次验收
- **THEN** 可报告相应研究完成，历史和原生证明不混用，不代表未运行的 Risk 或晋升
