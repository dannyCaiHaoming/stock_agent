## MODIFIED Requirements

### Requirement: 开发与运行 Agent 必须物理区分
系统 SHALL 在各宿主提供清晰分离的开发规则/角色与产品规则/角色，产品请求仅使用其获授权输入、资料与工具。当前宿主主线程进入产品阶段不继承源码修改、开发发布或生产配置权限；只读专业角色与受限业务 MCP 必须实际执行该边界。角色名称和提示词单独不构成权限隔离，不能为隔离而由项目新增模型执行器或跨宿主后端。

#### Scenario: Runtime Agent 尝试修改产品
- **WHEN** 产品角色请求修改 Skill、Agent、Risk、程序、测试或配置
- **THEN** 原生权限及工具边界拒绝并记录可观察违规，业务结果不掩盖源码变化；无法保证该隔离的宿主能力不能标记通过

### Requirement: 开发指令必须按任务条件读取
根指令 SHALL 维护开发原则、职责、安全边界和按需文档入口，产品规则集中在自有产品内容，默认中文。正常产品研究使用当前所选宿主原生会话，开发不因阅读产品指令取得 CIO 权限。确定性开发检查不启动模型、来源网络或额外沙箱；实际原生 Smoke 需明确宿主、样本、模型/调用预算及授权。旧执行 Replay 与专项评估保持显式维护范围，独立复核默认读取差异/规格/已有证据；不得通过底层工具或退役 launcher 绕过权限/运行授权。

#### Scenario: 普通开发与专项诊断
- **WHEN** 执行授权开发或仅诊断
- **THEN** 按目的读取必要规则，诊断不自授修复，普通开发不调用产品模型或扫描私人会话

#### Scenario: 产品运行不触发开发收尾
- **WHEN** 用户在当前宿主调用 portfolio-council
- **THEN** 使用适用产品输入和阶段，保留 advisory-only/PIT/Evidence/Risk 及非动作限制，不执行归档、Git 发布或生产文件修改

#### Scenario: 仅依靠根指令选择执行入口
- **WHEN** 从根规则决定确定性检查、原生产品验收或历史维护
- **THEN** 能区分三者，正常研究不被引导启动另一宿主；缺必要授权时说明最小需求而不自动运行

## ADDED Requirements

### Requirement: 架构瘦身优先级必须保留其他需求现场
用户指定本 Change 优先后，开发 SHALL 仅推进其获授权规划/实施/验收，其他活跃 Change 保留任务、未提交修改和原始证据，不重新排序、回退、勾选、归档或合并它们。后续需求调整必须在本 Change 完成后按用户指示重读原目标与新架构，不以瘦身为由提前实现列表、内容修复、成本优化或历史建议。已完成的配置对齐及独立交易功能不重开验收。用户默认 main 的工作偏好保持；如更高优先级执行约束要求分支操作，应先说明并请求决定，不静默创建。

#### Scenario: 共享文件含其他 Change 修改
- **WHEN** 原生迁移需修改共享 runtime/Schema/配置且已有其他需求差异
- **THEN** 先依据实际差异分离本次范围，保留原修改；无法安全归属时停止相关编辑/发布，不整文件回退或全目录提交

#### Scenario: 瘦身完成后准备继续后续需求
- **WHEN** 本 Change 已完成既定验收与人工批准
- **THEN** 只报告后续需求需重新对齐的接缝，等待用户安排，不自动将暂停需求扩大为本次工作或恢复旧运行层
