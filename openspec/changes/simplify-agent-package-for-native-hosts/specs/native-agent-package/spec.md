## Purpose

让同一套投研方法、角色正文与确定性业务工具在 Codex、Claude Code、OpenCode 的当前原生会话中使用，宿主负责模型与 Agent 执行，项目不再管理另一套宿主运行系统；保留来源、授权、独立反证、历史产物及私人数据安全边界。

## ADDED Requirements

### Requirement: 研究方法与角色必须共享且宿主配置保持薄层
系统 SHALL 为自有 Skills 与四类现有研究职责维护一份权威正文，分别提供 Codex、Claude Code、OpenCode 的原生角色、Skill 发现、业务工具与权限配置。宿主差异 MUST 限于配置、安装映射和简短操作说明；不得新增统一 Agent Runtime、模型 API/SDK 后端、会话管理器、调度器或事件翻译协议。第三方 Skill 与用户已有配置 MUST 保留原样；某宿主不支持的扩展不得混入公共研究正文并宣称通用。

#### Scenario: 在另一宿主安装同一能力包
- **WHEN** 用户选择一个已验证支持的宿主和明确安装范围
- **THEN** 同一研究正文和业务工具可被该宿主原生发现，配置差异明确，产品无需启动另一宿主或复制私人状态

#### Scenario: 同名用户配置或角色冲突
- **WHEN** 安装目标已有不同的同名角色、Skill 或 MCP 定义
- **THEN** 报告冲突与最小选择，不覆盖用户文件或默默加载错误来源，不修改第三方 Skill

#### Scenario: 桌面项目直接绑定已批准的私有研究连接
- **WHEN** Claude Code桌面产品项目没有继承连接环境变量，操作方为指定业务MCP显式提供已有仓库外私有连接文件
- **THEN** 项目原生MCP配置可直接启动同一确定性业务工具并读取本角色连接，不要求独立模型CLI登录、额外模型进程或全局环境修改；导出不读取/复制秘密，业务调用仍逐次校验任务授权

#### Scenario: 私有连接文件不合法或角色错配
- **WHEN** 显式文件存在路径/权限问题、缺少本角色字段或不能通过原连接与角色验证
- **THEN** 在工具暴露与业务副作用前脱敏拒绝，不回退其他环境凭据，不把文件存在当实际宿主加载或作者隔离证明

#### Scenario: Claude主线程操作指引随安装生效
- **WHEN** 导出已审阅的Claude Code产品包
- **THEN** 根CLAUDE.md包含同一份已审阅的Claude主线程短指引，普通本地研究不擅自传入worktree/remote隔离或覆盖角色继承模型；缺指引或来源漂移在创建导出目标前拒绝，不修改公共研究正文、旧安装或用户配置

#### Scenario: 同一桌面会话切目录后Skill仍来自旧包
- **WHEN** Claude桌面已报告新cwd或加载新CLAUDE.md，但实际Skill正文的Base directory仍指向旧产品包
- **THEN** 按实际来源不符停止，不能以cwd、同名Skill或正文hash相同放行，也不据此宣称其他角色/MCP已重新加载；新候选应从其精确项目目录新建原生产品会话并分别核对实际来源，仍需新的有界运行授权，不清空/删除旧会话、不改全局配置、不改用路径别名重试或新增项目加载器

#### Scenario: 可选参数展示不足或实际调用拒绝
- **WHEN** Agent展示类型只列额外隔离模式但未明确必填集合，或宿主实际拒绝省略参数的合法调用
- **THEN** 区分官方可选配置、当前工具实际Schema、已发生参数错误与未知的实际接受行为；不仅凭联合类型判永久不支持，不擅自创建Git/worktree、换远程上下文、另起后端或自动重派，保留当前授权与实际失败

#### Scenario: Claude Company调用端不暴露额外派发参数
- **WHEN** 获授权的Claude产品主线程委派Company，且主线程指引已加载仍发生Agent可选参数误填
- **THEN** 通过宿主自带的context fork Skill固定绑定现有Company角色，调用只传Skill名及本次完整任务授权；角色模型/正文/工具/预加载Skills沿原定义，不由模型构造Agent隔离或模型参数，不新增执行器、Hook或自动回退

#### Scenario: Claude原生Company入口缺源、漂移或同名冲突
- **WHEN** 导出清单缺少已审阅的Company原生Skill、源hash漂移或与共享Skill的发现路径冲突
- **THEN** 在创建目标前拒绝，旧包不变；仅Claude安装这个宿主配置，其他宿主及共享研究正文不变，不用另一Skill或通用Agent代替

#### Scenario: 原生Company Skill尚未实际运行
- **WHEN** Schema、固定角色配置及精确导出检查通过，但新入口没有原生发现/角色执行/业务回执证据，或宿主实际拒绝
- **THEN** 只报告调用入口配置检查及具体未验证/失败，不声称Company研究或行为复发预防已实证，不消耗已停止窗口、不自动转Agent重派、不减当前Claude验收与人工完成要求；其他两宿主的未验收义务保留在遗留清单

#### Scenario: Claude项目Company角色显式复用已有MCP连接
- **WHEN** 公司原生Skill已被发现，但宿主在作者创建前将精确Company工具解析为zero tools
- **THEN** 项目角色可用原生mcpServers字符串显式引用已有company连接，保持精确工具白名单、研究正文、五Skill和模型继承；不新增服务、复制凭据、扩大通用工具或通配权限，不把插件忽略字段假设为同等支持，配置检查与本机实际执行分别记录

#### Scenario: Claude已有Market与Skeptic复用固定原生绑定
- **WHEN** 同类Agent误参也发生于现有Market/Skeptic，且本次修复范围明确包含这两个角色
- **THEN** 仅新增固定原角色的薄context fork Skill及精确导出映射，两个项目角色引用各自已有MCP连接；保持原精确工具/Skills/继承模型，不新增派发程序、自动回退或通用工具。缺源/漂移/同名冲突写前拒绝，其他宿主不安装；实际首轮输入、工具池和模型仍须在新有效窗口核验，原失败不改

#### Scenario: 专业Skill加载与窗口首错停止
- **WHEN** 原生角色执行获授权研究，宿主提供Skill加载或预加载机制
- **THEN** 使用本角色工具并实际加载本能力所需共享Skill，加载来源和实际证据分别核对，不以提示或父线程加载代替。窗口规定首错停止时不得继续业务调用/提交或其他角色，不新增项目停止控制器；工具错误与合法保存分别保留

### Requirement: 正常研究必须由当前宿主原生执行
正常产品请求 SHALL 由当前宿主主线程调用共享 Skill、委派原生专业 Agent 并在明确综合阶段担任 CIO。项目 Python/Shell MUST NOT 启动额外宿主模型进程、调用模型 API/SDK，或实现派发/等待/重试的另一套执行循环。业务工具的有限数据处理、确定性查询与持久化进程不属于模型执行。现有单股、确认持仓、资料准备、多维、独立反证和显式 CIO 的输入及停止点 MUST 保留；独立 Intake、交易记录和复盘不自动进入 Council。

#### Scenario: 当前会话请求单股完整研究
- **WHEN** 请求通过现有证券、资料和阶段授权校验
- **THEN** 当前宿主完成专业委派和主线程综合，Python 仅提供业务能力，不创建第二个 Codex、Claude Code 或 OpenCode 模型会话

#### Scenario: 阶段依赖或原生委派不可用
- **WHEN** 必需报告不合法、必要工具不可用或宿主不能执行该专业职责
- **THEN** 对应阶段明确阻断并保留已完成成果，不换宿主、伪造报告、自动重试或开放未授权阶段

### Requirement: 独立研究和业务工具授权必须实际隔离
专业研究 SHALL 仅获得任务授权的证券、问题、Gate 资料和工具，独立 Skeptic 首轮 MUST 不继承正向结论或其他私人账户信息。宿主工具权限与服务端任务授权 MUST 同时生效；提示词、角色名字、任务 ID 或访问凭据单独均不得作为实际调用方认证或隔离证明。无法提供与现有边界等价的输入/工具隔离时 MUST 阻断对应能力，不通过配置存在或角色自报放行。

#### Scenario: 首轮 Skeptic 被注入正向结果
- **WHEN** 独立首轮输入包含 Analyst、Market 或 CIO 的结论、摘要或内部报告引用
- **THEN** 拒绝独立首轮研究，不能借用同会话换角色或后续针对性反证掩盖污染

#### Scenario: 非法调用在写入前被拒绝
- **WHEN** 调用缺少授权、绑定另一任务或请求超出 Gate 的事实及计算
- **THEN** 服务端在返回事实或修改报告状态前拒绝，不占用被冒用任务的修订额度；拒绝后原合法任务仍可正常提交

### Requirement: 原生业务连接必须按请求和角色限定任务路由
原生研究业务MCP SHALL 绑定一个合法研究请求、冻结Gate和明确角色范围，每次业务调用使用准备边界授予的精确任务引用及对应任务能力凭据；同一原生角色的多个获准证券/能力任务不要求逐项修改宿主配置或重启模型会话。服务端 MUST 在资料返回、计算、稿件名额或持久化前重验请求、Gate、角色、任务和允许对象；未授权、混用或未知引用拒绝且不改变合法任务。连接及任务凭据均不替代真实宿主调用方认证或独立上下文证明。业务路由 MUST NOT 派发/等待/重试Agent、维护宿主会话/生命周期、创建后台任务或调用模型；原生执行仍由当前宿主主线程承担。旧单任务接口及已保存产物按其原范围保留，不能自动扩权为新路由。

#### Scenario: 同一角色处理两项获准任务
- **WHEN** 当前宿主原生Company或Market角色在同一研究请求内分别处理任务A和B
- **THEN** 同一业务连接按各自引用/凭据访问相应资料与提交，证券、Gate、计算和报告绑定不串用，不更改宿主执行参数或启动新模型进程

#### Scenario: 任务引用与凭据或角色错配
- **WHEN** 使用A的凭据调用B、跨研究请求引用、未知任务或由非授权角色请求
- **THEN** 在取证或副作用前拒绝，B的稿件名额/文件不变，原合法调用仍可完成；Skeptic不能读取正向结果

#### Scenario: 原生角色只读取精确的小型任务授权
- **WHEN** 操作方通过已有task准备命令显式指定agent-grant输出位置
- **THEN** 在私有源码外新文件确定性写入本任务引用/凭据、最小范围与来源时点，不交付完整任务/事实ID/资源表或操作方连接凭据；原完整授权格式不变，正文和输出契约仍通过受限业务工具读取，不从旧上下文猜测或回退任务授权

#### Scenario: 小型授权输出位置不合法
- **WHEN** 指定输出是相对路径、源码内路径、公开目录、symlink、已存在或与完整授权同路径
- **THEN** 在新任务创建前拒绝，旧文件和任务名额不变，不回显秘密、不自动选择另一位置

#### Scenario: 大型事实允许集的上下文交付
- **WHEN** 原生任务的事实ID列表过大，调用research_context读取任务权限和输出契约
- **THEN** 工具返回显式有界ID页、总数及精确下一页偏移，完整允许集和输出契约不被截断；所有页保持同一任务授权和资源检查，目录不计作事实查询，计算输入血缘经已有计算工具读取

#### Scenario: 模型已选择的事实响应超过字节预算
- **WHEN** research_query的合法精确ID请求数量在允许范围内，但完整事实响应超过既有64KiB上限
- **THEN** 按请求顺序返回能装入预算的完整事实页及total/offset/next_offset，显式offset/limit可继续同一选择；小请求未指定分页且全量能装下时保持原响应。每页先重验整组ID的任务授权、Gate/PIT和资源，事实原字节语义、source_id/as_of/retrieved_at与原事实hash不改，不截断字段、跳过大事实或替模型选证据；单事实连同页信封仍超限时拒绝且不生成成功查询收据

#### Scenario: 分页查询只消费实际返回的事实
- **WHEN** 查询页只返回本次选中ID的一部分，或未返回页含未知、跨任务或排除事实
- **THEN** 成功查询收据的evidence_ids只包含实际返回事实，input_hash绑定原请求参数、result_hash绑定实际页；未读后页不能被提交为已查询。整组不合法在任何页面返回/收据写入前拒绝；非法页参数、单事实超限或资源漂移也不记成功，不新增自动翻页、模型重试或宿主生命周期控制

#### Scenario: 计算目录含大量重复输入血缘
- **WHEN** 已有成功计算或precomputed统计的完整目录超过工具响应预算
- **THEN** 通过既有research_calculations按offset/limit返回有界精确引用/原数值/单位/方法及血缘数量/hash；用calculation_ref与evidence_offset/evidence_limit显式读取完整输入ID页。实际JSON含页信封不超过65,536 UTF-8字节，不截断单项、不自动选择或翻页，不把ID目录当原始事实query；内部完整对象、k绑定和提交装配保持，小型未指定分页的合法原响应兼容

#### Scenario: 计算页越权、漂移或参数不合法
- **WHEN** 计算页使用未知/跨任务引用、非法参数或单项超限，或任务/Gate/PIT/资源/precomputed文件hash不符
- **THEN** 在数据返回前拒绝且无新运算/写入/稿件额度消耗；每页重新核验，并明确实际返回血缘范围和来源三字段，不扩大原始事实权限或回签已停止窗口

#### Scenario: 大型报告的精确回读保持完整内容
- **WHEN** 已有MCP精确有效回执回读的完整报告因完整计算血缘超过响应预算
- **THEN** 小报告原响应保持，大型或显式offset/limit返回按Unicode字符偏移的有界canonical JSON片段及total/next_offset，完整页信封不超过65,536 UTF-8字节；每页绑定原回执/报告hash、完整payload_hash和来源三字段，明确不是完整报告。读取者以同一回执显式读完并无损拼接，未读末页不声明完整回读；每页重验原授权/资源/稿件及报告hash，非法参数、越权、漂移无写入。内部完整读取、提交/依赖/归档对象不改，不摘要、删血缘、自动翻页或新增交付服务

### Requirement: 业务有效性与宿主观察及内容裁定必须分离
系统 SHALL 分别记录输入/引用/计算/报告的确定性有效性、可实际观察的宿主加载与执行、研究内容裁定。新原生业务产物 MUST NOT 以 Codex 专属 JSONL、Hook、子进程退出文件或 CLI 二进制为格式前提。技术字段须由可信任务和实际工具记录装配，模型只提交研究字段及明确选择；缺少可验证的宿主/model/作者观测 MUST 明示未验证，不能由模型填值、任务凭据或业务回执补造。严格身份或版本要求的维护/晋升操作仍须满足其原门禁。

#### Scenario: 业务报告合法但没有可观测模型身份
- **WHEN** 原生工具校验和保存成功，而宿主未提供可核验实际模型或作者事件
- **THEN** 业务验证与该项执行未验证分别展示，不冒称真实模型身份、完整执行验收或 Promotion PASS，也不伪造旧 Codex 字段

#### Scenario: 配置存在但未被实际使用
- **WHEN** 三个宿主的安装模板可解析但没有实际角色委派或工具使用观察
- **THEN** 仅报告静态配置检查，不标记该宿主实际研究能力验收完成

### Requirement: 控制层退役必须保留业务与历史能力
迁移 SHALL 在等价业务消费者可用后移除正常研究依赖的自建启动、重复调度、Hook 控制和状态重建，公开旧模型启动入口必须明确退役且不可被正常请求回退使用。历史只读读取不要求保留旧执行器；旧报告、Schema、失败记录、账本与 hash MUST 不改写。独立交易记录/复盘及只读券商边界不扩权。测试 SHALL 随职责保留、迁移或退役，不以保留旧测试为由保留冗余执行机制，也不得删除安全检查掩盖回归。

#### Scenario: 移除运行控制但混合模块含报告验证
- **WHEN** 退役宿主控制代码
- **THEN** 先保留并贯通 Schema/PIT/引用/计算/持久化消费者及其负例，再移除控制专属代码和测试，不整目录删除

#### Scenario: 读取旧报告或独立私人复盘
- **WHEN** 用户只读取合法历史产物或使用既有独立交易记录/复盘入口
- **THEN** 读取保持原版本和权限，旧文件不变，不启动研究模型、账户同步或新宿主进程

### Requirement: 当前Claude交付必须达到有限而真实的验收，其他宿主明确遗留
Change当前完成 SHALL 具有Claude Code的共享Skill/角色实际加载、原生专业委派、受限业务工具、合法提交及精确读取证据。最小合法阶段组合 MUST 覆盖Company、Market、独立Skeptic和明确综合阶段的主线程CIO；使用既有版本化fixture与合法冻结MRVL技术切片，不要求补齐全部研究来源或完整公开股票八维研究。独立首轮、任务授权、PIT、引用、计算、历史保真及实际工具权限 MUST 保持；各切片只认证实际完成能力及原报告内容，不推导完整股票研究、真实账户建议或Promotion。真实验收 MUST 取得明确宿主、样本、模型或用户批准映射、调用/时间上限与停止条件授权，不默认来源网络、账户或专项评估。Codex/OpenCode原生验收和内容义务 SHALL 明确列为遗留未完成，保留实现/模板及原证据，不再作为当前Claude交付完成前置，也不得宣称三宿主已经通过。旧失败、预算偏差和停止窗口 MUST 保留，不按新口径回签成功；当前Claude缺必要证据仍未完成，人工最终完成批准另行取得。
