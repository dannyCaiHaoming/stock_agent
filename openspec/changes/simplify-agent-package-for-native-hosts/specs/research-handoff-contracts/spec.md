## MODIFIED Requirements

### Requirement: 当前语义草稿必须区分模型判断和技术装配
当前支持新写入的资料准备、Company、多维、Skeptic、CIO 及适用评分入口 SHALL 保留各自研究/业务 Schema。模型只提交研究、评分或决策字段与明确引用/计算选择；确定性业务工具 MUST 从可信任务授权、实际资料与工具记录装配身份、来源、版本、hash 和路径，不让模型抄写。新原生入口不依赖某宿主 Stop Hook 才能装配或保存，且不得把未观察到的宿主/model/作者信息装成真实执行身份。旧协议仅按冻结版本读取，未迁移评分能力不得被暗中恢复新写入。

#### Scenario: 模型只提交研究草稿
- **WHEN** 授权任务提交合法研究字段和精确选择而未填写技术包
- **THEN** 业务工具校验后装配正式产物，所有事实保留 source_id/as_of/retrieved_at；实际执行缺证项单独标记，不伪造事件

#### Scenario: 草稿显式冒用其它身份
- **WHEN** 草稿附带冲突身份、未知任务或越权绑定
- **THEN** 写入前拒绝并保留准确错误，不覆盖冲突后继续

### Requirement: 提交回执必须精确绑定且不要求模型复制hash
新原生提交 SHALL 沿既有确定性提交边界返回指向唯一不可变草稿版本的短回执，结合服务端可信任务授权重验内容 hash、允许对象、角色范围和明确选用版本；不得要求模型复制 hash、猜最后一稿或依赖 Codex Stop 消息解析。权限校验必须在副作用和额度消耗前执行。访问凭据仅是任务能力，不替代实际宿主调用方认证；需要执行身份证明的用途必须另有真实证据，无法证明时不伪称验证。旧回执按原版本只读。

#### Scenario: 同一任务提交两版草稿
- **WHEN** 原作者在既定首稿加一次修订范围内明确选择有效回执
- **THEN** 只消费该版本并保留原稿、完整 hash 和修订关系；不存在、别任务、被替换回执或第三稿均拒绝

#### Scenario: 未授权调用冒用任务
- **WHEN** 缺少/错误授权或别任务凭据请求写入、接受或替换报告
- **THEN** 在占名额或改变任务状态前拒绝，不能仅凭 run/task/agent 字符串通过

### Requirement: 材料CIO及Eval的审计必须来自真实记录
资料获取尝试、CIO 的允许报告/实际读取/明确采用、计算和报告绑定 SHALL 来自实际业务工具记录；可验证宿主/model/作者信息从宿主真实观察获得。模型仍负责研究选择和判断，工具不得把允许目录自动填为已消费、执行成功或内容通过。新原生报告不要求 Codex 专属事件格式；缺观测项明确未验证，不搜索私人会话库或凭模型自报补证。独立 Skeptic 首轮隔离不因共享审计改变，旧 Eval 原锁和评分门禁保持。

#### Scenario: 材料获取失败
- **WHEN** 工具搜索/下载失败而模型完成其他合法选择
- **THEN** 保留真实失败和路径/来源限制，不要求模型复制日志，不把失败写成成功

#### Scenario: CIO没有读取获准报告
- **WHEN** 允许报告没有满足阶段要求的实际读取记录
- **THEN** 不生成已消费证明，保留目录授权与采用/读取的区别并拒绝对应不合法交付

#### Scenario: 两类Eval仅返回评分语义
- **WHEN** 另获明确评分授权且该评分入口的真实身份/输入/模型锁满足原要求
- **THEN** 确定性装配并验证评分产物，不修改 rubric 值或阈值；正常原生研究不自动调用评分
