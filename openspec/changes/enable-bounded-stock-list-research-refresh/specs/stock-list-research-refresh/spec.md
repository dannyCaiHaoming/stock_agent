## Purpose

为已确认持仓列表和无账户自选股列表提供可追溯的普通股批量研究与刷新，使证券变化、资料变化及局部失败后仅执行必要研究，在明确预算内显示真实推进或结束，并保留完整覆盖、已完成成果和历史判断的原始身份，而不新增账户决策、交易能力或第二套调度系统。

## ADDED Requirements

### Requirement: 两类列表输入必须显式区分且完整保留

系统 SHALL 接受真实已确认 PortfolioHandoff 加独立 CouncilRequest 的持仓列表，或显式 STOCK_LIST_RESEARCH 的无账户自选股列表；两者均仅在调用 portfolio-council 且明确阶段/范围后运行。自选股 MUST 保存不可变请求/hash、原代码/市场/问题、逐项证券解析状态、共同冻结 cutoff、身份来源与 source_id/as_of/retrieved_at，不生成账户、现金、数量、成本或伪 Handoff。持仓变更须重新 Intake 确认；仅研究范围/问题变更不得改 Handoff。完整输入 MUST 不因预算、固定样本数、未支持资产或单项错误而被截断；资源限制透明分批，未支持 ETF/期权等仍在覆盖清单中，不自动研究或当普通股。

#### Scenario: 输入多个自选股代码
- **WHEN** 用户以无账户模式提供多个代码和研究问题
- **THEN** 保存完整版本化列表及逐项身份来源/状态，不索取现金/数量、不假设持有或空仓；合格普通股进入计划，其他项保持明确未支持/身份阻断

#### Scenario: 持仓普通股和期权混合
- **WHEN** 已确认 Handoff 包含普通股、ETF 与期权，用户只授权普通股研究刷新
- **THEN** 原 Handoff 和全部覆盖项保持，普通股按请求研究，其余项明确不在当前研究能力/范围；不扩大成完整组合建议

#### Scenario: 列表超过一次预算可容纳范围
- **WHEN** 完整输入证券数超过一次批准预算能执行的任务数
- **THEN** 保留全部输入、明确本次执行波次与未执行原因，不删除末尾股票或暗设产品数量上限

### Requirement: 身份失败必须逐项阻断且 latest 必须真实冻结

每个自选股研究项 MUST 沿既有受支持普通股身份准入核实市场、资产、交易所/币种、share class、申报身份及原来源；ticker 不是永久身份。身份歧义、冲突、缺 provenance 或未支持品种须在该项 Provider 正式取证/模型派发前拒绝并保留原因，不静默替换候选；已合法核实的其他项可在批准预算内继续。重复同身份且研究问题/语义输入兼容的项 SHALL 合并研究任务但保留原输入到 canonical security 的完整映射；同身份不同问题须保留各研究需求并分别计划，冲突问题不能静默丢弃。latest SHALL 保留准备请求和实际获取时间，采集完成后确定性冻结本批共同 cutoff，显式历史 cutoff 不自动推进；没有合格冻结资料时模型前拒绝，不将今日身份/事实伪为过去可知。

#### Scenario: 一条代码歧义而其他合法
- **WHEN** 列表中一项无法唯一核实且两项普通股身份合法
- **THEN** 歧义项保留为阻断，不进入正式研究；两项合法证券仍可计划，不用歧义项导致整批无限等待

#### Scenario: 同代码对应不同市场或 share class
- **WHEN** 两个输入标签看似相同但来源核实身份不同
- **THEN** 不按 ticker 合并，不共享错身份缓存；显式解析各项或拒绝无法核实项

#### Scenario: 取证结束晚于准备时间
- **WHEN** latest 列表资料在准备请求之后才返回
- **THEN** 保留真实 retrieved_at 与原准备记录，冻结合格共同 cutoff，不倒填获取时间；历史 cutoff 分支不因新增资料自动延后

### Requirement: 每次刷新必须先交付逐项失效与复用计划

刷新 SHALL 生成不可变版本化计划，绑定原/新列表请求、证券身份、cutoff、问题、输入 View/Gate、来源策略与完整模型/Agent/Skill/Schema/Adapter/Risk Policy/数据版本、报告 hash 及依赖；逐任务区分 RUN、REUSED、BLOCKED、REMOVED、NOT_REQUESTED 与原因。资料获取、报告机械有效性和研究内容裁定 MUST 分开。只有严格通过现有准入、完整报告闭合及当前语境兼容的产物才能 REUSED；错误/失败原件不得当内容通过缓存。变更按实际依赖最小失效闭包传播，新增证券不使无依赖旧证券全部失效，删除只退出当前任务，不删除历史；资料/cutoff/模型/Skill/Schema/依赖变化不能按 ticker 或文件存在误复用。计划先于执行，LLM 不选择缓存、修改数据库或推进 checkpoint。

#### Scenario: 列表只增一只且旧输入完全兼容
- **WHEN** 固定 cutoff/资料/问题/版本/依赖均未变，只新增一只受支持股票
- **THEN** 未受影响旧任务重验后可复用，只新增该证券及实际共享依赖失效任务；记录准确调用差额，不无条件全链重跑

#### Scenario: 删除或调换顺序
- **WHEN** 删除一项或仅改变列表顺序，剩余研究语义和有效输入未变
- **THEN** 删除项在当前计划记录 REMOVED、旧成果仍可读；顺序变化只改变显示映射，不凭顺序使所有报告失效

#### Scenario: 新 cutoff 和行情改变
- **WHEN** 刷新推进共同 cutoff 或所需行情窗口/来源版本发生变化
- **THEN** 对受影响报告与消费者记录失效/新研究或合法确定性重验理由，不把旧时点报告当作新时点综合；不可安全迁用时拒绝复用，不承诺所有维度免跑

#### Scenario: 一份依赖正文或版本变化
- **WHEN** Company/Fundamental 内容/hash 或研究版本变化且后续任务依赖它
- **THEN** 失效传播到实际消费者及最终综合，独立无依赖任务按自己的输入重验；独立首轮 Skeptic 的隔离和版本证明单独检查

### Requirement: 列表执行必须共享有界调度且阶段授权不得扩散

系统 SHALL 沿现有主线程 Company、多维、独立 Skeptic 和研究级 CIO 入口消费计划，批次共享并发/调用/时间及可观测 usage 上限，阶段与子任务不得各自获得整批额度。派发前显示获批范围、波次、准确父/子计划、实际阶段 timeout/总预算及停止条件；状态来自 repair-single-stock-evidence-consumption 的可信事件/固定 deadline 接缝，包含最后有效事件、依赖阻塞与剩余预算。只研究 Company 的请求 MUST 不自动启动多维/Skeptic/CIO/Risk；完整研究综合需要对应阶段明确授权，无账户和持仓研究综合均仅 RESEARCH_SYNTHESIS、账户适配未评估、Risk=NOT_RUN，无交易动作/仓位/金额/数量。输入数量不是并发额度，不新增 Agent 或第二调度器。

#### Scenario: 多股票多维任务同时就绪
- **WHEN** 不同证券有多个无依赖研究任务可以派发
- **THEN** 在同一批准并发额度内透明分批，不按股票数乘维度数各开满额；任务完成补位，真依赖阻断不占永久等待槽

#### Scenario: 仅批准 Company 阶段
- **WHEN** 用户只授权列表 Company 研究
- **THEN** 停于 Company 报告及完整覆盖索引，不自动借列表授权推进 Skeptic、CIO 或完整组合流程

#### Scenario: token 只有结束后可见
- **WHEN** 模型只在结束事件提供 usage
- **THEN** 列表显示 usage 的部分/未知覆盖并使用已冻结调用/时间约束，不承诺在途硬 token 上限；已观察额度耗尽不追加派发

### Requirement: 局部失败必须隔离且恢复不得丢失已完成成果

单项来源、身份、执行、契约或内容失败 SHALL 保留原产物/事件并仅阻断实际消费者；无依赖任务在批准剩余预算内继续。共享库不可安全使用、状态不可可信或全批预算/中断等共同故障 MUST 停止受影响批次，输出原因及真实覆盖，已提交数据/checkpoint、合法报告和历史原件不回滚。每项执行/保存/内容状态 MUST 独立显示，批次不得以多数成功冒充全完成；PARTIAL/FAILED/BLOCKED/NOT_STARTED 不可改成成功。恢复 SHALL 由显式新请求/授权触发并重验原锁、PIT、允许集、报告/hash和依赖，只计划必要闭包，不重复已合格任务、不自动续额/换模型/追加修订。

#### Scenario: 一证券失败但另一已完成
- **WHEN** A 的 Fundamental 超时、B 已有合法报告且 C 无依赖可运行
- **THEN** 保留 B 原件和 A 失败，A 的实际消费者阻断，C 仅在剩余批准预算内推进；批次显示局部结果，不整批重跑

#### Scenario: 预算在下一波前耗尽
- **WHEN** 全批调用/时间或可确认 usage 达到批准上限
- **THEN** 不启动下一波，保留已完成、失败及未执行项和停止原因；新运行另获授权后严格重验，不把 pending 删除来伪装完成

#### Scenario: 恢复时旧依赖发生漂移
- **WHEN** 原完成报告或依赖产物 hash 变化，或缺必要长期对象
- **THEN** 拒绝该项复用并指出最小重验/重做闭包，原失败/旧hash保留，不手工混拼报告或降级 Schema

### Requirement: 列表完成必须分别证明两种模式及刷新行为

本 Change 验收 SHALL 交付持仓与无账户自选股两个模式的输入/覆盖/身份/运行包接缝，以及无变化、增删、资料更新、版本变化、局部失败、预算到期和显式恢复的确定性矩阵。受控样本 MUST 标零模型/合成，不冒充真实外部资料更新；受影响产品启动/加载和研究综合必须另获两类列表具体样本、完整版本锁、数据/模型预算及停止条件批准后取得真实宿主执行证据和独立内容核对。真实有界无变化刷新须证明重验/复用与实际调用，而非只统计索引数量；资料更新可用明确受控样本补机制证明，不等待外部自然更新或宣称已发生。没有真实范围授权须保留未完成，ALB 单次成功、历史 MRVL PASS 或前置 Change 完成均不替代本验收。独立裁定与人工最终批准后才收尾，不自动运行专项 Eval/Replay 或 Promotion。

#### Scenario: 合成列表矩阵通过但无真实批准
- **WHEN** 两模式和故障矩阵通过确定性检查，尚未批准本次真实列表运行
- **THEN** 报告实现/机制证据有效、真实执行与内容验收待完成，不启动模型或回签真实 PASS

#### Scenario: 只有持仓模式通过
- **WHEN** 持仓列表已验证，但无账户自选股输入或刷新仍失败
- **THEN** 本 Change 尚未完成，不将范围缩为持仓或只交付单股报告后归档
