# 交接开发

## 从实际交接开始

读取当前目标、相关输入输出契约及生产者/消费者实现；已有失败时只取定位该交接需要的原稿、收据或错误。沿一条实际路径确认“谁生成→谁装配→谁校验→谁消费”，不要仅凭两端同名字段判断接通。

对受影响字段区分：需要模型判断的内容与引用选择、程序可从可信记录取得的身份/版本/hash/路径、外部输入及其验证。模型仍负责选择支持主张的资料，程序只精确装配其已选对象，不替模型补选证据或改写结论。复用当前提交与校验边界，不为每个失败另造协议或调度器。

## 观察、区分、处理

| 观察 | 先区分什么 | 最小处理 |
|---|---|---|
| 计算收据成功，输出却缺字段 | 原稿是否符合当前提交契约；字段是否在装配/运输中丢失 | 对照原稿、收据、装配输入输出及首个消费者；修正确认出错的一端，不要求模型补造计算或抄hash |
| 两端各自合法，消费者仍拒绝 | 实际版本、字段结构、调用身份与授权范围是否一致 | 检查真实交接而非只测单端；身份冲突保留拒绝，不覆盖为“正确值” |
| 引用未知、来自另一任务或含说明后缀 | 允许对象集合与模型选择是否精确对应 | 保留拒绝，指出具体位置；不猜测、截断、模糊匹配或跨任务借用 |
| ID存在但内容不支持主张 | 期间、单位、原值及文档→主张关系是否成立 | 作为语义问题处理，不以ID合法宣称内容通过，也不由程序换证据 |
| 原始输出存在，正式产物缺失 | 执行成功与收集、装配、持久化是否分离 | 保留原稿，定位第一个失败接缝；有需要才使用项目现有诊断方法，不先重跑模型 |

授权实施时，围绕已定位接缝选择最小依赖范围的确定性正负检查：合法生产者输出能被真实消费者接收，非法引用/身份仍被拒绝。若项目存在多条受影响交付路径，检查它们的兼容性；不要为本任务新增统一重试机制。局部修订沿用入口已有次数、权限及完整重验要求，不能代替原任务明确要求的最终验收。

精简模型输入时优先移除重复机械包装，保留资料目录、实际可读取内容、引用选择和反证；没有实际消费证明，不把“发送了摘要”当作“使用了资料”。测量时区分bytes与token、缓存计量与总输入、父调用与全链路消耗；未测量就不承诺节省。

## 授权与结果

沿用用户当前目标及已有授权。只要求设计/诊断就不修改；已授权修复则继续范围、权限和预算内的实现及聚焦检查，不在每个阶段重复询问。真实越界、关键选择缺失或项目既有最终批准要求才暂停相应动作。此Skill不授予模型运行、发布或安全例外权限。

结果说明受影响交接、字段归属、最小修改、实际验证和剩余缺口即可，不要求另造整套报告。仅解释失败时使用目标项目已有诊断方法；判断验收完成时使用其已有收尾方法，不强制调用其他Skill或读取所有流程。

## 本仓库适配

以下仅适用于stock_agent；其他项目跳过，依其实际契约和授权工作，不要求创建这些目录或OpenSpec。

- 本仓库实施与收尾遵循[开发指令](../../../AGENTS.md)及按需读取的[开发流程](../../../docs/development/workflow.md)，不新增批准步骤。
- 从[Runtime入口](../../../product/runtime/cli.py)按当前工作区的真实调用关系定位提交装配、计算交接与引用映射。若存在`research_submission.py`、`calculation_handoff.py`或`multidimensional_references.py`等专用实现，再进入对应文件；不把源码名称当作功能已启用的证明，也不固定协议版本或认定所有入口均已迁移。
- 保留Evidence/PIT/Risk与角色信息隔离；不修改历史证据和版本锁，不把开发Skill当作CIO或投研方法。真实产品补跑仍遵循已授权范围及宿主入口，确定性检查不能冒称研究质量验证。
