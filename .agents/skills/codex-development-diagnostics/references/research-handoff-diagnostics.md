# 研究交接诊断：仅在该分支按需读取

本参考属于stock_agent开发控制面，不是产品研究方法或通用版本注册表。只读取当前授权运行、声明依赖和定位失败所需的源码；保持诊断只读。先明确失败的交接与实际消费者，再取对应输入、原稿、收据、错误或输出，避免全链路日志扫描。

## 从原始材料区分问题

| 类别 | 对照材料与关键区别 | 下一项最小动作 |
|---|---|---|
| 结构 | 当前提交Schema、原始草稿、首次校验错误 | 定位具体字段及提交/装配边界；有真实计算收据不等于草稿结构正确 |
| 引用 | 本任务允许的对象、精确映射、草稿选择 | 检查未知、跨任务或带说明后缀的引用；不截断、不猜选、不借另一任务对象 |
| 身份/权限 | 调用上下文、入口授权、可信装配记录 | 区分“目标任务合法”与“调用方获准”；不覆盖冲突身份，不扩大权限来绕过拒绝 |
| 执行 | 原始命令/工具事件、进程结果、阶段记录 | 区分未执行、执行中断、工具错误；shell退出0或只有prepare不证明研究完成 |
| 收集/装配 | 原始输出、提交收据、Hook/装配事件、正式产物 | 输出已产生但未落入正式报告时先定位丢失处；保留原稿，不自动重复模型调用 |
| 来源 | 获取记录、准入结果、实际交付、工具查询与引用 | 数据未取得、被Gate排除、未交付、交付未读取、读取未正确引用分别报告；不混称“数据不足” |
| 语义 | 文档正文、期间/单位/原值、来源主张和结果主张 | ID存在不等于支持关系成立；程序不能换证据或改写研究意义来消除错误 |

只有同一输入在某阶段前后的材料足以比较时，才认定首处分歧。第一条stderr异常未必导致当前失败；证据不足时写明未知和所缺片段，不笼统归为模型非确定性。

## 必要时定位当前实现

- 提交、计算和引用：从[Runtime入口](../../../../product/runtime/cli.py)及[研究阶段](../../../../product/runtime/multidimensional_stage.py)沿当前工作区实际调用定位。若专用实现`research_submission.py`、`calculation_handoff.py`、`multidimensional_references.py`存在，再按失败分支进入对应文件；名称不证明它已交付或启用，不依赖其他未提交Change才能使用本参考的方法。
- 收集与Hook：[codex_hook_recorder.py](../../../../product/runtime/codex_hook_recorder.py)；实际消费者按当前入口调用关系继续定位，不预设所有研究阶段采用同一协议。
- 文件与对象一致性问题才读[hashing.py](../../../../product/runtime/hashing.py)及对应调用方，核对序列化、hash种类和算法；不试算不同算法挑一个能通过的值，不重签历史包。

这些是源码定位，不是“文件存在即能力已运行”的证明。实际加载/消费须有对应输入、事件或产物；无关分支不必打开。协议版本、状态和局部修订次数从当前实现及获授权任务读取，不在本参考固定一套。

## 收束诊断

报告`FIRST_DIVERGENCE`、有依据的`ROOT_CAUSE`或证据不足、必要材料位置及最小后续动作。仅相关时附完整hash，不复制私人日志、凭据或全量对象表。来源限制、执行失败、研究充分性、格式建议分别记录；确定性检查不能证明研究质量。

已授权修复由原实施流程继续，不重新索取同一授权；仅诊断时不修改。局部处理沿用入口既有次数与权限，保留原失败证据并遵守原最终验收要求；不会自动补跑产品、建立新沙箱或扩大为全量Gate，也不能放宽Evidence/PIT/Risk。
