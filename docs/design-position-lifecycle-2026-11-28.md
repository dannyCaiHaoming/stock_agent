## 1. 背景：为什么换决策单位

**已有事实**（`docs/roadmap.md`“已验证的结论”）：大盘股 60 日方向判断在消融、A/A'/C、方案 D 中都约等于抛硬币；买入侧没有信号通过事先登记的检验；唯一通过的是 terra 消息面归因（公司坏消息后继续跑输板块，防守侧）。

**外部证据**（方向研究，可信度 A/B 的部分）：
- 九成大盘主动基金 15 年跑不赢 S&P 500（SPIVA）；大盘股 PEAD 2006 年后基本消失（Martineau）；LLM 交易框架在长样本、计成本后没有显著 α（FINSABER、StockBench）。单股大盘 60 日相对板块，是最难的一格。
- 可核实的优秀交易者优势不在胜率：Qullamaggie 自述胜率约 25–30%，Minervini 约 45–55%，靠“小亏截断、赢家拿住、熊市降仓”。台湾扣费后持续盈利的日内交易者不到 1%，巴西坚持 300 天以上的 97% 亏损。A 股游资的收益依赖涨跌停、T+1 与龙虎榜注意力，不能移植到美股。
- 止损只有在存在动量或状态切换时才有正价值，随机游走下止损降低收益（Kaminski & Lo）。所以“挑对情形”比“设止损”更重要。

**诊断：问题在决策单位、问题和指标，不只在模型。**

| | 现在（decision-card） | 优秀选手 |
|---|---|---|
| 决策单位 | 某一时点的一张卡，固定 20/60 日结算 | 一笔交易的完整周期：计划、进场、复核、加减、离场 |
| 问的问题 | 会不会跑赢（概率） | 错了最多亏多少；什么事实说明我错了；什么事实值得加 |
| 衡量 | 方向准确率、平均超额；HOLD 记 0 | 整笔净损益、R 倍数、平均盈/平均亏、最大单笔亏损 |

固定窗口的卡片无法表达“早砍”，也无法表达“让它跑”。

## 2. 目标

> 用户考虑一笔普通股交易时，Agent 帮他在进场前写下**可核实的理由、放弃理由的事实和预算亏损**；之后每出现新的公开事实，Agent 回到原文判断理由是否还成立，再给出持有、减仓或离场的建议；结束后能按原计划手算出这笔的净损益和 R。

产品承诺分三层，按阶段兑现，不提前宣称：

| 层次 | 承诺 | 何时 |
|---|---|---|
| 可用 | 用户能照原计划完成一次真实事件复核，并复述失效条件 | L1 |
| 行为 | 计划被事先留痕、建议可追到原条件、复核结论稳定、用户负担可接受 | L2 |
| 经济价值 | 照计划管理，扣费后优于同入场的持有对照和简单退出对照 | L3 有结论后才能宣称 |

**非目标**：方向预测、因子选股、自动交易、订单、真实账户写入、组合优化、期权、新 Agent、通用回测平台或参数网格。

**即使程序能运行也算失败的情形**：
- 计划在看到结果后被改写，或 R 的分母可被事后调整；
- 只统计成交并已平仓的交易，WAIT、未成交、仍持有的被排除；
- 复核结论随价格涨跌改变，却指不出新的公开事实；
- 失效条件写成“趋势坏了”这类无法核实的话；
- 私人账户的逐笔流水、账户号或凭据进入模型上下文或仓库。

## 3. 整体设计

### 3.1 生命周期与职责

```
候选登记 → 计划（冻结）→ 模拟/真实成交 → 复核（事件触发，可多次）→ 离场/期末估值 → 结算与复盘
```

| 环节 | 谁 | 做什么 |
|---|---|---|
| 候选登记 | 用户提出，工具记录 | 用户提交的机会先登记，在看到结果前写下状态（见 3.4） |
| 计划 | Agent 判断 | 按一张模板写论点、市场错在哪、催化剂、**放弃理由的事实**、价格失效位、持有依据、复核日 |
| 风险算术 | Python | 由参考入场价、失效价、风险预算算出计划股数与 R0；不做任何判断 |
| 成交 | Python | 纸面按决定后下一常规交易日开盘、预设费用；跳出入场区间记未成交 |
| 复核 | Agent 判断 | 两步法（见 3.6）：先判论点，再看价格与动作 |
| 结算 | Python | 整笔净损益、R、两个对照的配对差（见 3.7） |
| 复盘 | Agent 写 | 是否按计划、偏离原因、单例教训（标 n=1 与结果已知日） |

规则只做风险算术、成交模拟和“哪条条件被哪份公开材料触发”的事实提示；论点等级、动作建议全部由 Agent 判断，判断在结果出来之前写下。

### 3.2 交易计划记录 `plan/v1`

只追加；每次开新仓取得独立 `plan_id`，同股重新开仓是新计划。首期只做**普通股多头、一次建仓**，加仓在 L2 之后再开放。

冻结字段（首笔成交前写定，之后不可改）：
- `plan_id`、`ticker`、`template`、`decided_at`、`frozen_at`、`source`（on_demand / candidate_batch）、`model`（由运行脚本写入，不由模型自报）、`code_version`；
- `thesis`、`market_misread`、`catalyst`；
- `abandon_facts`：至少一条“下一次哪份公开材料中的哪项事实，会让我放弃这个理由”，例如“下期业绩公告下调全年收入指引”；
- `price_invalidation`：初始失效价；
- `entry`：参考入场价、允许成交区间；
- `risk_budget`、`shares_planned`；
- `hold_basis`：继续持有的依据；`review_dates`：到期复核日；`horizon_cap`：计划最长持有期（用于对照）；
- `cash_destination`（cash / sector_etf）。

**R 的定义**：`R0 = (参考入场价 − 初始失效价) × 计划股数`，必须为正，冻结后不变。成交偏差与跳空进入损益，不改 R0。例：计划 100 股、参考价 100、失效价 95，1R = 500；跳空后在 90 离场，记 −2R 再减费用。卡上写“预算亏损”，并说明跳空可能超出预算。

**版本**：新事实可以改变之后的动作，以追加版本实现：`version`、`effective_at`、`reason`、`sources`、改了哪些字段。历史按当时有效的版本复算。放宽止损会压低亏损 R、收紧止损会放大盈利 R，因此结算同时报告净收益率、止损距离分布和风险预算占比，并始终与初始计划对照。

### 3.3 计划模板

一张计划只用一张模板，模板来自现有交易者卡（`product/references/methods/trader-*.md`），只取与本机会吻合的一张，写明“经验，未验证”。候选模板（用户在 §8 选 1–2 个）：

| 模板 | 来源 | 必答问题（在通用必答之外） |
|---|---|---|
| 催化跳空 | Qullamaggie EP、Balder 跳空后看开盘低点 | 催化是否改变了经营预期；跳空日开盘低点是否守住 |
| 强势突破 | Minervini 第二阶段、Labubu 确认后加 | 是否在当前主线、是否领涨；突破前的平台与成交量 |
| 趋势回踩 | Labubu 回踩关键均线分批 | 趋势是否未破；回踩的原因是公司还是大盘 |
| 错杀买入 | Ryan Leung “原因不在经营就分批” | 下跌原因是否确实不在经营；有无可核实的经营事实 |

通用必答：放弃理由的事实（具体到材料与事项）、价格失效位、持有依据、复核日。“趋势坏了”这类无法核实的条件退回重写；经营数据暂缺时写“未知”，不编造。

### 3.4 候选分母与成交口径

- 事先固定候选入口：例如用户连续提交的第一批合格机会。每个候选在看到结果前登记为 `wait`、`not_formed`（计划不成立）、`pending_fill`、`unfilled`、`abandoned`、`open`、`closed` 之一。这个分母只代表用户提交的机会，不代表市场。
- 建议、用户选择、成交分开记录；多次部分卖出合并为一个持仓周期；期末仍未平仓的单列，按统一截止日收盘估值。
- 纸面：决定后下一常规交易日开盘、预设费用；收盘才看到跌破的，不能假设当天按阈值价卖出。真实：实际成交与费用，与纸面分开报告。

### 3.5 Agent 的位置：判断与算术的边界

| Agent 负责 | Agent 不负责 |
|---|---|
| 读公告、新闻、指引，判断催化是否真实、下跌是公司还是大盘 | 给方向概率当买入理由 |
| 写论点、放弃理由的事实、持有依据 | 选择 R0 的计算方式、改冻结字段 |
| 复核时判断论点“增强 / 不变 / 动摇 / 已坏”并建议动作 | 决定何时被叫醒（由用户或事实提示决定） |
| 用用户听得懂的话解释 | 编造期望收益或胜率 |

### 3.6 复核两步法

1. **论点**：只给原计划原文和截至复核时已公开的新材料（带发布时间），不给价格。逐条引用原条件、证据、发布时间与冲突，写出论点等级。
2. **动作**：再展示当时价格、板块与大盘表现、可执行动作，给出持有、减仓或离场建议。价格本身就是原条件时，在这一步核对。

这样能查出“因为亏了，所以说公司逻辑变差”的倒推。复核结论与上一版相反却指不出新证据时，展示分歧，由用户决定；不靠连续重跑挑结果。

**稳定性**：同一份冻结证据包、同一模型做两次独立复核，分别统计论点等级翻转和影响仓位的动作翻转（L2 抽 10 个包）。两次一致也可能一起读错公告，所以抽查原文仍要做。

### 3.7 结算与对照

每个成交计划同时算三条线，使用同一入场、同一初始仓位、同一成本与资金去向：
- **照计划**：按版本链实际的离场；
- **持有对照**：持有到 `horizon_cap` 截止；
- **简单退出对照**：只按初始失效价离场，其余持有到截止。

配对差拆为“提前离场避开的跌幅”和“错过的涨幅”，并报告换手、净成本和重新进场次数（无趋势的来回波动会让价格止损反复卖低买高）。按事后赢家统计持有天数只作描述，不作判据。

### 3.8 事实提示（L2 起按需，不是编排层）

需要时由确定性脚本每日输出“哪条计划条件、被哪个公开来源触发、何时首次可见”：价格触及失效位或复核日到期、新 8-K（按 accession 去重）、`classify_decision_event` 的 E1/E2 事件。缓存陈旧要显示为覆盖缺口。脚本不决定论点等级与动作，也不循环调用模型；复核由用户或宿主会话发起。

### 3.9 隐私

- L1、L2 只做纸面计划，暂不接 Tiger。
- 真实账户接入另需用户授权；接入时私账只在本机私有目录（`product/.private/`）计算，凭据、账户号、逐笔流水不进模型、不进仓库。单笔 R 配日期与代码可还原持仓，默认只在本机展示；需要模型解释时，经用户授权只给跨多笔、去标识的汇总。
- 历史成交只能描述换手、持有时间与净损益，并注明缺费、缺期初仓位、无法配对的笔数。历史交易没有事前风险预算，**不能算出可比的 R，不作改造前基线**。

| 已有 | 新角色 |
|---|---|

| `classify_decision_event`、`get_key_moments` | 事实提示与复核背景，不再定死窗口 |

## 4. 与 Decision-First 和 P2 的关系

- **P0、P1 成果保留**：协议 v1、`decision/v2`、开盘口径分布、`score-decisions.py`、decision-card 继续可用，也是本设计的复用基础。P1 第二版盲读的用户结论仍待记录。
- **P2 协议 v1 保留、独立计分、暂缓开跑**。它衡量的是 E1/E2 事件上“减半 vs 不动”的行动增益，HOLD 记 0 准确表达“相对继续持有的增量”；生命周期另算整笔绝对损益。两者合并会同时改变人群、成交路径与问题，所以不合并。生命周期记录不写成 `scan`。P2 开工前仍须完成的事项（SEC 列表 `checked_at` 显示、S&P 500 与板块映射快照、扫描脚本、出处由脚本写入、调度）见 handoff；是否开跑由用户在 L1 之后决定（§8）。
- 前一路线的“继续调 60 日方向提示词”“旧前瞻定时”保持停止。

| 阶段 | 交付 | 完成判据 | 预算 | 停止规则 |
|---|---|---|---|---|

| **L2 执行行为** | 连续 20 个候选或 8 周先到即停；按需加事实提示脚本；抽 10 个证据包双跑 | ≥ 90% 候选有事前留痕；所有改变仓位的建议能追到原条件或明确记录的计划偏离；报告用户遵守率、每周阅读耗时、无新信息提醒占比 | ≤ 60 次模型调用 | 10 对双跑中出现 ≥ 2 次相反动作：暂停扩展，先查证据提取或条件歧义。几十笔只能发现漏记、噪声与负担，不能据此宣称盈亏比改善（20 次中 16 次遵守，Wilson 95% 区间约 58%–92%） |
| **L3 经济价值** | 事先登记：同机会、同入场、同初始仓位的持有对照与简单退出对照，扣费后配对净值差；真实账户另报采纳率与成交偏差 | 先写最小有用差异，再用 L2 配对差的波动与同周相关估算样本量和预算 | 由登记文件定 | 预算达不到所需精度：停在“行为工具”；到期区间仍跨零与最小有用差异：报告“证据不足”，不延长收样 |

## 6. 已知风险与未验证假设

- **Agent 能否挑对情形没有证据**。止损只在有动量或催化时有正价值；如果 Agent 挑不出真催化、真主线，计划管理只会带来纪律，不会带来收益。
- 短期最可能先看到“少亏”（纪律），“多赚”要到 L3 才能判断，可能是“证据不足”。
- 用户负担：写计划、读复核需要时间；L2 记录每周阅读耗时，负担过重就简化模板。
- 运行间概率约 5pp 的波动不能直接换算成论点等级的翻转率，要在 L2 实测。
- 历史回放只能验证时间与数据隔离：训练截止后的样本也可能通过之后的新闻、案例卡或旧报告泄漏。回放须冻结输入包与发布时间，并放一条次日材料检验它被排除。

## 7. 否决与延后

| 项 | 处理 | 理由 |
|---|---|---|
| 纯规则的水温开关、行业轮动、机械止损作为主线 | 否决（用户 2026-11-28） | 用户不要机械化的因子控制；它们最多作为卡片背景，不单独立项 |
