# 项目审查与 CIO 回放评估（2026-11-11）

范围：代码与目录现状、2026-11 的三轮 CIO 回放（方案 A、A'、C）的设计与结论、提高判断有效性的建议。
本文只有审查结论与建议，没有修改任何规则、方法卡或代码；建议项都待用户确认。
核对脚本与明细在 `.local/scratch/review-2026-11-11/`（`verify.py` 读已有回放决策与价格缓存，`reach.py` 做 import 可达性分析）。

## 一、结论摘要

1. **到目前为止，没有任何证据表明这套流程有选股优势。** 27 样本对照实验、三轮 31 只回放都没有超过简单基准。这不是“还差一点调优”，是“还没有量到信号”。
2. **NO_TRADE 占九成的直接原因已经确认，是情景估值的写法。** 84 份可解析的情景表里，65 份的“中性情景”本身就是负回报。期望回报衡量的是“一年后的基本面价值缺口”，却被当成 60 日动作的门槛。
3. **方案 C 的“主升日有排序能力（0.48）”证据不足。** 放到板块内只剩 0.23，主要是押对了板块；31 只股票只有 6 个板块，有效样本接近 6。
4. **评估方法本身是瓶颈。** 每个数据点要一次约 10 分钟的完整研究；31 只同一天、同一批高位股，测不出 5 个百分点量级的优势。唯一干净的前瞻账本从 10-27 起只跑过一次。
5. **仓库里研究 Agent 实际用到的 Python 约占四成。** `product/` 下 31.9k 行，MCP server 可达 13.1k 行；其余是暂缓阶段的独立模块和瘦身后没清完的旧代码。

## 二、CIO 回放：核对结果

数据：A'（2026-07-17，tag `stressB`）、C 主升（2026-04-17）、C 震荡（2025-10-23），各 31 只，Codex `gpt-6-luna`。
“组内超额”= 个股之后收益减 31 只同日平均。

### 1. 负期望来自情景表的结构，不是概率

| | 回调 07-17 | 主升 04-17 | 震荡 2025-10-23 |
|---|---|---|---|
| 情景表可解析 | 28/31 | 29/31 | 27/31 |
| 低 / 中 / 高情景相对现价（中位数） | −62% / −20% / +30% | −56% / −14% / +33% | −63% / −7% / +36% |
| 中性情景为负 | 24/28 | 22/29 | 19/27 |
| 主观概率（低/中/高，中位数） | 30/50/25 | 25/50/25 | 30/45/25 |
| 三情景等权时期望为正 | 4/28 | 7/29 | 8/27 |

- 三种行情下形状几乎一样：下行约 −60%，上行约 +33%，中性已经为负。即使把概率改成等权，期望为正的也只有 19/84。问题在情景的取值，不在概率。
- 具体例子（主升日）：AMD 现价对应 P/E 约 105 倍，中性情景用 40 倍 EV/EBIT；ALAB 现价隐含约 71 倍，中性情景用 50 倍。中性情景等于“一年内倍数压缩三到四成”。
- 两个成因：
  - **期限不一致**：情景用下一财年收入 × 利润率 × 倍数，是一年以上的基本面价值；动作的主窗口是 60 个交易日。报告自己也写“这不是 60 日价格目标”，但规则要求 `风险收益不对称` 由期望回报 ≤ 0 支持，BUY 触发时要求期望回报为正。
  - **方法卡措辞（待验证）**：`implied-expectations` 的“常见误用”第一条是“中性情景沿用现价隐含倍数，于是没有上行”。模型很可能因此在中性情景里主动下调倍数。只截取一年的收入，对高增长公司也天然偏低。
- 中性情景回报与之后 60 日组内超额的秩相关：−0.01、0.34、−0.11。没有稳定的信息量。

### 2. “主升日有排序能力”主要是板块效应

特征与之后 60 日组内超额的秩相关，写作“整体｜板块内”（板块内 = 两边都减去板块均值）：

| 特征 | 回调 07-17 | 主升 04-17 | 震荡 2025-10-23 |
|---|---|---|---|
| CIO 方向概率 | −0.06｜0.06 | 0.47｜0.23 | 0.36｜0.26 |
| CIO 期望回报 | −0.12｜−0.05 | 0.41｜0.01 | −0.05｜−0.16 |
| 之前 60 日涨幅 | 0.31｜0.26 | −0.24｜−0.38 | 0.64｜0.45 |
| 之前 126 日涨幅 | 0.31｜0.14 | −0.17｜−0.26 | 0.49｜0.25 |
| 距 252 日高点 | −0.12｜0.10 | 0.02｜−0.38 | 0.41｜0.39 |

- 主升日 0.47 降到板块内 0.23；期望回报从 0.41 降到 0.01。n=31 时秩相关的抽样误差约 ±0.19，0.23 与 0 无法区分。
- 主升日的得分来自“半导体、储存给高分，太空给低分”，这两组之后组内超额 +43、+42，太空 −32。这是 6 个板块的一次排序，不是 31 次独立判断。
- 对 CIO 有利的一点：主升日的方向判断不是简单追涨，当天所有动量特征都是负相关。
- 对 CIO 不利的一点：震荡日“之前 60 日涨幅”一个特征（0.64）就超过了 CIO（0.36）；回调日 CIO 为零。
- 简单特征的符号在三个日期之间来回翻转。单一日期的结果由当天的板块轮动决定，一个日期只能算一个观测。
- 三个日期合并后（93 个预测、18 个日期 × 板块，`scripts/score-group-forecasts.py`）：CIO 方向概率的板块内秩相关 0.22，之前 60 日涨幅 0.09；命中 45/78；逐个（日期 × 板块）的秩相关均值 0.12，为正 10/18。有微弱的正向迹象，但只有 3 个日期，其中一个可能在模型训练数据内，不足以下结论。

### 3. 设计上的问题

| 问题 | 影响 |
|---|---|
| 31 只按 2026 上半年涨幅选出，三轮都用同一批 | 名单本身含未来信息：主升日之后 60 日里约 50 日落在选股窗口内，绝对收益被抬高；结论只适用于“高位股” |
| 每轮一个日期、6 个板块 | 有效样本接近 6；命中率 61% 对 65% 的差距没有意义（n=31 时误差约 ±9 个百分点） |
| 口径不统一 | 预测目标是“126 日相对板块 ETF”，A' 按“60 日相对 SPY”评，C 按“60 日组内超额”评，主窗口写 60 日 |
| 对照只有“一律猜多数” | 没有与价格特征对比，分不清 CIO 的得分是判断还是动量或板块 |
| 规则在看到结果后修改 | 计划写“不用这批结果调参数”，但 7b9a199、14e91d2 都是看了同一批股票的结果后改的 CIO 规则，之后又在同一批股票上重跑；`investment-decision` 里还直接写入了“35 次决策 34 次不是 BUY” |
| 修改前后混有模型差异 | A 主要是 Haiku，A' 是 luna；同模型对照只有 8 只 |
| 回放日期在模型可能知道的范围内 | “不得使用记忆”无法强制；2025-10-23 尤其可疑 |
| 每个数据点成本高 | 一次完整研究约 10 分钟、约 $0.9（Haiku），只换来一个二元方向判断 |

做得对、应保留的部分：运行前登记、失败不补选、NO_TRADE 也记录、报告冻结副本、如实写“小样本不做显著性结论”。

### 4. 前瞻账本与每日采集没有持续运行

- `evals/forward/ledger.jsonl` 只有 5 行：10-26、10-27 各一次选股，3 条预测。v2 改为每周五运行后，11-06 那次没有记录。
- 分析师预期与社区快照缺 2026-11-02 至 11-06 整周（`.local/data/history/estimates/` 只有 12 天）。
- roadmap 把前瞻账本称为“唯一干净的检验来源”，P1 把预期快照称为“越早开始越有价值”。这两件事的优先级应当高于再做一轮回放。

## 三、建议：怎样才可能提高胜率

先说明边界：现有证据不支持“改几条规则胜率就会上去”。下面的建议是让系统先能量出优势在哪里，再把资源集中过去。

### 建议 1：先定义“胜率”，统一成一个口径
- 主指标：方向判断的命中率与秩相关，目标为“之后 60 个交易日相对板块 ETF 的超额”，按日期、按板块分层报告。126 日作辅助。主窗口本来就是 60 日，反馈周期也缩短一半。
- 动作指标：BUY 的 60 日相对板块超额均值与为正的比例，对照“同日同板块未选中的股票”。
- 每次评分固定附三个对照：一律猜多数、之前 60 日涨幅、之前 126 日涨幅。CIO 超过它们才算有信息。

### 建议 2：把期望回报从动作门槛里拿掉（需要对照实验确认）
- 情景估值改回方法卡原本的定位：“只衡量空间与仓位”。报告保留“现价隐含了什么要求”，不再用一个点估计的期望回报决定买不买。
- 动作由方向判断与信心决定，估值与拥挤决定仓位大小（试探 / 标准）。
- 如果保留期望回报：中性情景应当锚定“市场隐含预期兑现”（相对现价约 0），上下行表达的是与市场预期的偏离；并删去或改写“中性情景沿用现价隐含倍数”那条误用说明。
- 这是规则修改，要先登记、在**新的日期和新的股票**上对照（有门槛 / 无门槛），不要再在这 31 只上验证。

### 建议 3：改变评估方式——广度优先，轻量预测
要分辨 55% 与 50% 的命中率，大约需要 400 个相互独立的判断。按每周 4 只完整研究，要两年。
- **轻量预测模式**：每周对整个股票池（`universe.txt`，106 只）各出一个方向判断（方向、概率、一句依据），不写完整报告、不启动正反两个子 Agent。对照实验已经表明，流程结构（单人 / 交锋 / 新流程）对方向预测没有可靠影响，评估时不必为它付三倍成本。
- 结果写入现有的前瞻账本（只追加）。一个季度可以得到约 1,300 个前瞻判断、13 个日期，足以按板块内排序评估。
- 完整研究（正反方 + CIO 报告）只用在用户真正要看的股票，以及轻量预测里排名最高与最低的几只。它的价值在解释与风险梳理，不在提高命中率。
- 这只需要一个 Skill 加现有的 `dev-research.sh` / `forward-run.sh` 循环，不需要新的 Python 控制层。

### 建议 4：把研究资源放在 LLM 可能有优势的地方
已有统计的含义：106 只大中盘股上，7 个单一信号、组合叠加、内部人、议员、SUE、宏观、空头拥挤都没有可用的方向优势；有证据的只有两条，都是风险侧（财报大跌后继续偏弱；波动期限结构倒挂后波动更高）。据此：
- **财报事件的文字判断**：读业绩新闻稿与指引，对比上一季的措辞与数字，判断“指引相对公司自己之前的说法是变好还是变差”。这是 LLM 相对规则最可能有优势的环节，也是 roadmap P2 第 6、7 项。前瞻账本 v2 已经优先选财报股，方向正确，缺的是数量。
- **预期修正**：公开文献里最稳定的信号之一，免费数据没有历史，只能靠每日快照自己积累。保证采集不断档比任何调优都重要。
- **回避输家**：现有证据都在下行侧。短期内更现实的目标是“少买错”（财报大跌后不急于接、拥挤加波动上升时降仓位），而不是“挑出最强的那只”。
- **不再为方向预测投入的方向**：增加正反方轮次、扩充 CIO 规则文字、在同一批股票上追加回放日期。

### 建议 5：规则与版本纪律
- CIO 规则里不写入某一轮回放的具体数字；回放教训进案例卡，规则修改走“登记 → 新样本对照 → 冻结版本”。
- 前瞻账本固定用冻结版本运行（目前记录的是运行时的 main），规则变了就是新版本，分开统计。

### 设计上不合理的地方

- **moomoo 五个步骤“必做”，但规则规定“不参与研究判断”。** 每次实时研究都付出时间与失败面，对结论没有作用；回放里又全部禁用，实时流程与被评估的流程不是同一个。建议改为按需调用：用户要看第三方观点时才跑。
- **`investment-decision` 持续打补丁。** 118 行，九个步骤、十三个报告章节，每轮回放后加一段规则。回放表明“规则文字能改变格式，改变不了判断”，继续加条文的边际价值很低。
- **报告章节标题的硬校验。** 三轮回放里 3–5 次首次保存失败来自标题不符，靠整轮重跑兜底。`save_decision` 拒收时已经列出缺少的标题，模型仍会改写章节名；评估用的记录不应依赖十三个章节的完整报告（见建议 3 的轻量模式）。
- **测试套件不能用作回归。** `.venv` 里没有 pytest；用 unittest 跑 757 个测试，41 个失败或报错（18 个是导入已删除模块）。其中 1 个在现行路径上：`tests/test_stock_data_tools.py` 的 `test_signal_stats_only_count_outcomes_known_before_as_of`，`_events()` 的返回值从 2 个变成 3 个后测试没跟上。清掉已删代码的测试后，剩余测试应当全绿。
- **一次性评分脚本放在 `.local/`。** `score-A2.py`、`score-C.py` 是结果文档的依据，但不在仓库里，口径也各写各的。统一进 `scripts/score-forecasts.py`（建议 1 的口径）。
- **PRODUCT.md 与现状不符。** 架构图仍是 portfolio-council、Company Analyst、Market Catalyst、Research Memory、PIT Gate、Risk Engine；实际是 advocate、skeptic、CIO 加 MCP 工具。
