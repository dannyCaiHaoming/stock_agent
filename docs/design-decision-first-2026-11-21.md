# Design Plan：Decision-First 单股决策顾问（2026-11-21）

状态：**已确认**（2026-11-22，§7 按推荐答案定）。可执行的细则以 [决策账本协议 v1](../evals/forward/decision-protocol-v1.md) 为准；两者冲突时以协议为准。

来源：用户与 ChatGPT 的分析 `研究.md`；Claude Code 核对仓库后与 Codex（`gpt-6.2-astra`，只读）进行了两轮讨论，记录在 `.local/runs/design-dialog-20261121/`（`round1-*`、`round2-*`）。本文是讨论后的定稿建议。

---

## 1. 目标

> 给定一只股票、一个决策时点和当前持仓，Agent 每次都给出**明确动作**，并附同一期限、同一口径的概率、收益、风险与改判条件；所有决策进入新账本，用真实前瞻结果衡量“照建议做”是否比“维持现状”和“简单规则”更好。

两条底线：

- **允许不交易，不允许模糊**：WAIT/HOLD 必须写明类型（无优势 / 有判断）、当前承担什么风险、什么事件触发重评。
- **没算出来就留空**：概率、幅度、期望没有可信来源时写缺失，不让 LLM 编造。

产品对用户的承诺分两层，不能混淆：

| 层次 | 承诺 | 何时兑现 |
|---|---|---|
| 决策工具 | 任何覆盖的股票都能得到可读、可复算、口径一致的决策卡，以及“上次决策后什么变了” | P1 结束（约 2026-12 中） |
| 投资优势 | 某类动作扣成本后优于维持现状和简单规则 | P2 有结果后才能宣称；在那之前卡片写“尚无前瞻验证的优势” |

## 2. 讨论结论：对 `研究.md` 的取舍

| 研究.md 的主张 | 结论 | 理由 |
|---|---|---|
| 不再以预测方向为目标，改为决策与交易结果 | **采纳** | 与 2026-11-11 以来的方向一致 |
| 历史/前瞻/评分三种成交口径要统一 | **采纳，已核实** | `key_moments.outcome` 用次日收盘；`evals/forward/README.md` 用次日开盘；`score-forecasts.py` 用当日收盘 + 63/126 日 |
| 删除“跑赢→默认 BUY”和 `p > 0.5` 强制 | **采纳** | 今天 a9bde3c 已去锚，但 `investment-decision/SKILL.md` 第 28、64、83、128–129 行仍在 |
| 用 key_moments 的历史分布作为收益分布来源 | **部分采纳** | 多数图形之后的分布与任意一天无差别（`distribution-latest.md`），只能当**风险基线**，不能当优势来源 |
| 期限由 Agent 按事件“auto”选择 | **改为事先冻结映射表** | 让 LLM 选期限，等于给了事后挑期限的自由度；PEAD 大跌组 20 日相对 ETF −0.24pp，60 日却是 +3.08pp，期限选错会把结论翻过来 |
| Python 用 p × avg_gain − (1−p) × avg_loss 计算期望 | **修正** | 只有概率与幅度来自同一收益变量、同一人群、同一期限、同一入场价时，乘加才成立。LLM 的 p 与历史幅度来自不同条件，不能相乘；同一批样本的期望直接取逐笔均值 |
| Advocate / Skeptic / CIO 按需调用 | **采纳，轻量路径作默认** | 消融显示完整流程不改善方向判断；每次 5–6 分钟，常把额度打满 |
| 约 100 个事件作首轮正式检验 | **修正** | 60 日超额收益单事件标准差约 19pp（9,126 个事件实算）。即使 terra 低档效应为真，100 个事件里约 11 次减仓，检出概率也只有 39–55%；80% 功效约需 165–255 个事件 |
| “读取上一份决策，回答什么变了” | **采纳，最小版本放进 MVP** | 不依赖收益结果，就能让 WAIT 有后续 |
| 自动监控 | **推迟到 P3** | P2 的每日扫描只服务实验分母，不向用户推送 |

`研究.md` 没有提到、但讨论中确认的问题：

1. **唯一通过登记检验的信号属于防守一侧**。terra 消息面概率（Q1 秩相关 +0.28；Q3 向下偏离中公司原因比非公司原因低 11.4pp）的低概率档 11 个全是财报与指引。买入侧没有任何通过检验的信号。
2. **PEAD 数字的口径**。−1.07pp 是相对同日对照池；个股减板块 ETF 只有 −0.24pp，扣 0.2pp 成本后机械减仓几乎为零。所以防守价值几乎全部押在“LLM 能否从偏离事件里认出真正的公司坏消息”。
3. **要冻结三个时间**：事件发生、决策写入、可模拟成交。周五批量回看周一事件时，成交只能锚在周五决策之后的开盘。
4. **回撤有两个定义**：`key_moments` 是“相对入场价的最低收盘”，`score-forecasts.py` 是“窗口内峰值到谷底”。两者要分开命名。
5. **概率语义**：旧记录的 `p` 是“所选方向”的概率（0.55 跑输 = 0.45 跑赢），新记录统一存单向 `p_outperform`，允许等于 0.5。
6. **前瞻分母**：要保留入选清单、失败、迟到、不可成交、缺价；用户主动查询的股票有选择偏差，与规则扫描分开报。

## 3. 设计

### 3.1 两种入口，同一条决策链

| 入口 | 谁触发 | 进入哪里 | 用途 |
|---|---|---|---|
| 按需决策卡 | 用户：“INTU 我持有，该怎么办” | 用户历史，不进主实验样本 | 日常使用 |
| 规则扫描（P2） | 每日扫描，按事先条件全收 | 新决策账本，进入主实验 | 验证优势 |

### 3.2 轻量决策链（默认）

```
输入契约 → 确定性取数 → 事件分组与固定主窗口 → [满足偏离条件才] 消息归因 → 行动比较 → 决策卡 → 记录
```

1. **输入契约**：`ticker`、`as_of`、`position`（not_held / held + 股数、成本，可选）、`cash_destination`（cash / sector_etf，默认取用户设定）。成本价只用于展示浮盈亏，不进入判断。
2. **确定性取数**（Python，已有工具）：`get_key_moments`（当前图形 + 同类分布 + 任意日基线）、5 日相对板块偏离（`sample-idiosyncratic-moments.py` 的 `deviation`）、是否满足 PEAD 大跌定义、板块 ETF 映射。
3. **事件分组与主窗口**（事先冻结，Agent 不能改）：

| 决策时已知的条件 | 组别 | 主窗口 | 说明 |
|---|---|---:|---|
| 财报 8-K 信号日板块超额 < −5%（PEAD v2 定义） | E1 财报大跌 | 20 日 | 次要检验；同时满足偏离条件的归 E2（协议 v1 §2 修正：terra 的低概率档全是财报与指引，E1 优先会移走主检验最有信息的事件） |
| 关键图形 + 5 日相对板块偏离 \|z\| ≥ 2 | E2 个股偏离 | 60 日 | 沿用 terra 登记检验的目标 |
| 单纯图形 / 无事件的主动查询 | E0 常规 | 60 日 | 只展示基线；5 日为复核点 |
| 长期估值修复 | 不进动作实验 | — | 按需完整研究，一年期估值不填入短期收益栏 |

4. **消息归因**：只在 E1/E2 运行一次 `moment-review`（terra），同一事件只跑一次、全流程复用。另记录一个低成本对照字段：**当时是否有明确、可核实的指引下修**，用于判断 LLM 的价值有多少只是“读出一个公开事实”。
5. **行动比较**：按持仓状态列出候选动作，只比较同一期限、同一口径的数字（见 3.4）。
6. **完整研究**（advocate/skeptic/CIO）只在用户明确要求时运行，结果附在卡后，不改变卡的口径。

### 3.3 动作集与纸面数量

| 持仓状态 | 候选动作 | 纸面数量（评分用，事先固定） |
|---|---|---|
| 未持有 | BUY（试探）/ WAIT | BUY = 一份试探仓（每 100 元可调整资金的固定比例，P0 写定） |
| 已持有 | ADD / HOLD / REDUCE / EXIT | REDUCE = 减现有仓位的一半；EXIT = 全部；ADD = 一份试探仓 |

- `WAIT` 是新增动作，旧账本里对应 `NO_TRADE`；新 schema 用新枚举，旧记录不改写。
- WAIT/HOLD 都要写类型：`无优势`（本案与基准相差 < 5 个百分点，赔率也不明显不对称）或 `有判断`（说明为什么不动），并给出至少一条价格位复核条件和一条经营事实复核条件。
- 用户的真实数量可选填；评分一律折算成每 100 元可调整资金。

### 3.4 概率与收益口径

决策卡上的数字分三栏，**不跨栏相乘**：

| 栏 | 内容 | 来源 |
|---|---|---|
| 相对板块 | `p_outperform`（基准 → 本案，调整依据）、同类事件超额收益 25/50/75 分位 | 基准：Python；本案：LLM，须写证据 |
| 绝对收益 | 同类事件绝对收益分位、上涨概率、途中最低收盘（相对入场） | Python，与任意日基线并排；与基线相同不算优势 |
| 资金去向 | “减半留现金”与“减半换 ETF”各自的影响 | Python 按同一历史样本逐笔计算 |

- 本案净期望只在三项都来自同一批样本时才写，否则留空。
- 历史分布全部改为**次日常规交易日开盘入场**后重算；旧的收盘入场结果只作背景。
- LLM 相对基准的调整在 5 个百分点以内、又没有新证据时，必须写“无优势”。

### 3.5 决策卡格式（首屏）

```
# {TICKER} · {组别 E0/E1/E2} · {as_of} 收盘 · {持仓状态}
动作：{ACTION}（{纸面数量}）｜主窗口：{20/60} 日｜类型：{有判断/无优势}
一句话：{为什么}
上次决策：{日期 动作} → 变化：{哪条复核条件触发 / 无新增证据}

| 栏 | 基准 | 本案 | 依据 |
| 相对板块 p_outperform | … | … | … |
| 同类超额 25/50/75 | … | — | n=… |
| 绝对收益 25/50/75、途中最低 | … | — | 与任意日对照 |
| 减半：留现金 / 换 ETF | … | … | 同一样本 |

消息归因：{原因类别｜公司原因 是/否/未确认｜是否明确指引下修}
复核条件：价格位 … ；经营事实 …（触发时按当时价格重新计算，不是自动指令）
数据缺口：…
```

### 3.6 记录：新账本 `evals/forward/decision-ledger.jsonl`（schema v2）

只追加，与旧账本分开。每行 `kind` 为 `selection`（扫描入选，研究开始前写入）、`decision`、`failure`、`not_fillable`。`decision` 至少包含：

```json
{
  "schema": "decision/v2",
  "ticker": "INTU", "group": "E1", "source": "scan|on_demand",
  "event_time": "...", "decided_at": "...", "fill_rule": "next_regular_open_after_decided_at",
  "horizon_days": 20, "benchmark": "XLK",
  "position": {"state": "held", "w0": 1.0},
  "action": "REDUCE", "w1": 0.5, "cash_destination": "cash",
  "p_outperform": {"baseline": 0.48, "case": 0.42, "basis": "..."},
  "abs_dist": {"q25": null, "q50": null, "q75": null, "source": "..."},
  "attribution": {"category": "...", "company_cause": true, "explicit_guidance_cut": true},
  "hold_type": null,
  "review_triggers": ["...", "..."],
  "prior_decision_id": "...",
  "model": "gpt-6.1-terra", "code_version": "..."
}
```

`save_decision` 旧接口保持兼容；新接口为单独工具或新参数，由 P1 决定最小改法。

### 3.7 成交与评分（`scripts/score-decisions.py`，新增）

- **成交**：`decided_at` 之后的第一个常规交易日开盘；入场日算第 1 日；第 20/60 日收盘结算；个股与 ETF 使用同一日历。缺开盘价就记为不可成交，不得用收盘价替代。
- **行动增益**（每 100 元可调整资金）：

  Δ = (w1 − w0) × (R_stock − R_alt) − (C_建议 − C_维持)

  R_alt 为资金去向的收益（现金 = 0，ETF = 同窗口 ETF 收益）。HOLD/WAIT 的 Δ = 0，并且计入全体均值，所以“永远不动”的得分恰好是 0。
- **同场基线**（同一事件、同一起点）：
  - B0 维持现状（Δ = 0）；
  - B1 机械规则：E1 大跌 → 减半；E2 向下偏离 → 减半；
  - B2 指引规则：有明确指引下修 → 减半（检验 LLM 是否只是读出公开事实）。
- **辅助报告**：HOLD 对“减半”、WAIT 对“买一份试探仓”的反事实（放弃的收益 / 避免的损失）；两种回撤分别命名；概率校准（分档实际频率）。
- 重叠窗口按日期块估计区间；同一仓位上的重复建议不能当作多笔独立资金。

### 3.8 上一卡对照（最小版本）

同一只股票有历史卡时，只读决策前最近一张，回答三件事：上次为何这样做、哪条复核条件已触发、当前动作与暴露怎样变化。上次建议不能当作用户已执行；当前持仓以本次输入为准。

### 3.9 本轮不做

新 Agent、全面新闻监控、用户推送、组合优化、期权、更多数据源、GUI、真实交易；不再给 60 日方向预测调提示词；不新增方法卡。

## 4. 核心假设与验收

### 4.1 P2 要检验的唯一假设（事先登记）

> 在事前入选、期限固定的 E1/E2 事件中，terra 利用决策时已公开的公司消息决定何时减半，其全部入选事件的平均扣费行动增益，同时高于维持现状（B0）和同期限的机械规则（B1）。

买入侧不在本假设内；有候选时另行登记。

### 4.2 P1 功能验收（不依赖收益结果）

- **12 张冻结案例**，包括三组成对案例：只改成本价、只改资金去向、只改公司消息证据；其余覆盖池外股票、板块普跌、事件重叠、缺价、有上一卡。
- 硬性 0 次：概率对象混用、使用未来信息、成交早于决策、把旧建议当真实持仓。
- 只改成本价（税务与风险约束不变）时，动作与收益判断保持不变。
- **用户盲读**：至少 10/12 张卡，用户在 60 秒内答出“现在做什么、为什么、什么变化会重新评估”。
- 至少 1 张真实卡在可成交时间之前入账；已到期的历史案例可以用 `score-decisions.py` 复算。
- 达标即停，不因发现新维度扩充。

### 4.3 P2 验收与停止

- 前 30 个事件只检查完整性与成交模拟，不看收益、不调参。
- 事先写定：最小有用增益、区间方法、样本上限、日历上限。
- 首批 100 个到期主窗口事件时报一次效应与区间；继续到上限。
- 区间排除最小有用增益 → 停止该动作假设，回到数据与假设；到上限时区间仍跨零 → 结论是“证据不足”，不延长、不改阈值重验。
