# MVP 架构边界评审

评审对象：候选版本 `0.1.0`  
评审范围：开发控制面、产品运行面、学习优化面

## 评审结论

- 通过——产品运行面只包含 CIO 编排、专业研究指令、与供应商无关的只读工具契约、确定性计算与风险、验证和存储。
- 通过——Runtime Agent 使用只读沙箱，禁止审批和 Apps，仅允许 `lookup`、`query`、`calculate` 工具，并返回结构化研究产物。
- 通过——Risk Policy 指标仅限会计恒等式、数学定义、数据质量和明确 Mandate 约束。测试会拒绝公司质量、估值吸引力、新闻含义和买卖信号等主观规则。
- 通过——Council 综合仍由 LLM 回调负责。Python 不选择证券、不生成 Thesis、不对投资排序，也不使用评分取代冲突证据。
- 通过——最终输出仅供研究建议，提供目标仓位范围而非可执行订单；遇到过期数据、未解决冲突、错误输入和风险否决时采取失败关闭策略。
- 通过——学习组件可以追加观察并创建 Improvement Proposal，但权限政策禁止其写入生产 Skill、Agent、Schema、Risk Policy 和版本指针。
- 通过——产品包中不存在券商、账户修改、订单路由或真实交易连接器。

## 延后处理的集成边界

由于首发生产市场和数据供应商已明确延后选择，当前插件不声明具体 MCP 传输。Runtime Agent 只声明可由父运行时注入的、与供应商无关的只读能力。仓库内的 reference adapter 和确定性 fixture 构成本候选版本的验收数据面；接入生产 MCP 必须创建独立 OpenSpec Change，并继续保持只读。

## 总结

该候选版本保持了 LLM-native 边界：语言模型组件负责研究解释与综合；Python 负责确定性的证据处理、数学计算、硬风险约束、验证、回放和存储。
